집의 위치와 시설을 보고 가격을 예측하려고 한다. 결정트리 하나를 학습할 수도 있지만, 서로 다른 결정트리 여러 개의 예측을 합칠 수도 있다. 이렇게 <strong>여러 모델의 예측을 결합하는 방법을 앙상블(ensemble)</strong>이라고 한다.

랜덤 포레스트와 그래디언트 부스팅은 모두 결정트리를 여러 개 사용한다. 다만 각 트리에게 맡기는 일이 다르다. <strong>회귀 랜덤 포레스트에서는 각 트리가 집값을 예측하고, 전체 모델이 그 값들을 평균 낸다. 제곱오차 회귀 그래디언트 부스팅에서는 각 트리가 현재 집값 예측을 얼마나 고칠지 예측하고, 전체 모델이 그 보정값을 차례로 더한다.</strong>[^ensemble]

이 차이를 이해하려면 먼저 트리 하나가 무엇을 학습하고 어떤 값을 반환하는지 알아야 한다. 집 4채의 같은 자료를 사용해 개별 트리의 학습부터 여러 트리의 결합까지 따라가 보자. 계산에서는 모든 집의 가중치를 같게 두고, 예측과 정답의 차이를 제곱하는 기준을 사용한다. 아래 그림의 <strong>잔차는 실제 정답에서 현재 전체 예측을 뺀 값</strong>이다.

## 1. 집 한 채의 입력과 정답을 한 쌍으로 준비한다

다음은 계산을 살펴보기 위한 <strong>가상의 집값 자료</strong>다. 한 행은 집 한 채를 나타낸다. 역세권·리모델링·주차장 컬럼은 `0=아니오`, `1=예`로 기록했고, 집값의 단위는 <strong>억 원</strong>이다.

| 집 | 역세권 | 리모델링 | 주차장 | 실제 집값 |
| --- | ---: | ---: | ---: | ---: |
| A | 0 | 0 | 1 | 5 |
| B | 0 | 1 | 0 | 7 |
| C | 1 | 0 | 0 | 11 |
| D | 1 | 1 | 1 | 17 |

예측에 사용할 입력 정보를 <strong>특성(feature)</strong>이라고 한다. 이 표에서는 역세권·리모델링·주차장이 특성이다. 모델이 맞히려는 <strong>정답 또는 목표값(target)</strong>은 실제 집값이다.

입력 표에는 관례적으로 `X`, 정답 배열에는 `y`라는 이름을 붙인다. 이 글의 `X`는 집 4채의 특성 세 개를 모은 표이고, `y`는 `[5, 7, 11, 17]`이다. A의 정답은 첫 번째 값 5 하나다. 나머지 세 값은 각각 B·C·D의 정답이다.

<strong>배열은 여러 값을 순서대로 담는 자료 구조</strong>다. 배열의 `shape`는 각 차원의 크기를 나타낸다. 여기서는 다음과 같이 읽으면 된다.

| 자료 | 담고 있는 값 | `shape` |
| --- | --- | --- |
| `X` | 집 4채 × 입력 특성 3개 | `(4, 3)` |
| `y` | 집마다 실제 집값 하나씩, 모두 4개 | `(4,)` |
| 모델이 `X`를 예측한 결과 | 집마다 예측값 하나씩, 모두 4개 | `(4,)` |

`(4,)`는 값 네 개를 가진 1차원 배열이라는 뜻이다. 입력과 정답의 순서는 함께 유지해야 한다. `X`의 집 순서만 바꾸고 `y`를 그대로 두면 다른 집의 가격을 정답으로 연결하게 된다.

집값처럼 <strong>크기를 가진 숫자를 예측하는 문제를 회귀(regression)</strong>라고 한다. 구매 여부나 펭귄 종류처럼 <strong>어느 범주에 속하는지 예측하는 문제는 분류(classification)</strong>다. 두 문제 모두 결정트리를 사용할 수 있다. 회귀트리도 조건에 따라 데이터 행을 나누지만, 마지막에 출력하는 것은 가격 같은 숫자다.[^tree]

## 2. 노드 하나, 트리 하나, 전체 모델 하나를 구분한다

<strong>노드(node)</strong>는 트리 안에 있는 구성 요소다. 트리의 시작 노드는 <strong>루트(root)</strong>라고 한다. 조건을 검사하는 노드에서는 다음으로 갈 곳을 선택하고, 더 나눠지지 않는 마지막 노드인 <strong>리프(leaf)</strong>에서는 예측값을 출력한다.

예를 들어 루트에서 한 번 나눈 뒤 두 리프 중 하나로 이동하는 구조라면, 루트 하나와 리프 둘을 합쳐 노드는 세 개다. <strong>이 세 노드를 포함한 구조 전체가 결정트리 한 개</strong>다.

| 구분 | 무엇을 가리키는가 |
| --- | --- |
| 노드 하나 | 한 트리 안에서 조건을 검사하거나 결과를 출력하는 구성 요소 하나 |
| 결정트리 하나 | 자기 루트와 모든 분기·리프를 포함한 개별 모델 하나 |
| 전체 앙상블 모델 하나 | 여러 개별 모델과 그 예측을 결합하는 규칙 |
| 회귀 부스팅 한 단계 | 새 회귀트리 하나를 학습해 전체 예측에 보정을 반영하는 과정 한 번 |

부스팅에서 트리를 세 개 사용하면 각 트리는 자기 루트와 리프를 따로 가진다. 두 번째 트리를 만들 때 첫 번째 트리의 리프에 가지를 이어 붙이지 않는다. <strong>여러 완성된 트리의 출력값을 결합해서 전체 모델을 구성한다.</strong>

### 깊이는 한 트리 안에서 센다

<strong>깊이(depth)</strong>는 루트에서 해당 노드까지 지나온 연결의 개수다. 루트의 깊이는 0이고, 루트의 바로 아래 자식 노드는 깊이 1이다.

`max_depth`는 각 트리에 허용하는 <strong>깊이의 상한</strong>이다. scikit-learn의 이진 결정트리에 `max_depth=1`을 지정하면 최대 두 리프와 세 노드를 가질 수 있다. 조건에 따라 분할하지 않을 수도 있으므로 실제 크기는 더 작을 수 있다. `max_depth=3`은 깊이 0·1·2·3을 허용하며, 실제로 깊이 3까지 자라야 한다는 뜻은 아니다.[^regressor]

반면 `n_estimators`는 여러 모델을 결합할 때 사용하는 개수를 정한다. 이번 회귀 부스팅의 `n_estimators=3`은 <strong>보정용 트리 세 개</strong>다. 각 트리의 깊이는 `max_depth`로 따로 정하고, 시작할 때 사용하는 초기 예측은 이 세 트리에 포함하지 않는다.

### `fit()` 한 번으로 트리 전체를 학습한다

`DecisionTreeRegressor`는 회귀트리 객체를 만드는 <strong>클래스</strong>다. 클래스의 설정으로 생성한 개별 객체가 실제 모델이며, 객체에 속한 함수는 <strong>메서드</strong>, 객체에 저장된 값은 <strong>속성</strong>이라고 한다.

| 코드 | 수행하는 일 | 반환값 |
| --- | --- | --- |
| `DecisionTreeRegressor(...)` | 설정을 가진 새 트리 객체를 만든다. | 아직 학습하지 않은 모델 객체 |
| `tree.fit(X, target)` | 입력과 목표값으로 분할 조건과 리프 값을 결정한다. | 학습된 `tree` 객체 자신 |
| `tree.predict(X)` | 완성된 조건을 입력 행마다 적용한다. | 각 행의 예측값을 담은 배열 |

여기서 `target`은 트리에 전달할 학습 목표를 가리킨다. 집값을 학습할 때는 `y`를 넣고, 뒤에서 보정값을 학습할 때는 계산한 잔차를 넣는다.

`fit()` 안에서는 후보 조건을 비교하고, 자식 노드를 만들고, 필요한 분할을 반복하고, 리프의 출력값을 저장한다. 따라서 <strong>`fit()`을 한 번 호출하는 동안 여러 노드에서 많은 계산이 일어난다.</strong> 일반적인 `DecisionTreeRegressor`에 다시 `fit()`을 호출하면 새로 전달한 데이터로 트리를 다시 구성한다.[^regressor]

`predict()`는 학습이 끝난 규칙을 사용한다. 입력이 네 행이면 메서드를 한 번 호출해도 네 집의 예측값을 반환한다. <strong>모델의 개수, 메서드를 호출한 횟수, 결과 배열에 들어 있는 숫자의 개수는 각각 따로 세어야 한다.</strong>

## 3. 회귀트리는 어떤 기준으로 나누고 무엇을 출력할까

역세권 컬럼이 0 또는 1이라면 `역세권 <= 0.5`라는 조건으로 두 그룹을 만들 수 있다. A·B는 조건을 만족하고, C·D는 만족하지 않는다. `0.5`는 두 입력값 0과 1을 구분하는 기준값이다.

조건이 이미 정해져 있다면 입력 `X`만 보고 행을 나눌 수 있다. <strong>학습할 때는 어떤 조건이 좋은지 선택하고, 나눈 그룹마다 어떤 가격을 출력할지도 결정해야 한다.</strong> 이때 정답 `y`가 필요하다.

### 예측의 오차를 제곱해서 평균 낸다

<strong>평균제곱오차(MSE, Mean Squared Error)</strong>는 각 행에서 정답과 예측의 차이를 제곱한 뒤, 그 값들을 더해 행 수로 나눈 값이다. 모델의 오차를 평가하는 이런 값을 <strong>손실(loss)</strong>이라고 부른다. 이 글에서는 MSE가 작아지도록 예측을 학습한다.

한 리프에 도달한 집들에게 공통 가격 6을 예측한다고 하자. 그 집들의 정답이 A의 5와 B의 7이면 다음처럼 계산한다.

<div class="boost-math">
$$
\mathrm{MSE}=\frac{(5-6)^2+(7-6)^2}{2}
=\frac{1+1}{2}=1
$$
</div>

두 집의 차이는 각각 −1과 +1이지만, 제곱하면 둘 다 1이 된다. 제곱하지 않고 차이만 평균 내면 서로 상쇄되어 실제로는 틀렸는데도 0이 나올 수 있다.

제곱했기 때문에 단위도 바뀐다. 집값의 단위가 억 원이면 <strong>MSE의 단위는 `(억 원)²`</strong>다. MSE 1을 “평균적으로 정확히 1억 원 틀렸다”라고 읽으면 안 된다.

### 같은 리프의 집들에게는 왜 평균을 예측할까

제곱오차를 기준으로 학습하는 회귀트리는 리프에 들어온 목표값의 평균을 출력한다.[^regressor] 이유는 <strong>같은 그룹의 모든 행에 숫자 하나를 공통으로 출력할 때, 평균을 선택해야 그 그룹의 MSE가 가장 작기 때문</strong>이다. 이 관계를 일반식으로 확인해 보자.

| 기호 | 뜻 |
| --- | --- |
| $k$ | 한 리프에 들어 있는 학습 행 수. 1 이상이다. |
| $t_i$ | 그 리프의 $i$번째 행에 해당하는 학습 목표값 |
| $c$ | 리프에서 모든 행에 공통으로 출력하려는 숫자 |
| $a$ | 그 리프에 들어 있는 목표값들의 산술평균 |
| $\sum_{i=1}^{k}$ | $i$를 1부터 $k$까지 바꾸며 각 항을 모두 더하라는 표시 |

평균 $a$와 공통 예측값 $c$의 MSE를 다음과 같이 쓴다.

<div class="boost-math">
$$
a=\frac{1}{k}\sum_{i=1}^{k}t_i,
\qquad
\mathrm{MSE}(c)=\frac{1}{k}\sum_{i=1}^{k}(t_i-c)^2
$$
</div>

이제 각 차이 $t_i-c$를 평균을 기준으로 두 부분으로 나눈다. $(t_i-a)+(a-c)$를 더하면 중간의 $-a$와 $+a$가 없어져 원래 차이가 된다.

<div class="boost-math">
$$
\begin{aligned}
\mathrm{MSE}(c)
&amp;=\frac{1}{k}\sum_{i=1}^{k}\bigl((t_i-a)+(a-c)\bigr)^2\\
&amp;=\frac{1}{k}\sum_{i=1}^{k}(t_i-a)^2
+\frac{2(a-c)}{k}\sum_{i=1}^{k}(t_i-a)
+(a-c)^2
\end{aligned}
$$
</div>

두 번째 줄에서는 두 항의 합을 제곱하는 공식으로 괄호를 전개했다. $(a-c)^2$는 모든 행에서 같은 값이므로 $k$번 더한 뒤 $k$로 나누면 그대로 남는다.

가운데 항에 있는 합은 0이다. 평균을 정의한 식에서 $ka=\sum_{i=1}^{k}t_i$이기 때문이다.

<div class="boost-math">
$$
\sum_{i=1}^{k}(t_i-a)
=\sum_{i=1}^{k}t_i-ka
=0
$$
</div>

따라서 식은 다음처럼 정리된다.

<div class="boost-math">
$$
\boxed{\mathrm{MSE}(c)=\mathrm{MSE}(a)+(a-c)^2}
$$
</div>

$(a-c)^2$는 항상 0 이상이며, $c=a$일 때만 0이다. 즉, 평균 이외의 숫자를 출력하면 평균을 출력했을 때의 MSE에 $(a-c)^2$만큼이 더해진다. 그래서 공통 예측값을 평균으로 정한다.

이 결론은 <strong>제곱오차와 동일한 행 가중치</strong>를 전제로 한다. 행마다 중요도를 다르게 주면 가중평균을 사용한다. 또한 절대오차를 기준으로 하는 회귀트리는 평균 대신 중앙값을 사용한다. 중앙값은 숫자를 정렬했을 때 가운데에 놓이는 값이다. 개수가 짝수이면 가운데 두 수의 평균을 사용한다.[^regressor]

### 평균을 구한 뒤 분할 후보를 비교한다

집값을 직접 학습하는 깊이 1의 트리는 각 컬럼으로 나눴을 때의 MSE를 비교할 수 있다. 다음 표의 예측 배열은 항상 A·B·C·D 순서다.

| 분할 후보 | 각 그룹의 평균 집값 | A·B·C·D의 예측 | 전체 MSE |
| --- | --- | --- | ---: |
| 나누지 않음 | 전체 평균 10 | `[10, 10, 10, 10]` | 21 |
| 역세권 | A·B: 6 / C·D: 14 | `[6, 6, 14, 14]` | 5 |
| 리모델링 | A·C: 8 / B·D: 12 | `[8, 12, 8, 12]` | 17 |
| 주차장 | B·C: 9 / A·D: 11 | `[11, 9, 9, 11]` | 20 |

예를 들어 역세권으로 나누면 두 리프의 출력은 $(5+7)/2=6$과 $(11+17)/2=14$다. 네 집 전체의 MSE는 다음과 같다.

<div class="boost-math">
$$
\frac{(5-6)^2+(7-6)^2+(11-14)^2+(17-14)^2}{4}
=\frac{1+1+9+9}{4}=5
$$
</div>

후보 중 이 값이 가장 작아서 첫 분할에 역세권을 선택한다. 평균은 행을 조건으로 나누기 위해 필요한 계산이 아니라, <strong>나눈 뒤의 예측값을 정하고 각 후보의 예측 오차를 비교하기 위한 계산</strong>이다. 두 그룹의 행 수가 다르면 전체 MSE를 구할 때 각 그룹의 행 수를 반영해야 한다.

깊이를 더 허용하면 각 그룹 안에서도 다시 조건을 비교할 수 있다. 지금은 깊이를 1로 제한했으므로 A와 B는 같은 리프의 값 6을 받는다. 각 노드에서 좋은 분할을 찾는 이런 방식이 가능한 모든 전체 트리 중 최적의 구조를 보장하는 것은 아니다.[^tree]

## 4. 배깅은 학습 자료를 다르게 뽑아 모델 여러 개를 만든다

트리 하나는 학습 자료가 조금만 달라져도 분할 조건이 바뀔 수 있다. 첫 조건이 바뀌면 뒤에서 나누는 그룹도 달라진다. <strong>배깅(Bagging)</strong>은 서로 다르게 뽑은 학습 자료로 여러 모델을 만들고, 그 예측을 종합해 이런 변동을 줄이려는 방법이다.[^ensemble]

먼저 <strong>복원추출</strong>을 알아야 한다. 복원추출은 이미 뽑은 행도 다음 추출에서 다시 뽑을 수 있게 하는 방식이다. 원본 행이 A·B·C·D라면 네 번을 뽑은 결과가 다음과 같을 수 있다. 아래 묶음은 추출 방식을 보여 주기 위한 예시다.

| 개별 모델 | 학습에 사용할 집의 순서 | 함께 가져오는 실제 집값 |
| --- | --- | --- |
| 모델 1 | A, A, C, D | 5, 5, 11, 17 |
| 모델 2 | B, C, C, A | 7, 11, 11, 5 |
| 모델 3 | D, D, B, C | 17, 17, 7, 11 |

각 묶음은 네 행이지만 모든 집을 한 번씩 포함하지는 않는다. 모델 1에는 A가 두 번 들어가고 B가 없다. <strong>행을 뽑을 때는 그 행의 입력과 정답을 함께 뽑는다.</strong>

이처럼 복원추출로 표본을 다시 구성해 활용하는 방법을 <strong>부트스트랩(bootstrap)</strong>이라고 한다. 배깅은 이렇게 만든 표본으로 개별 모델을 학습한다. 회귀 배깅에서는 새 입력에 대한 개별 모델의 예측값을 평균 내서 최종 예측을 구한다.[^bagging]

각 모델에는 동일한 학습 알고리즘과 설정을 사용할 수 있다. 그래도 모델 객체는 서로 별개이며, 보는 자료가 다르므로 학습된 조건과 출력값까지 같을 필요는 없다. <strong>각 모델의 학습은 다른 모델의 예측 결과를 기다리지 않아도 된다.</strong> 따라서 모델별 학습을 동시에 진행하기 쉽다. 이런 동시 실행을 병렬 처리라고 한다.

여러 모델이 거의 같은 오차를 낸다면 평균을 내도 그 오차는 크게 줄지 않는다. 예측을 종합하는 효과를 얻으려면 모델들이 서로 조금씩 다르게 예측할 여지가 필요하다. 배깅은 자료를 다르게 뽑아 그 차이를 만든다. 배깅에 사용하는 개별 모델은 결정트리로 한정되지 않는다.[^bagging]

## 5. 랜덤 포레스트는 분할에 사용할 컬럼도 조절한다

<strong>랜덤 포레스트(Random Forest)</strong>는 여러 결정트리의 예측을 종합하는 모델이다. scikit-learn의 기본 설정에서는 트리마다 학습 행을 복원추출한다. 여기에 <strong>각 노드에서 분할 후보로 검토할 컬럼의 수</strong>를 제한할 수 있다.[^forest]

앞의 집값 자료에서 세 컬럼을 매번 전부 확인하면, 여러 트리가 역세권이라는 같은 조건을 먼저 고를 수 있다. 후보 컬럼을 무작위로 제한하면 다른 조건도 선택될 기회가 생긴다. 트리들이 비슷해지는 정도를 줄이는 한 가지 방법이다.

예를 들어 `max_features=2`를 사용하면 분할을 찾을 때 후보 컬럼 두 개를 고른다. 다음은 노드마다 후보가 달라질 수 있다는 것을 보여 주는 예시다. 앞에서 학습한 깊이 1 트리의 실제 기록을 나타낸 표는 아니다.

| 후보를 고르는 위치 | 검토할 수 있는 컬럼 두 개의 예 |
| --- | --- |
| 한 트리의 루트 | 역세권, 리모델링 |
| 그 트리의 왼쪽 자식 노드 | 리모델링, 주차장 |
| 그 트리의 오른쪽 자식 노드 | 역세권, 주차장 |

<strong>후보를 고르는 단위는 분할할 노드다.</strong> 트리마다 컬럼 하나를 전담시키거나, 같은 깊이의 모든 노드에 같은 컬럼을 지정하는 방식이 아니다. 같은 컬럼이 여러 노드와 여러 트리에서 다시 사용될 수 있다. 후보 선택과 조건 비교는 `fit()` 내부에서 수행한다.

### 같은 `max_features`라도 적용하는 위치가 다르다

| 모델 | `max_features`가 조절하는 것 |
| --- | --- |
| `BaggingRegressor` | 개별 모델 하나에 전달할 입력 컬럼 수 |
| `RandomForestRegressor` | 각 노드에서 분할을 찾을 때 검토할 후보 컬럼 수 |

기본값도 분류와 회귀에서 다르다. `RandomForestClassifier`는 기본적으로 `max_features="sqrt"`를 사용한다. 전체 컬럼 수의 제곱근을 구한 뒤 정수 부분만 취하되 최소 한 개를 고려한다. `RandomForestRegressor`의 기본값은 <strong>`max_features=1.0`</strong>, 즉 전체 컬럼을 고려하는 설정이다.[^forest][^forest-classifier]

따라서 회귀 랜덤 포레스트가 언제나 일부 컬럼만 검토한다고 생각하면 안 된다. 정수 `1`은 컬럼 한 개, 실수 `1.0`은 전체 컬럼의 100%라는 차이도 있다. 또한 유효한 분할을 찾기 위해 지정한 수보다 많은 컬럼을 검사할 수 있다는 구현상 조건이 있다.[^forest]

노드별 후보 제한은 일반 `DecisionTreeRegressor`에도 설정할 수 있다. 랜덤 포레스트는 이와 같은 트리의 학습 과정을 여러 트리의 결합과 함께 사용한다. 배깅은 개별 모델이 내부적으로 노드를 가지고 있을 필요가 없지만, 랜덤 포레스트를 이루는 개별 모델은 결정트리다.

### 학습이 끝나면 같은 집에 대한 예측을 평균 낸다

회귀 랜덤 포레스트의 각 트리는 집값을 출력한다. 트리가 세 개라면 <strong>같은 집에 대한 세 예측값을 더해 3으로 나눈다.</strong> 다른 집들의 예측을 한꺼번에 평균 내는 계산이 아니다.

분류에서는 결합 방식도 출력에 맞게 달라진다. scikit-learn의 분류 랜덤 포레스트는 각 트리가 계산한 <strong>범주별 확률을 같은 범주끼리 평균</strong> 낸 다음, 평균 확률이 가장 높은 범주를 선택한다. 분류 배깅도 개별 모델이 확률 예측을 제공하면 확률을 평균 내고, 그 기능이 없으면 예측 범주의 투표를 사용한다.[^forest-classifier][^bagging-classifier]

## 6. 부스팅은 현재 예측에 필요한 보정값을 학습한다

랜덤 포레스트에서는 각 트리가 원래 집값을 예측했다. 이제는 <strong>현재 예측을 유지하면서, 새 트리의 출력을 더해 예측을 개선하는 구조</strong>를 생각해 보자.

<div class="boost-math">
$$
\text{새 전체 예측}=\text{현재 전체 예측}+\text{새 트리의 보정 예측}
$$
</div>

앞 단계의 학습 결과를 반영해 다음 모델을 순서대로 학습하고 결합하는 전략을 <strong>부스팅(boosting)</strong>이라고 한다. <strong>그래디언트 부스팅(gradient boosting)</strong>은 손실을 줄일 방향을 계산해 그 방향을 예측하는 모델을 추가한다. 우선 제곱오차 회귀에서의 계산을 살펴보고, 이름에 들어 있는 그래디언트는 9절에서 이 계산과 연결한다.[^boosting]

이 절과 다음 수치 예제에서는 새 보정을 전부 더한다. 뒤에서 설명할 <strong>학습률</strong>, 즉 보정을 반영하는 비율을 1로 두는 경우다.

### 실제 정답에서 현재 전체 예측을 뺀다

현재 예측에 무엇을 더하면 실제 정답이 될까? 두 값의 차이를 구하면 된다.

<div class="boost-math">
$$
\text{잔차}=\text{실제 정답}-\text{현재 전체 예측}
$$
</div>

<strong>잔차(residual)</strong>가 양수이면 예측이 정답보다 작으므로 높일 필요가 있다. 잔차가 음수이면 예측이 정답보다 크므로 낮출 필요가 있다. 잔차는 현재 예측에 필요한 수정량이며 집값과 같은 단위를 가진다.

바깥의 부스팅 코드가 잔차를 계산한 다음, 새 회귀트리에 `fit(X, residual)`로 전달한다. `residual`은 잔차 배열의 이름이다. 새 트리는 입력 특성으로 이 숫자들을 예측하도록 학습한다. 트리가 잔차라는 말의 뜻이나 이전 트리의 내부 구조를 알아야 하는 것은 아니다.

이 과정에서도 <strong>원래 정답 `y`는 보관한다.</strong> 현재 예측이 바뀔 때마다 그 정답과 다시 비교해야 하기 때문이다.

### 잔차를 잘 예측하면 왜 최종 오차가 줄어들까

실제 정답을 $y_{\text{true}}$, 현재 전체 예측을 $\hat y$, 새 트리의 보정 예측을 $v$라고 하자. 현재 잔차를 $r=y_{\text{true}}-\hat y$로 정의하면, 보정 후 제곱오차는 다음과 같다.

<div class="boost-math">
$$
\begin{aligned}
\bigl(y_{\text{true}}-(\hat y+v)\bigr)^2
&amp;=\bigl(y_{\text{true}}-\hat y-v\bigr)^2\\
&amp;=\bigl((y_{\text{true}}-\hat y)-v\bigr)^2\\
&amp;=(r-v)^2
\end{aligned}
$$
</div>

첫 줄은 새 전체 예측과 정답을 비교한 식이다. 마지막 줄은 새 트리의 보정 예측과 잔차를 비교한 식이다. 두 식의 값이 같으므로, <strong>현재 전체 예측을 고정한 상태에서 새 트리가 잔차를 잘 예측하도록 학습하는 일은 보정 후 전체 예측의 제곱오차를 줄이는 일과 같은 목표</strong>가 된다.

그래서 새 트리에는 집값을 다시 예측시키는 대신 현재 잔차를 학습시킨다. 다만 한 리프의 여러 집에는 공통 숫자를 출력하므로, 개별 잔차를 전부 정확하게 맞히지는 못할 수 있다. 보정하고도 남은 차이는 다음 트리를 학습할 때 사용한다.

## 7. 집 4채의 예측을 트리 세 개로 고쳐 본다

아직 보정 트리가 없는 처음에는 모든 집에 같은 가격을 예측한다. 제곱오차에서 공통 숫자로 가장 적합한 값은 앞에서 확인한 평균이다.

<div class="boost-math">
$$
\text{초기 예측값}=\frac{5+7+11+17}{4}=10
$$
</div>

scikit-learn의 `GradientBoostingRegressor`도 제곱오차 회귀의 기본 초기 예측으로 학습 정답의 평균을 사용한다.[^boosting] 여기서 10은 각 집의 <strong>시작 예측값</strong>이다. 보정 트리와 별도로 보관하는 숫자다.

### 첫 번째 트리: 현재 잔차를 두 그룹으로 나눈다

| 집 | 실제 집값 | 현재 전체 예측 | 새 트리의 학습 목표인 잔차 |
| --- | ---: | ---: | ---: |
| A | 5 | 10 | $5-10=-5$ |
| B | 7 | 10 | $7-10=-3$ |
| C | 11 | 10 | $11-10=1$ |
| D | 17 | 10 | $17-10=7$ |

깊이 1인 새 회귀트리를 만들고 이 잔차를 학습시킨다. 역세권으로 나누면 A·B가 같은 리프에 들어가고 C·D가 다른 리프에 들어간다. 각 리프의 출력값은 <strong>그 리프에 들어온 잔차의 평균</strong>이다.

<div class="boost-math">
$$
\text{A와 B의 보정 예측}=\frac{-5+(-3)}{2}=-4
$$
</div>

<div class="boost-math">
$$
\text{C와 D의 보정 예측}=\frac{1+7}{2}=4
$$
</div>

<figure class="boost-figure">
<img src="/random-forest-gradient-boosting/first-tree-ko.svg" alt="첫 번째 보정 트리 전체. 깊이 0인 루트 하나와 깊이 1인 리프 둘로 이루어지며, 역세권 여부에 따라 -4 또는 +4를 출력한다.">
</figure>

이 그림 전체가 첫 번째 트리다. A의 실제 잔차 −5와 B의 실제 잔차 −3에 대해 이 트리는 둘 다 −4를 예측한다. <strong>학습 목표인 잔차와 트리가 예측한 보정값은 서로 다를 수 있다.</strong>

역세권으로 나눴을 때 보정 후 MSE는 5다. 리모델링으로 나누면 17, 주차장으로 나누면 20이므로 이번에도 역세권을 선택한다. 원래 목표값 모두에서 같은 초기값 10을 뺐기 때문에, 각 그룹의 평균도 10씩 줄고 평균과 목표 사이의 차이는 그대로다. 그래서 앞서 집값을 직접 학습했을 때와 후보별 MSE가 같다.

선택한 보정값을 기존 예측에 더하면 다음과 같다.

| 집 | 기존 예측 | 첫 트리의 보정 | 갱신한 전체 예측 | 남은 잔차 |
| --- | ---: | ---: | ---: | ---: |
| A | 10 | −4 | 6 | −1 |
| B | 10 | −4 | 6 | +1 |
| C | 10 | +4 | 14 | −3 |
| D | 10 | +4 | 14 | +3 |

보정 후 모든 집의 오차가 줄어드는 것은 아니다. C는 정답이 11인데 예측이 10에서 14로 바뀌어, 오차의 크기가 1에서 3으로 커졌다. 이 트리는 C와 D에 같은 보정값을 출력하며 네 집 전체의 제곱오차를 기준으로 학습한다. 이번 보정에서 전체 MSE는 21에서 5로 줄었다.

집값을 직접 학습한 깊이 1 트리와 같은 `[6, 6, 14, 14]`가 나왔다. 같은 그룹에 대해 집값 평균을 바로 출력하든, 초기값 10에 잔차 평균을 더하든 이 조건에서는 같은 숫자가 된다. 부스팅의 이후 과정은 여기서 남은 잔차에 새로운 트리를 계속 학습하는 것이다.

### 보정값 −4와 MSE 1은 각각 다른 일을 한다

A·B의 리프에서 사용하는 보정값은 평균 −4다. 이 값이 두 목표 잔차를 얼마나 잘 예측하는지 평가하면 다음과 같다.

<div class="boost-math">
$$
\frac{(-5-(-4))^2+(-3-(-4))^2}{2}=1
$$
</div>

−4는 예측을 얼마나 낮출지 정하는 숫자이고, 1은 그 보정 예측의 제곱오차를 평가한 숫자다.

잔차 자체를 제곱해서 평균 낸 $((-5)^2+(-3)^2)/2=17$은 <strong>아직 보정값을 0으로 두었을 때의 MSE</strong>다. 이 17을 예측에 더하는 것이 아니다. 보정값에는 높일지 낮출지를 나타내는 부호가 필요하다.

같은 리프의 잔차가 −3과 +3이면 공통 보정값은 평균 0이다. 그래도 MSE는 $(9+9)/2=9$다. 두 집을 같은 값으로만 고칠 수 있어서 0이 최선인 것이지, 두 집의 예측이 모두 정확해진 것은 아니다.

### 두 번째 트리: 갱신한 예측에서 잔차를 다시 구한다

첫 단계가 끝나면 현재 전체 예측은 `[6, 6, 14, 14]`다. 실제 집값에서 이 배열을 빼면 두 번째 학습 목표가 나온다.

<div class="boost-math">
$$
[5,7,11,17]-[6,6,14,14]=[-1,1,-3,3]
$$
</div>

이번에는 새 트리가 리모델링 여부로 나눈다. 리모델링하지 않은 A·C의 잔차 평균은 $(-1-3)/2=-2$, 리모델링한 B·D의 잔차 평균은 $(1+3)/2=2$다.

| 집 | 기존 전체 예측 | 두 번째 트리의 보정 | 갱신한 전체 예측 | 남은 잔차 |
| --- | ---: | ---: | ---: | ---: |
| A | 6 | −2 | 4 | +1 |
| B | 6 | +2 | 8 | −1 |
| C | 14 | −2 | 12 | −1 |
| D | 14 | +2 | 16 | +1 |

첫 번째 트리에 저장한 −4와 +4는 그대로다. 두 번째 트리가 별도로 −2와 +2라는 보정을 학습해서 전체 예측에 더해졌다.

### 세 번째 트리: 마지막으로 남은 차이를 학습한다

새로 남은 잔차는 `[1, -1, -1, 1]`이다. 주차장이 있는 A·D는 +1, 주차장이 없는 B·C는 −1이므로, 세 번째 트리는 주차장 조건으로 이 값을 구분할 수 있다.

<div class="boost-math">
$$
[4,8,12,16]+[1,-1,-1,1]=[5,7,11,17]
$$
</div>

각 단계까지 누적한 결과를 모으면 다음과 같다. 배열의 순서는 모두 A·B·C·D다.

| 상태 | 이번에 추가한 트리의 보정 예측 | 전체 집값 예측 | 전체 MSE |
| --- | --- | --- | ---: |
| 초기 | 보정 트리가 없음 | `[10, 10, 10, 10]` | 21 |
| 1단계 | `[-4, -4, 4, 4]` | `[6, 6, 14, 14]` | 5 |
| 2단계 | `[-2, 2, -2, 2]` | `[4, 8, 12, 16]` | 1 |
| 3단계 | `[1, -1, -1, 1]` | `[5, 7, 11, 17]` | 0 |

역세권·리모델링·주차장을 트리마다 미리 배정한 것은 아니다. 각 단계의 잔차에 맞춰 조건을 비교한 결과가 이 순서로 나온 것이다. 학습 자료나 설정을 바꾸면 같은 컬럼이 여러 단계에서 반복해서 선택될 수도 있다.

아래에서 단계를 선택하면 <strong>그 단계에 새로 만든 트리</strong>와 집별 잔차·보정값·전체 예측을 함께 볼 수 있다. 학습률 1인 위 계산을 표시한 그림이다.

## 8. 처음 보는 집은 저장된 트리로 예측한다

이제 E라는 새 집을 예측해 보자. E는 <strong>역세권이고, 리모델링하지 않았으며, 주차장이 있다.</strong> 입력은 `[[1, 0, 1]]`이다. 바깥 대괄호는 집들을 담고, 안쪽 대괄호는 그중 집 한 채의 특성 세 개를 담으므로 `shape`는 `(1, 3)`이다.

세 트리는 모두 이 입력을 받는다. 첫 번째 트리는 역세권 컬럼을 보고 +4를 출력하고, 두 번째는 리모델링 컬럼을 보고 −2를 출력하고, 세 번째는 주차장 컬럼을 보고 +1을 출력한다.

| 예측에 사용하는 구성 요소 | E에 적용하는 계산 | 출력 |
| --- | --- | ---: |
| 초기 예측 | 학습 때 저장한 시작값을 사용한다. | 10 |
| 첫 번째 트리 | 역세권인 집의 리프로 이동한다. | +4 |
| 두 번째 트리 | 리모델링하지 않은 집의 리프로 이동한다. | −2 |
| 세 번째 트리 | 주차장이 있는 집의 리프로 이동한다. | +1 |

전체 예측은 다음과 같다.

<div class="boost-math">
$$
10+4-2+1=13
$$
</div>

이 모델은 E의 집값을 <strong>13억 원</strong>으로 예측한다. 실제 가격은 주어지지 않았으므로 예측이 얼마나 정확한지는 아직 평가할 수 없다.

새 집을 예측할 때는 실제 정답도, 실제 잔차도 필요하지 않다. <strong>학습할 때 잔차를 목표로 만든 규칙을 새 집의 입력에 적용해서 보정값을 구한다.</strong> `fit()`을 다시 호출하는 과정도 없다.

또한 두 번째 트리의 입력은 첫 번째 트리의 출력 +4가 아니라 E의 원래 특성 세 개다. <strong>학습할 때 다음 트리는 앞 단계의 전체 예측에 의존하지만, 학습이 끝난 각 트리는 같은 입력에서 자기 출력을 계산할 수 있다.</strong> 트리의 학습 순서와 새 입력의 전달 구조를 구분해야 한다.

## 9. 잔차를 학습하는데 왜 이름이 그래디언트 부스팅일까

<strong>미분값은 어떤 숫자를 아주 조금 바꿨을 때 함수값이 얼마나 바뀌는지 나타내는 순간 변화율</strong>이다. 여러 숫자를 바꿀 수 있다면 각 숫자에 대한 미분값을 모아서 <strong>그래디언트(gradient)</strong>라고 부른다.

<strong>경사하강법</strong>은 손실의 변화율을 구한 뒤, 손실이 내려가는 방향으로 값을 조금씩 바꾸는 방법이다. 이 글에서는 전체 모델이 출력한 <strong>예측값 자체</strong>가 얼마나 바뀌어야 할지 살펴본다.

### 예측값을 조금 바꿔서 손실의 변화를 계산한다

앞과 같이 실제 정답은 $y_{\text{true}}$, 현재 예측은 $\hat y$로 쓴다. 한 행의 손실 함수 $L$을 다음과 같이 정의하자.

<div class="boost-math">
$$
L(\hat y)=\frac12(y_{\text{true}}-\hat y)^2
$$
</div>

제곱오차 앞에 붙인 $1/2$는 미분 결과를 간단하게 만들기 위한 양의 상수다. 모든 손실값을 같은 비율로 줄이므로 손실이 최소가 되는 예측값은 달라지지 않는다.

이제 예측값에 더할 작은 변화량을 $\Delta$라고 하자. $\Delta$는 양수나 음수가 될 수 있으며, 나눗셈을 할 때는 0이 아니라고 둔다. 예측을 $\hat y+\Delta$로 바꾸면 손실의 변화는 다음과 같다.

<div class="boost-math">
$$
\begin{aligned}
L(\hat y+\Delta)-L(\hat y)
&amp;=\frac12\left[(y_{\text{true}}-\hat y-\Delta)^2
-(y_{\text{true}}-\hat y)^2\right]\\
&amp;=-(y_{\text{true}}-\hat y)\Delta+\frac12\Delta^2\\
&amp;=(\hat y-y_{\text{true}})\Delta+\frac12\Delta^2
\end{aligned}
$$
</div>

두 번째 줄은 제곱을 전개하고 공통 항을 뺀 결과다. 이 손실의 변화를 예측의 변화량 $\Delta$로 나누면 그 구간의 변화율을 얻는다.

<div class="boost-math">
$$
\frac{L(\hat y+\Delta)-L(\hat y)}{\Delta}
=\hat y-y_{\text{true}}+\frac12\Delta
$$
</div>

$\Delta$를 0에 가까워지게 하면 마지막 항이 0에 가까워진다. 그때 남는 순간 변화율을 $\frac{dL}{d\hat y}$라고 쓴다. 예측값 $\hat y$에 대한 손실의 미분값이라는 뜻이다.

<div class="boost-math">
$$
\frac{dL}{d\hat y}=\hat y-y_{\text{true}}
$$
</div>

예측이 정답보다 크면 이 값은 양수다. 예측을 더 키우면 손실이 커지므로 예측을 낮춰야 한다. 예측이 정답보다 작으면 미분값은 음수이고, 예측을 높이는 쪽에서 손실이 줄어든다. 즉, 작은 보정에서는 <strong>미분값과 반대 부호인 방향</strong>으로 움직인다.

<div class="boost-math">
$$
\boxed{-\frac{dL}{d\hat y}=y_{\text{true}}-\hat y=\text{잔차}}
$$
</div>

앞에서 새 트리가 학습한 잔차가 바로 이 손실을 낮추는 방향이다. <strong>그래디언트 부스팅은 이 방향을 입력 특성으로 예측하는 새 트리를 학습하고, 그 트리의 출력으로 전체 예측을 바꾼다.</strong> 개별 회귀트리는 여전히 후보 분할을 비교하고 리프 값을 구하는 방식으로 학습한다.[^ensemble]

### MSE 전체를 미분하면 상수 배수가 붙는다

앞의 정확한 등식은 <strong>한 행의 손실을 절반 제곱오차로 정의했을 때</strong> 성립한다. 일반적인 MSE는 행별 제곱오차를 모두 평균 낸 값이다.

전체 행 수를 $n$, $i$번째 행의 정답과 예측을 각각 $y_i$, $\hat y_i$, 전체 MSE를 $J$라고 쓰면 다음과 같다.

<div class="boost-math">
$$
J=\frac1n\sum_{i=1}^{n}(y_i-\hat y_i)^2
$$
</div>

여러 예측 중 $\hat y_i$ 하나만 바꿀 때의 미분은 $\frac{\partial J}{\partial\hat y_i}$로 표시한다. 다른 행들의 손실은 이 예측값을 바꿔도 그대로이고, 해당 행의 제곱오차만 변하므로 다음 결과가 나온다.

<div class="boost-math">
$$
\frac{\partial J}{\partial\hat y_i}
=\frac1n\cdot2(\hat y_i-y_i),
\qquad
-\frac{\partial J}{\partial\hat y_i}
=\frac2n(y_i-\hat y_i)
$$
</div>

잔차에 양의 상수 $2/n$이 곱해진 형태다. 따라서 손실을 낮추는 방향은 같지만, 손실을 어떻게 정의하든 미분값이 잔차와 숫자까지 항상 같다고 말할 수는 없다.

## 10. 학습률과 손실 함수가 바뀌면 무엇이 달라질까

<strong>학습률(learning rate)</strong>은 새 트리의 보정 예측을 얼마나 반영할지 정한다. 학습률을 $\eta$로 표시하면 갱신식은 다음과 같다.

<div class="boost-math">
$$
\text{새 전체 예측}
=\text{현재 전체 예측}+\eta\times\text{새 트리의 보정 예측}
$$
</div>

앞의 수치 예제는 $\eta=1$이어서 보정을 전부 반영했다. 학습률을 0.1로 두면 첫 번째 트리의 A에 대한 보정 −4 중 10%만 적용한다.

<div class="boost-math">
$$
10+0.1\times(-4)=9.6
$$
</div>

그러면 A의 다음 잔차는 $5-9.6=-4.6$이다. 학습률 1일 때의 다음 잔차 −1과 다르다. <strong>학습률을 바꾸면 다음 트리가 학습할 목표도 달라진다.</strong> 이미 학습률 1로 만든 트리들의 출력을 마지막에 0.1배 하는 것과, 처음부터 학습률 0.1로 새 트리들을 학습하는 것은 다른 과정이다.

작은 학습률은 한 단계의 보정을 작게 만든다. 따라서 비슷한 학습 오차까지 내려가는 데 더 많은 트리가 필요할 수 있다. 학습률과 트리 개수는 함께 비교해야 하며, 크게 보정한다고 성능이 반드시 좋아지는 것은 아니다.[^boosting]

### 분류 부스팅에서는 숫자 점수를 보정한다

지금까지 계산한 잔차 평균은 <strong>제곱오차 회귀</strong>에 대한 설명이다. 그래디언트 부스팅에는 다른 손실 함수도 사용할 수 있고, 그에 따라 새 모델의 학습 목표와 리프 값 계산이 달라진다.[^ensemble]

예를 들어 구매·미구매를 구분하는 이진 분류에서는 전체 모델이 먼저 숫자 점수를 만들고, 이 점수를 0과 1 사이의 확률로 바꿀 수 있다. 이때 사용하는 <strong>시그모이드(sigmoid)</strong>는 숫자 점수를 확률로 변환하는 함수다.

로그 손실을 사용하는 일반적인 이진 분류 부스팅에서는 각 회귀트리가 이 <strong>확률 이전의 점수를 보정</strong>한다. 로그 손실은 실제 정답 범주에 낮은 확률을 줄수록 큰 값을 주는 평가 기준이다. 트리들의 점수 보정을 합친 뒤 확률을 계산하므로, 회귀 예제의 보정값을 그대로 확률에 더한다고 생각하면 안 된다.

전체 모델은 분류를 수행하지만, 그 안의 개별 트리는 숫자 보정값을 출력하는 회귀트리다. 또한 scikit-learn의 `GradientBoostingClassifier`는 이진 분류에서는 단계당 회귀트리 하나를, 다중 분류에서는 단계당 범주 수만큼의 회귀트리를 학습한다. <strong>한 단계에 트리 하나라는 설명은 앞의 회귀 예제를 기준으로 한 것</strong>이다.[^boosting-classifier]

부스팅 전체가 항상 단순한 잔차를 학습하는 것도 아니다. AdaBoost처럼 학습 자료에 주는 가중치를 조절해 다음 모델의 학습에 반영하는 방법도 있다. 알고리즘의 이름과 손실 함수를 함께 확인해야 한다.[^ensemble]

## 11. 트리를 계속 늘릴 때는 새 데이터의 성능을 확인한다

랜덤 포레스트에서 트리를 추가하면 평균에 참여하는 집값 예측이 하나 늘어난다. 기존 트리들이 잘못 예측한 집을 찾아서 그 오차만 학습하도록 새 트리를 만드는 것은 아니다. 서로 다른 표본과 조건에서 얻은 예측을 더 많이 평균 내는 것이다.

평균에 들어가는 예측이 많아지면 특정 트리 하나의 영향은 작아진다. 그 결과 무작위 학습 과정에 따른 예측의 변동은 대체로 줄지만, 비슷한 예측을 더 모아도 개선 폭은 점점 작아질 수 있다. 유한한 검증 자료에서 점수가 매번 일정하게 좋아진다는 보장은 없다.[^ensemble]

부스팅에서 새 트리는 현재 전체 예측의 남은 차이를 학습한다. 단계를 더 진행하면 집값과 특성 사이의 관계를 더 자세히 표현할 수 있지만, 학습 자료에만 우연히 나타난 차이까지 따라갈 수도 있다.

<strong>과적합(overfitting)</strong>은 학습 자료에 지나치게 맞춘 결과, 그 성능이 새로운 자료에서도 유지되지 않는 상태다. 부스팅뿐 아니라 깊은 단일 트리와 랜덤 포레스트에서도 확인해야 한다. 특히 앞 예제의 학습 MSE 0은 새 집의 실제 가격을 맞힌 증거가 아니다.

| 비교할 내용 | 회귀 랜덤 포레스트 | 제곱오차 회귀 그래디언트 부스팅 |
| --- | --- | --- |
| 각 트리의 학습 목표 | 추출한 집의 원래 집값 | 현재 전체 예측의 잔차 |
| 다른 트리의 결과가 필요한 시점 | 각 트리의 학습은 따로 진행할 수 있다. | 다음 트리의 목표를 구하려면 앞 단계의 예측이 필요하다. |
| 새 집의 최종 예측 | 트리별 집값 예측의 평균 | 초기 예측에 학습률을 적용한 보정값들을 합산 |
| 트리를 늘리는 효과 | 평균에 사용하는 예측이 늘어난다. | 현재 예측을 고치는 단계가 늘어난다. |
| 함께 확인할 점 | 개선 폭이 작아지는지, 깊은 트리의 오차가 여전히 남는지 | 검증 성능이 좋아지는지, 보정을 계속하면서 과적합하는지 |

두 방법 모두 트리 수를 늘리면 학습·예측에 필요한 계산과 모델을 저장할 공간이 늘어날 수 있다. 랜덤 포레스트의 트리들은 따로 학습하기 쉬운 반면, 부스팅은 앞 단계의 결과로 다음 목표를 만들기 때문에 트리 전체를 한꺼번에 학습할 수 없다. 다만 이것이 각 단계 내부의 계산까지 모두 병렬화할 수 없다는 뜻은 아니다.

### 학습용·검증용·테스트용 자료의 역할을 나눈다

실제 분석에서는 먼저 무엇을 예측할지 정하고, 각 컬럼의 의미와 값이 적절한지 확인한다. 결측값, 중복 기록, 현실적으로 불가능한 값도 점검한다. 그다음 목적에 따라 자료를 나눈다.

| 자료 | 사용하는 목적 |
| --- | --- |
| 학습용 | 분할 조건, 리프 값, 초기 평균, 단계별 잔차를 학습한다. |
| 검증용 | 트리 깊이·개수·학습률처럼 사람이 정하는 설정을 비교한다. |
| 테스트용 | 설정 선택을 마친 뒤 최종 성능을 평가한다. |

이런 설정값을 <strong>하이퍼파라미터(hyperparameter)</strong>라고 한다. 아래 값들은 서로 다른 부분을 조절한다.

| 설정 | 조절하는 부분 |
| --- | --- |
| `max_depth` | 개별 트리의 깊이 상한 |
| `min_samples_leaf` | 리프 하나에 남겨야 하는 최소 학습 표본 수 |
| `n_estimators` | 포레스트에서는 트리 수, 그래디언트 부스팅에서는 학습 단계 수 |
| `max_features` | 배깅에서는 모델별 입력 컬럼 수, 포레스트에서는 노드별 분할 후보 컬럼 수 |
| `learning_rate` | 부스팅에서 새 보정을 반영하는 크기 |
| `random_state` | 무작위 선택을 같은 조건에서 재현하기 위한 설정 |

`random_state=42`의 42에 정확도를 특별히 높여 주는 성질은 없다. 같은 조건으로 비교하기 위한 숫자다.

부스팅에서는 <strong>조기 종료(early stopping)</strong>를 사용할 수도 있다. 검증 성능이 일정한 기준으로 더 이상 개선되지 않으면 학습을 끝내는 방법이다. 조기 종료를 설정하면 지정한 `n_estimators`에 도달하기 전에 멈출 수 있다. 앞의 세 트리 예제에는 조기 종료를 설정하지 않았다.[^boosting]

학습에 사용하면 안 되는 정보가 모델 학습에 들어가거나, 최종 평가용 테스트 자료가 설정 선택에 사용되는 문제를 <strong>데이터 누수(data leakage)</strong>라고 한다. 예를 들어 부스팅의 초기 평균은 학습용 정답에서만 계산해야 한다. 검증·테스트용 집값까지 함께 평균 내거나, 그 자료를 새 트리의 잔차 학습에 포함하면 평가용 정답이 학습에 들어간다. 전처리에서 평균 등의 기준을 구할 때도 같은 원칙을 적용한다.[^pitfalls]

설정은 검증용 자료에서 비교하고, 선택을 끝낸 뒤 테스트용 자료에서 평가한다. 네 행으로 만든 계산 예제는 트리들이 결합되는 원리를 보여 준다. 실제 문제에서 어느 방법이 좋은지는 별도로 확보한 자료와 그 문제에 맞는 평가로 확인해야 한다.

## 12. 전체 계산을 Python으로 실행한다

아래 코드는 같은 집 4채로 단일 회귀트리, 배깅, 랜덤 포레스트를 만든 다음, 부스팅의 학습 과정을 직접 반복한다. 마지막에는 scikit-learn의 전체 부스팅 모델을 학습해서 같은 결과가 나오는지 확인한다. 필요한 패키지는 NumPy와 scikit-learn이다.

<strong>NumPy는 여러 숫자를 배열로 다루고 계산하는 Python 라이브러리</strong>다. 코드에서 새로 사용하는 함수와 메서드는 다음과 같다.[^numpy]

| 이름과 종류 | 입력과 반환값 |
| --- | --- |
| `np.array(...)` 함수 | 목록의 값들로 NumPy 배열을 만든다. 중첩된 행 목록은 2차원 배열이 된다. |
| `np.full(shape, fill_value)` 함수 | 지정한 크기의 배열을 만들고 모든 원소를 같은 값으로 채운다. |
| `y.mean()` 메서드 | 이 코드에서는 집값 네 개의 평균인 숫자 10을 반환한다. |
| `np.mean(...)` 함수 | 이 코드에서는 집별 제곱오차 네 개를 받아 평균 숫자를 반환한다. |
| `trees.append(tree)` 메서드 | 학습한 트리 객체를 리스트 끝에 추가한다. 반환값은 `None`이다. |
| `tree.apply(X)` 메서드 | 각 행이 도달한 리프의 노드 번호를 반환한다. 이 예제에서는 `(4,)`다. |
| `boosting.staged_predict(X)` 메서드 | 단계별 전체 예측 배열을 차례로 제공한다. 각 배열은 `(4,)`다. |

NumPy에서 같은 크기의 배열끼리 `y - current_prediction`을 계산하면 같은 위치의 원소끼리 뺀다. `** 2`는 각 원소를 제곱한다. 그래서 `np.mean((y - current_prediction) ** 2)`가 네 집 전체의 MSE다.

포레스트의 개별 예측을 모은 `forest_outputs`는 <strong>트리 세 개 × 새 집 한 채</strong>이므로 크기가 `(3, 1)`이다. `mean(axis=0)`은 이 배열에서 트리 세 개가 놓인 첫 번째 차원을 평균으로 줄인다. 그러면 <strong>그 집 하나의 평균 예측</strong>을 담은 `(1,)` 배열이 남는다. 집을 여러 채 넣으면 각 집의 위치를 유지하면서 트리들의 예측을 평균 낸다.

`tree.tree_`는 학습된 내부 트리 구조를 담은 속성이다. `tree_.node_count`는 노드 수이고, `get_depth()`는 실제 깊이를 반환한다. `apply(X)`에서 나오는 1과 2는 <strong>개별 트리 안의 리프 번호</strong>다.

한편 `boosting.estimators_`는 학습한 개별 트리들을 담은 속성이다. 이번에는 크기가 `(3, 1)`로, 세 단계마다 회귀트리 하나가 있다. `boosting.estimators_[0, 0]`은 첫 번째 완성된 트리 객체다. Python의 위치 번호는 0에서 시작한다.[^regressor][^boosting]

수동 반복에서 `tree.fit(X, residual)`에 잔차를 전달했던 것과 달리, <strong>전체 모델의 `boosting.fit(X, y)`에는 실제 집값 `y`를 전달한다.</strong> 이 호출 안에서 라이브러리가 초기 예측과 단계별 학습 목표를 계산하고, 개별 트리를 순서대로 학습한다. 전체 모델의 `fit()` 한 번 안에 여러 트리의 학습이 들어 있는 셈이다.

[실행할 Python 파일 내려받기](/random-forest-gradient-boosting/examples-ko.py)

```python
"""집 4채로 결정트리, 배깅, 랜덤 포레스트, 회귀 부스팅의 계산을 확인한다.

필요한 패키지: numpy, scikit-learn.
데이터는 계산 과정을 설명하기 위한 가상 자료다. 집값의 단위는 억 원이다.
모든 행의 가중치는 같고, 회귀트리는 제곱오차를 기준으로 학습한다.
"""

import numpy as np
from sklearn.tree import DecisionTreeRegressor
from sklearn.ensemble import (
    BaggingRegressor,
    RandomForestRegressor,
    GradientBoostingRegressor,
)

# 한 행은 집 한 채다. 컬럼 순서는 [역세권, 리모델링, 주차장]이다.
# 각 입력의 0은 아니오, 1은 예를 뜻한다.
X = np.array([
    [0, 0, 1],  # 집 A
    [0, 1, 0],  # 집 B
    [1, 0, 0],  # 집 C
    [1, 1, 1],  # 집 D
])
y = np.array([5.0, 7.0, 11.0, 17.0])  # 같은 순서의 실제 집값
new_X = np.array([[1, 0, 1]])  # 새 집 E: 1행, 3컬럼. 실제 집값은 모른다.

print("입력과 정답의 크기:", X.shape, y.shape)  # (4, 3), (4,)

# 1. 집값 자체를 학습하는 회귀트리 하나를 만든다.
single_tree = DecisionTreeRegressor(
    criterion="squared_error",  # 분할 조건을 제곱오차로 평가한다.
    max_depth=1,                # 루트 깊이 0에서 깊이 1까지만 허용한다.
    random_state=42,            # 무작위 선택을 재현하기 위한 설정이다.
)
fit_result = single_tree.fit(X, y)  # 트리 전체의 조건과 리프 값을 학습한다.
assert fit_result is single_tree   # fit의 반환값은 모델 객체 자신이다.
print("집값을 직접 학습한 트리:", single_tree.predict(X))  # [6, 6, 14, 14]

# 2. 서로 다른 학습 표본으로 모델 세 개를 학습하는 배깅이다.
bagging = BaggingRegressor(
    estimator=DecisionTreeRegressor(max_depth=1),
    n_estimators=3,
    bootstrap=True,    # 학습 행을 복원추출한다.
    max_features=1.0,   # 각 모델에 전체 컬럼을 전달한다.
    random_state=42,
)
bagging.fit(X, y)       # 각 모델은 추출된 집의 원래 집값을 학습한다.
print("배깅의 모델 수:", len(bagging.estimators_))  # 3

# 3. 랜덤 포레스트의 max_features는 노드에서 검토할 후보 컬럼 수다.
forest = RandomForestRegressor(
    n_estimators=3,
    max_depth=1,
    bootstrap=True,
    max_features=2,    # 이 예제에서는 각 분할에서 후보 컬럼 두 개를 선택한다.
    random_state=42,
)
forest.fit(X, y)

# 각 트리는 같은 새 집에 대한 집값을 예측한다. 결과들을 평균 내면 최종 예측이다.
forest_outputs = np.array([tree.predict(new_X) for tree in forest.estimators_])
print("포레스트의 개별 집값 예측:", forest_outputs)
print("포레스트의 평균 집값 예측:", forest.predict(new_X))
np.testing.assert_allclose(forest.predict(new_X), forest_outputs.mean(axis=0))

# 4. 부스팅의 바깥 반복을 직접 작성한다. 앞의 모델들과 별도로 학습한다.
initial_value = y.mean()  # 학습 정답의 평균 10.0을 계산한다.
learning_rate = 1.0      # 이번 계산에서는 새 보정값을 전부 반영한다.
current_prediction = np.full(y.shape, initial_value)  # [10, 10, 10, 10]
trees = []              # 학습한 트리를 보관할 리스트다.

print("초기 전체 예측:", current_prediction)
print("초기 MSE:", np.mean((y - current_prediction) ** 2))  # 21.0

# range(1, 4)는 1, 2, 3을 차례로 제공한다. 마지막 4는 포함하지 않는다.
for step in range(1, 4):
    residual = y - current_prediction  # 각 집의 현재 잔차를 계산한다.

    # 반복할 때마다 별도의 새 트리를 만든다.
    tree = DecisionTreeRegressor(
        criterion="squared_error",
        max_depth=1,
        random_state=42,
    )
    tree.fit(X, residual)       # 이 새 트리 전체를 잔차에 맞춰 학습한다.
    correction = tree.predict(X)  # 각 집의 보정값 네 개를 계산한다.

    # 새 트리의 예측을 기존 전체 예측에 더한다.
    current_prediction = current_prediction + learning_rate * correction
    trees.append(tree)         # 완성된 트리를 저장한다. 이전 트리는 수정하지 않는다.
    mse = np.mean((y - current_prediction) ** 2)

    print(f"\n부스팅 {step}단계")
    print("학습 목표인 잔차:", residual)
    print("새 트리의 보정 예측:", correction)
    print("갱신된 전체 집값 예측:", current_prediction)
    print("전체 MSE:", mse)    # 단계별로 5.0, 1.0, 0.0

np.testing.assert_allclose(current_prediction, y)

# 5. 학습한 트리 내부를 확인한다. 인덱스 0은 첫 번째 원소를 뜻한다.
first_tree = trees[0]
print("첫 트리의 실제 깊이:", first_tree.get_depth())       # 1
print("첫 트리의 노드 수:", first_tree.tree_.node_count)     # 3
print("집별 리프 노드 번호:", first_tree.apply(X))           # [1, 1, 2, 2]

# 6. 새 집을 예측한다. fit이나 실제 잔차 계산은 하지 않는다.
new_prediction = np.full(new_X.shape[0], initial_value)  # 집 한 채의 시작값 [10]
for tree in trees:
    new_prediction = new_prediction + learning_rate * tree.predict(new_X)

print("\n새 집 E의 부스팅 예측:", new_prediction)  # [13.]
np.testing.assert_allclose(new_prediction, [13.0])

# 7. 같은 설정으로 라이브러리의 전체 부스팅 모델을 학습한다.
boosting = GradientBoostingRegressor(
    loss="squared_error",  # 전체 모델이 줄일 손실을 지정한다.
    n_estimators=3,        # 보정 트리 세 개를 순서대로 학습한다.
    max_depth=1,           # 개별 트리마다 적용하는 깊이 상한이다.
    learning_rate=1.0,
    random_state=42,
)
boosting.fit(X, y)  # 실제 집값을 전달한다. 라이브러리가 내부 잔차를 계산한다.

print("라이브러리의 새 집 예측:", boosting.predict(new_X))  # [13.]
print("내부 트리 배열의 크기:", boosting.estimators_.shape)  # (3, 1)

# staged_predict는 각 단계까지 누적한 전체 예측 배열을 차례로 제공한다.
for stage_prediction in boosting.staged_predict(X):
    print("라이브러리의 단계별 전체 예측:", stage_prediction)

# 두 구현이 이 데이터와 설정에서 같은 결과를 내는지 검사한다.
# assert_allclose는 값이 허용 오차 안에서 같으면 통과하고, 다르면 오류를 낸다.
np.testing.assert_allclose(boosting.predict(X), current_prediction)
np.testing.assert_allclose(boosting.predict(new_X), new_prediction)
```

이 코드에서 직접 반복한 부스팅과 `GradientBoostingRegressor`는 모두 단계별 예측 `[6, 6, 14, 14]`, `[4, 8, 12, 16]`, `[5, 7, 11, 17]`을 반환한다. 새 집 E에 대한 결과도 둘 다 `[13.]`이다. `13.`은 실수 13.0을 표시한 것이다.

포레스트는 이 코드의 설정에서 새 집 E를 각각 17·17·9로 예측한 세 트리를 사용하고, 최종적으로 $(17+17+9)/3\approx14.3333$을 출력한다. 부스팅의 13과 서로 다른 예측이지만, E의 실제 집값이 없으므로 두 숫자만 보고 어느 모델이 정확한지 판단할 수 없다.

예제는 <strong>scikit-learn 1.8.0, NumPy 2.3.5</strong>에서 실행해 수동 부스팅과 라이브러리 결과가 일치하는 것을 확인했다. 수동 반복은 제곱오차 회귀의 처리 순서를 드러낸 구현이며, scikit-learn 내부 소스 전체를 재현한 것은 아니다. 공식 문서는 2026년 10월 18일 기준으로 확인했다.
