부리 길이와 몸무게 같은 측정값으로 펭귄의 종류를 구분하려고 한다. 결정트리는 이런 입력에 조건을 차례로 적용해 종류를 예측한다. 학습할 때는 정답이 붙은 자료를 사용해 **어느 특징을 어느 값과 비교할지** 정하고, 예측할 때는 **이미 정한 조건을 새 입력에 적용**한다.

중요한 것은 조건을 잘게 나누는 일 자체가 아니다. 학습 자료를 완벽하게 구분한 트리라도 새로운 펭귄을 잘못 분류할 수 있다. 따라서 조건을 고르는 계산과 학습이 끝난 모델을 평가하는 일을 구분해야 한다.

먼저 입력·학습·예측의 관계와 트리 구조를 살펴본다. 이어서 여섯 개의 가상 샘플로 분할 조건을 계산하고, 펭귄 분류 실험표에서 트리 크기와 검증 정확도가 어떻게 달라지는지 읽는다. 마지막에는 계산용 데이터와 실행 코드를 함께 제시한다.

## 1. 입력과 정답을 나누고, 학습과 검증을 나눈다

**샘플(sample)**은 관측한 대상 한 개다. 펭귄 데이터에서는 한 행이 펭귄 한 마리를 나타낸다. **특성 또는 특징(feature)**은 예측에 사용할 입력 정보이고, **클래스(class)**는 분류하려는 정답 종류다. **라벨(label)**은 각 샘플에 붙인 정답 표시다.

라벨을 0·1·2로 저장했다면 이 숫자는 종류를 구분하는 코드다. 0이 오답이고 1이 정답이라는 뜻이 아니다. 코드가 실제로 어떤 종류를 나타내는지는 데이터의 정의에서 확인해야 한다.

입력은 `X`, 실제 정답은 `y`로 구분한다. 여기에 데이터를 사용하는 목적에 따라 `train`과 `val`을 붙인다. 학습 자료 204개, 검증 자료 69개에 각각 특징 네 개가 있다면 다음과 같다.

| 이름 | 담고 있는 정보 | 형태 |
| --- | --- | --- |
| `X_train` | 학습할 펭귄들의 입력 특징 | `(204, 4)` |
| `y_train` | 바로 그 펭귄들의 실제 정답 | `(204,)` |
| `X_val` | 검증할 펭귄들의 입력 특징 | `(69, 4)` |
| `y_val` | 바로 그 검증 펭귄들의 실제 정답 | `(69,)` |

**`shape`는 차원별 크기**다. `(204, 4)`는 204행과 네 컬럼을 가진 2차원 입력이다. `(204,)`는 정답 204개가 담긴 1차원 배열이며, 마지막 쉼표는 두 번째 차원을 생략했다는 뜻이 아니다.

`X_train`과 `y_train`은 학습 자료와 검증 자료가 아니다. **같은 학습 대상의 입력과 정답**이다. 모델은 입력값으로 자료를 나누고, 그 자료들의 정답을 확인해 분할이 클래스를 잘 구분하는지 판단한다. 그래서 `fit(X_train, y_train)`에 둘 다 필요하다.

입력의 첫 번째 행과 정답의 첫 번째 값은 같은 펭귄을 가리켜야 한다. 개수만 같아서는 부족하다. 정답만 따로 정렬하면 다른 펭귄의 정답을 연결할 수 있다. 자료형을 배열로 바꾸는 것만으로 이런 대응 오류가 복구되지는 않는다.

### 데이터를 사용하는 목적을 먼저 고정한다

**학습**은 예측에 필요한 값이나 구조를 데이터로 결정하는 과정이다. **검증**은 후보 모델을 비교하기 위한 평가다. **테스트**는 설정 선택이 끝난 뒤 별도로 남겨 둔 자료로 하는 최종 평가다.

```text
입력 X와 실제 정답 y를 준비한다.
    ↓
학습·검증·최종 테스트에 사용할 자료를 구분한다.
    ↓
모델을 생성하고 설정을 지정한다.
    ↓
fit: 학습 자료로 분할 조건과 트리 구조를 구한다.
    ↓
predict: 검증 입력에 조건을 적용해 클래스를 예측한다.
    ↓
accuracy_score: 예측과 검증 정답을 비교한다.
    ↓
검증 점수와 트리 크기를 비교해 설정을 선택한다.
    ↓
별도 테스트 자료로 최종 성능을 평가한다.
```

검증 입력에는 학습 때와 같은 특징을 같은 컬럼 순서로 넣는다. 전처리가 있다면 학습 자료에서 정한 기준을 검증에도 적용한다. 평가에 남겨 둔 자료로 전처리 기준을 구하면 평가용 정보가 학습에 들어가는 **데이터 누수**가 발생한다.[^pitfalls]

## 2. 모델 생성, 학습, 예측은 서로 다른 작업이다

`DecisionTreeClassifier`는 분류용 결정트리 객체를 만드는 **Python 클래스**다. 여기서 객체는 생성해서 실제로 사용하는 개별 모델이다. 객체에 속한 함수는 **메서드**, 객체가 제공하는 값은 **속성**이라고 한다. Python의 클래스와 분류할 정답 종류를 뜻하는 클래스는 서로 다른 개념이다.

| 코드 | 하는 일 | 반환하는 것 |
| --- | --- | --- |
| `DecisionTreeClassifier(...)` | 설정을 가진 모델을 만든다. | 아직 학습하지 않은 모델 객체 |
| `model.fit(X_train, y_train)` | 학습 입력과 정답으로 트리를 만든다. | 학습한 모델 객체 자신 |
| `model.predict(X_val)` | 학습한 조건으로 검증 입력을 예측한다. | 샘플별 예측 라벨 배열 |
| `accuracy_score(y_val, val_pred)` | 실제 정답과 예측 라벨을 비교한다. | 기본 설정에서는 정확도 숫자 |

모델을 생성하는 코드에는 아직 학습 데이터가 들어가지 않는다. `fit`을 호출해야 데이터로 조건을 구한다. 또한 `fit`의 반환값은 평가 결과가 아니라 모델 자신이다. 예측 결과는 `predict`로 구하고 평가 함수에 따로 전달한다.[^classifier]

### 결정트리의 학습은 경사하강법이 아니다

**경사하강법**은 오차를 나타내는 함수의 기울기를 이용해 학습할 숫자를 조금씩 갱신하는 방법이다. 머신러닝의 모든 학습이 이 방법을 사용하는 것은 아니다.

결정트리는 컬럼과 기준값의 조합을 비교해 분할 조건을 선택한다. 학습 후에는 검사할 특징의 번호, 기준값, 다음 조건으로 이어지는 연결 관계, 각 부분에 속한 자료의 클래스 구성 등이 저장된다. **결정트리가 학습하는 것은 입력을 구분할 조건과 그 조건들의 연결 구조다.**[^tree]

`random_state=41`은 학습 중 무작위 선택을 재현하기 위한 설정이다. 같은 데이터와 나머지 조건을 유지하며 실험을 비교할 때 사용한다. `criterion="gini"`는 조건을 고르는 기준으로 지니 불순도를 사용한다는 뜻이며 기본값이다. 지니의 계산은 5절에서 다룬다.

### 정확도는 정답 두 묶음을 비교한 비율이다

`accuracy_score`는 모델 객체를 받지 않는다. 실제 정답과 **이미 계산한 예측값**을 받아 같은 대상끼리 비교한다. 기본 설정의 정확도는 다음과 같다.[^accuracy]

$$
\text{정확도}=\frac{\text{맞힌 개수}}{\text{평가한 전체 개수}}
$$

맞힌 개수를 전체 개수로 나누면 전체에서 차지하는 비율이 된다. 검증 자료 69개 중 67개를 맞혔다면 다음과 같다.

$$
\frac{67}{69}\approx0.971014\approx97.10\%
$$

정답 배열과 예측 배열을 `==`로 비교하면 각 위치에 `True` 또는 `False`가 나온다. 이를 합산하면 `True`는 1, `False`는 0으로 계산되므로 맞힌 개수를 얻는다.

학습 자료를 다시 예측해서 계산한 값은 **학습 정확도**, 그 모델의 학습에 쓰지 않은 검증 자료에서 계산한 값은 **검증 정확도**다. 두 값의 차이를 `gap = train_accuracy - validation_accuracy`로 기록할 수 있다. `gap=0.05`는 5%포인트 차이다. 두 점수가 모두 낮으면 차이가 작더라도 성능이 좋은 모델이라고 할 수 없다.

## 3. 노드, 리프, 깊이는 각각 무엇을 세는가

**노드(node)**는 조건이나 클래스 분포를 가진 트리의 구성 요소다. 시작 노드는 **루트(root)**라고 한다. 조건을 검사해 다음 노드를 선택하는 곳은 **분할 노드**, 자식이 없어 예측을 마치는 곳은 **리프(leaf)**다.

**이진트리**는 각 노드가 최대 두 자식과 연결되는 구조다. 분할 노드에는 자식이 둘 있고 리프에는 없다. 여기서 ‘이진’은 두 갈래로 나눈다는 뜻이지 정답 종류가 두 개라는 뜻이 아니다. 정답이 세 종류 이상인 문제도 이진트리로 분류할 수 있다.

예측 경로를 살펴보기 위해 다음 트리를 사용하자. `x1`은 숫자로 표현된 입력 특징 하나이고, 클래스 0과 1은 구분하려는 두 종류다. 노드 앞의 숫자는 각 노드를 구별하는 **노드 ID**다.

```text
노드 0: x1 <= 0.5 ?                           깊이 0
│
├─ 참   → 노드 1: 클래스 0을 예측 [리프]        깊이 1
│
└─ 거짓 → 노드 2: x1 <= 1.5 ?                 깊이 1
             │
             ├─ 참   → 노드 3: 클래스 0 [리프]  깊이 2
             │
             └─ 거짓 → 노드 4: 클래스 1 [리프]  깊이 2
```

노드 1은 이미 리프다. 노드 3과 4로 이어지는 것은 노드 2다. 리프는 노드 1·3·4로 총 세 개이며, 같은 깊이에 있을 필요도 없다. 서로 다른 리프가 모두 클래스 0을 예측할 수 있으므로 **리프 수와 클래스 수는 다르다.**

| 구분 | 위 트리의 값 | 뜻 |
| --- | --- | --- |
| 노드 ID | 0·1·2·3·4 | 각 노드를 구별하는 번호 |
| 예측 클래스 | 0·1 | 정답 종류 |
| 리프 수 | 3 | 자식 없는 최종 노드의 개수 |
| 실제 최대 깊이 | 2 | 루트부터 가장 깊은 리프까지의 연결 개수 |

노드나 리프의 개수만으로 학습 샘플 수는 알 수 없다. 여러 샘플이 하나의 리프에 속할 수 있기 때문이다.

### 깊이는 루트의 0부터 센다

깊이는 루트에서 해당 노드까지 거친 **연결의 개수**다. 루트에서는 아직 연결을 건너지 않았으므로 깊이가 0이다.

`max_depth=2`는 루트까지 포함해 최대 세 층, `max_depth=3`은 최대 네 층을 허용한다. 깊이가 한 단계 늘 때마다 각 노드가 최대 둘로 나뉠 수 있으므로 가능한 최대 리프 수는 `1 → 2 → 4 → 8`처럼 증가한다. 최대 깊이가 $d$이면 리프 수의 상한은 $2^d$다.

`max_depth`는 **허용 상한**, `model.get_depth()`는 **실제로 만들어진 최대 깊이**다. 상한을 4로 정해도 그 전에 분할이 끝나면 실제 깊이는 4보다 작다. `model.get_n_leaves()`는 실제 리프 수를 반환한다.[^classifier]

`max_depth=None`은 깊이 상한을 지정하지 않는다는 뜻이다. 모든 자료가 한 클래스인 부분, 유효한 분할이 없는 부분, 최소 샘플 수 조건에 걸리는 부분에서는 분할을 멈춘다. 실제 깊이는 0일 수도 있지만 `max_depth` 설정에는 양의 정수 또는 `None`을 사용한다.

## 4. 한 입력의 예측 경로를 따라간다

앞의 트리에 `x1=1`을 넣으면 다음 계산이 일어난다.

| 순서 | 조건 | 결과 |
| --- | --- | --- |
| 1 | 노드 0에서 `1 <= 0.5` | 거짓이므로 오른쪽 노드 2를 선택한다. |
| 2 | 노드 2에서 `1 <= 1.5` | 참이므로 왼쪽 노드 3을 선택한다. |
| 3 | 노드 3은 리프다. | 저장된 클래스 분포로 예측을 마친다. |

이동한다는 것은 원본 데이터의 저장 위치를 바꾼다는 뜻이 아니라 **다음 계산에 사용할 노드를 선택한다는 뜻**이다. 왼쪽이면 항상 클래스 0이 되는 것도 아니다. 방향은 조건의 결과이고, 예측 클래스는 도착한 리프의 정보로 결정한다.

노드 3의 클래스 비율이 `{0: 0.5, 1: 0.5}`라면 두 클래스의 비중이 같다는 뜻이다. 가중치를 지정하지 않은 학습에서는 이 리프에 속한 학습 샘플의 클래스 비율이다. **검증 정확도가 50%라는 뜻은 아니다.** 비율만으로 리프의 샘플 개수도 알 수 없다.

이 분류기는 가장 높은 클래스 비율이 동률이면 `classes_`에 저장된 순서에서 앞선 클래스를 선택한다. 클래스 순서가 `[0, 1]`이라면 예측은 0이다. 실제 정답이 1인 입력이었다면 그 예측은 틀린 것이다.[^classifier]

### 예측값과 노드 정보는 서로 다른 반환값이다

| 기능 | 반환하거나 보여 주는 것 |
| --- | --- |
| `export_text(model, ...)` | 트리 전체의 조건과 리프 예측을 표현한 문자열 |
| `model.predict(X)` | 각 입력의 예측 클래스 |
| `model.predict_proba(X)` | 각 입력의 클래스별 확률 |
| `model.apply(X)` | 각 입력이 도착한 리프의 노드 ID |
| `model.decision_path(X)` | 각 입력이 어떤 노드를 사용했는지 나타내는 행렬 |

`apply`의 `[3]`은 클래스 3이 아니라 **노드 ID가 3인 리프**를 가리킨다. `predict_proba`의 반환 형태는 `(샘플 수, 클래스 수)`이며 클래스 순서는 `classes_`로 확인한다.[^structure]

`decision_path`가 반환하는 행렬에서 행은 입력 샘플이고 열은 노드 ID다. 사용한 노드는 1, 사용하지 않은 노드는 0이다. 위의 입력이 `0 → 2 → 3`을 사용했으므로 다음과 같다.

```text
노드 ID       0  1  2  3  4
사용 여부    [1, 0, 1, 1, 0]
행렬 shape   (1, 5)
```

0이 많은 행렬을 **희소 행렬**이라고 한다. `decision_path`는 0이 아닌 값과 위치를 중심으로 저장하는 CSR 형식을 사용한다. 한 입력만 조회했다면 `.indices`에서 그 행의 노드 ID들을 확인할 수 있다. 여러 입력을 넣었다면 전체 `.indices`를 한 입력의 경로로 읽어서는 안 된다. 이 열 번호 목록 자체는 시간순 실행 로그도 아니다.[^csr]

`.toarray()`는 이를 일반 배열로 펼치는 메서드다. 작은 예제를 확인할 때는 편하지만 큰 행렬을 펼치면 메모리를 많이 사용할 수 있다. 자식 연결을 직접 읽을 때는 `model.tree_.children_left[node_id]`와 `children_right`를 사용한다. 자식 ID `-1`은 자식이 없다는 표시다.

### 한 행도 2차원 입력으로 유지한다

pandas의 `.iloc`은 정수 **위치**로 데이터를 고른다. 위치는 0부터 세고 슬라이스는 시작을 포함하되 끝은 제외한다. 특징이 네 개인 검증 자료에서 두 번째 샘플을 고르면 다음 차이가 생긴다.[^indexing]

| 선택 | 결과 | 형태 |
| --- | --- | --- |
| `X_val.iloc[1]` | 두 번째 행의 값들을 담은 Series | `(4,)` |
| `X_val.iloc[1:2]` | 두 번째 한 행을 가진 DataFrame | `(1, 4)` |
| `val_pred[1:2]` | 같은 위치의 예측값 하나를 가진 배열 | `(1,)` |

`predict`에는 `(샘플 수, 특징 수)`의 2차원 입력을 전달하므로 한 행도 `(1, 4)`로 유지한다. 이미 전체 예측을 계산했다면 같은 위치의 예측값을 선택해도 된다. 다만 그 뒤 모델을 재학습하거나 입력의 순서를 바꾸지 않아야 한다.

pandas Series의 인덱스 라벨과 배열 위치는 다르다. 정수 라벨을 가진 Series의 `y_val[1]`은 라벨 1인 값을, `y_val.iloc[1]`은 두 번째 위치의 값을 선택한다. NumPy 배열의 `[1]`은 두 번째 위치다.

앞의 경로 계산은 결측값이 없는 입력을 전제로 한다. 결측을 나타내는 `NaN`이 있거나 표시된 기준값이 반올림되었다면, 화면의 단순 비교식만으로 실제 분기를 단정하지 말고 모델의 조회 결과를 확인해야 한다.

## 5. 지니 불순도는 클래스가 섞인 정도를 계산한다

예측에서는 저장된 조건을 따라갔다. 이제 학습으로 돌아가 **어떤 조건을 저장할지** 살펴보자. 모델이 조건을 비교하려면 나뉜 자료의 클래스 구성을 숫자로 평가할 기준이 필요하다.

**지니 불순도(Gini impurity)**는 한 노드의 실제 정답이 한 종류에 모였는지, 여러 종류로 섞였는지를 나타낸다. 예측과 정답을 비교한 오답률이 아니다.

$K$는 클래스 수, $k$는 0부터 $K-1$까지의 클래스 번호다. $n_k$는 현재 노드에서 클래스 $k$인 샘플 수, $n$은 그 노드의 전체 샘플 수다. 여기서는 $n>0$이며 샘플·클래스 가중치를 따로 지정하지 않는다. $\sum$는 지정된 항들을 더하라는 기호다.

클래스 비율 $p_k$와 지니 $G$는 다음과 같다.[^tree]

$$
p_k=\frac{n_k}{n},\qquad
G=1-\sum_{k=0}^{K-1}p_k^2
$$

**더하는 단위는 샘플 한 개가 아니라 클래스 한 종류**다. 클래스가 둘이면 두 항, 셋이면 세 항을 더한다.

### 왜 비율을 그냥 더하지 않고 제곱할까?

클래스 비율을 그냥 더하면 항상 1이다. 한 종류가 대부분인 경우와 반씩 섞인 경우를 구별할 수 없다.

제곱은 자기 자신을 곱하는 연산이다. $0<p<1$에서는 $p^2<p$이므로 비율 자체는 더 작아진다. 예를 들어 $9/10=90/100$인데 이를 제곱하면 $81/100$이다. 분자뿐 아니라 분모도 달라진다.

동시에 서로 다른 양수의 상대적인 크기비는 제곱 뒤 더 벌어진다. $a>b>0$이면 다음이 성립한다.

$$
\frac{a^2}{b^2}=\left(\frac{a}{b}\right)^2>\frac{a}{b}
$$

$a/b$가 1보다 크기 때문에 제곱한 비율이 원래 비율보다 크다. 이는 두 값의 절대적인 차이가 언제나 커진다는 주장과는 다르다.

합이 1인 클래스 비율을 비교해 보자.

| 클래스 비율 | 비율의 제곱합 | 1에서 뺀 지니 |
| --- | --- | --- |
| `[0.9, 0.1]` | $0.81+0.01=0.82$ | $0.18$ |
| `[0.5, 0.5]` | $0.25+0.25=0.50$ | $0.50$ |

한 종류에 집중된 분포에서 제곱합이 더 크다. 이를 1에서 빼면 혼합이 적을수록 작은 점수가 나온다. 모든 샘플이 같은 클래스이면 지니는 0이다. 정해진 $K$개 클래스의 비율이 모두 같을 때 최대값은 $1-K(1/K)^2=1-1/K$다. 따라서 **0.5는 두 클래스일 때의 최대값**이다.

**MSE(평균제곱오차)**도 제곱을 사용하지만, 제곱하는 대상은 예측값과 실제 값의 차이다. 지니는 클래스 비율을 제곱한다. 같은 연산을 사용한다고 같은 대상을 평가하는 것은 아니다. 불순도를 측정하는 기준도 지니 하나뿐은 아니며 엔트로피라는 다른 기준이 있다.

### 여섯 개의 가상 샘플을 나누어 본다

다음 자료는 분할 계산을 확인하기 위한 가상 데이터다. `x1`과 `x2`는 단위를 부여하지 않은 숫자 특징이고, 0과 1은 두 정답 종류다. 앞에서 경로를 읽었던 트리와는 별도로 이 표의 분할을 계산한다.

| 샘플 번호 | x1 | x2 | 실제 클래스 |
| --- | --- | --- | --- |
| 1 | 1 | 1 | 0 |
| 2 | 2 | 2 | 0 |
| 3 | 3 | 4 | 0 |
| 4 | 4 | 3 | 1 |
| 5 | 5 | 5 | 1 |
| 6 | 6 | 6 | 1 |

조건 `x2 <= 2.5`를 적용하면 왼쪽에는 샘플 1·2, 오른쪽에는 샘플 3·4·5·6이 들어간다. 클래스 0과 1의 개수를 순서대로 적으면 왼쪽은 `[2, 0]`, 오른쪽은 `[1, 3]`이다.

오른쪽 전체 개수는 4이지만 지니에 필요한 정보는 **클래스별 개수 `[1, 3]`**다.

$$
G_R
=1-\left[\left(\frac14\right)^2+\left(\frac34\right)^2\right]
=1-\left(\frac1{16}+\frac9{16}\right)
=\frac6{16}
=0.375
$$

$1/4$과 $3/4$은 클래스 0과 1의 비율이다. 클래스 1인 샘플이 세 개라는 정보는 이미 $3/4$의 분자에 들어 있다. $(3/4)^2$을 세 번 더하면 같은 클래스 비율을 중복 계산한다.

왼쪽은 두 샘플 모두 클래스 0이므로 다음과 같다.

$$
G_L=1-\left[\left(\frac22\right)^2+\left(\frac02\right)^2\right]=0
$$

## 6. 자식들의 지니를 샘플 수에 따라 가중평균한다

왼쪽에는 두 샘플, 오른쪽에는 네 샘플이 있다. 지니 두 개를 더해 2로 나누면 크기가 다른 두 부분에 같은 비중을 준다. 전체 자료가 얼마나 섞였는지 평가하려면 각 부분이 차지하는 크기를 반영해야 한다.

**가중평균**은 각 값이 차지해야 할 비중을 반영하는 평균이다. $n_L$, $n_R$는 왼쪽과 오른쪽 샘플 수이고 $n=n_L+n_R$다. 자식 지니 $G_L$, $G_R$를 해당 샘플 수만큼 반영한 뒤 전체 샘플 수로 나누면 다음 식이 된다.

$$
\text{가중 지니}
=\frac{n_LG_L+n_RG_R}{n}
=\frac{n_L}{n}G_L+\frac{n_R}{n}G_R
$$

나눗셈은 각 자식의 데이터 비중을 구한다. 곱셈은 그 비중만큼 자식의 지니를 반영한다. 덧셈은 두 자식의 기여를 합친다.

방금 나눈 여섯 샘플에 적용하면 다음과 같다.

$$
\text{가중 지니}
=\frac26\times0+\frac46\times0.375
=0.25
$$

계산 순서는 **클래스별 개수 → 클래스 비율 → 자식별 지니 → 데이터 비중에 따른 가중평균**이다. 오른쪽 항에는 비율의 제곱합 $1/16+9/16$이 아니라, 이를 1에서 뺀 지니가 들어간다.

다른 후보인 `x2 <= 3.5`로 나누면 왼쪽은 `[2, 1]`, 오른쪽은 `[1, 2]`다. 양쪽 지니는 모두 $1-(4/9+1/9)=4/9$이고 샘플 수는 각각 세 개다. 가중평균도 $4/9\approx0.4444$가 된다.

같은 부모에서 비교하면 **0.25인 `x2 <= 2.5`가 0.4444인 후보보다 혼합을 더 많이 줄인다.** 이것은 학습 중 분할 조건을 비교한 결과이지 검증 정확도를 비교한 결과가 아니다.

## 7. 무한한 실수 대신 서로 다른 분할을 비교한다

기준값은 2.1, 2.11, 2.111처럼 계속 바꿀 수 있다. 결정트리는 가능한 모든 실수를 시험하지 않는다. **현재 학습 자료를 서로 다르게 나누는 경우**를 비교한다.

수치형 특징에 결측값이 없고 기본 `splitter="best"`를 사용하는 경우를 보자. 위 표의 `x2`를 정렬하면 `[1, 2, 3, 4, 5, 6]`이다. `x2 <= 2.1`과 `x2 <= 2.9`는 모두 값 1·2를 왼쪽에 넣으므로 학습 분할과 불순도가 같다.

서로 다른 인접값이 $a<b$일 때 조건 $x\le t$에서 $a\le t<b$인 기준값들은 같은 학습 분할을 만든다. 보통 $(a+b)/2$를 대표로 사용한다. 서로 다른 값이 $m$개라면 양쪽이 비지 않는 수치 분할의 경계는 최대 $m-1$개다.

다만 학습 분할이 같다고 미래의 모든 입력까지 같은 쪽으로 나뉘는 것은 아니다. 2.1과 2.9 사이의 새 값은 어떤 기준값을 저장했는지에 따라 다른 쪽으로 갈 수 있다.

### 정렬된 경계를 옮기며 개수를 갱신한다

`x2`를 정렬하면 샘플 순서는 `1, 2, 4, 3, 5, 6`이 된다. 정답도 그 샘플을 따라 `[0, 0, 1, 0, 1, 1]`로 움직여야 한다. 특징만 정렬하고 정답은 그대로 두면 다른 자료를 계산하게 된다.

처음에는 왼쪽 `[0, 0]`, 오른쪽 `[3, 3]`에서 시작한다. 경계를 오른쪽으로 옮길 때 새로 왼쪽에 들어오는 샘플의 클래스 개수만 갱신하면 된다.

| 기준값 | 왼쪽 클래스별 개수 | 오른쪽 클래스별 개수 | 가중 지니 |
| --- | --- | --- | --- |
| 1.5 | `[1, 0]` | `[2, 3]` | 0.4000 |
| 2.5 | `[2, 0]` | `[1, 3]` | 0.2500 |
| 3.5 | `[2, 1]` | `[1, 2]` | 0.4444 |
| 4.5 | `[3, 1]` | `[0, 2]` | 0.2500 |
| 5.5 | `[3, 2]` | `[0, 1]` | 0.4000 |

이렇게 하면 후보마다 모든 행의 정답을 처음부터 다시 세지 않아도 된다. 클래스별 점수를 계산하는 비용은 남는다. 실제 구현에는 추가 제약과 계산 최적화도 있으며 정렬이 학습 전체에서 단 한 번만 일어나는 것은 아니다.[^implementation]

위 표는 `x2` 하나의 후보 비교다. 모델은 검토한 **컬럼과 기준값의 조합**을 비교한다. 같은 자료에서 `x1 <= 3.5`를 사용하면 `[3, 0]`과 `[0, 3]`으로 나뉘므로 가중 지니는 0이다. `x2`에서 얻은 0.25를 모든 컬럼을 통틀어 최선이라고 말할 수 없는 이유다.

결정트리는 현재 노드에서 조건을 고른 뒤 자식에서 같은 과정을 반복한다. 미래의 모든 트리 구조를 전부 비교해 전체 최적해를 보장하는 방식은 아니다.[^tree]

## 8. 엔트로피와 정보 이득으로도 조건을 비교할 수 있다

**엔트로피(entropy)**는 클래스 구성의 불확실성을 측정하는 다른 기준이다. `criterion="gini"`는 지니를, `criterion="entropy"`는 엔트로피 감소를 기준으로 분할을 비교한다. 지니를 계산한 다음 엔트로피로 다시 채점하는 두 단계가 아니다.

엔트로피를 이해하려면 로그와 정보량을 먼저 연결해야 한다. **로그**는 지수의 역연산이다. $\log_2(p)=r$는 $2^r=p$라는 뜻이다. 확률 $p$인 결과의 **정보량**을 다음과 같이 정의한다.[^entropy]

$$
I(p)=-\log_2(p),\qquad 0<p\le1
$$

확실한 결과는 $p=1$이므로 정보량이 0이고, 드문 결과일수록 정보량이 커진다. $0<p<1$에서는 로그가 음수이므로 마이너스를 붙여 음이 아닌 값으로 바꾼다. 독립적인 결과들의 결합 확률이 곱으로 표현될 때 로그는 그 정보량을 합으로 표현하게 해 준다.

$$
-\log_2(pq)=-\log_2(p)-\log_2(q)
$$

엔트로피 $H$는 각 클래스의 정보량을 해당 클래스 비율로 **가중평균**한 값이다. 앞에서 정의한 $p_k$와 클래스 번호를 사용하면 다음과 같다.

$$
H=\sum_{k=0}^{K-1}p_kI(p_k)
=-\sum_{k=0}^{K-1}p_k\log_2(p_k)
$$

로그는 확률을 정보량으로 바꾸고, 비율을 곱해 더하는 연산은 그 정보량의 평균을 구한다. $p_k=0$인 항의 기여는 0으로 처리하며 `log2(0)`을 그대로 계산하지 않는다.

### 정보 이득은 분할 전후의 차이다

**정보 이득(information gain)**은 부모 엔트로피에서 자식들의 가중평균 엔트로피를 뺀 값이다. 분할 후 불확실성이 많이 줄수록 크다.

여섯 샘플의 부모 클래스별 개수는 `[3, 3]`이다. 두 비율이 $1/2$이고 $\log_2(1/2)=-1$이므로 부모 엔트로피는 1이다. `x2 <= 2.5`의 왼쪽 `[2, 0]`은 엔트로피가 0이고, 오른쪽 `[1, 3]`은 다음과 같다.

$$
H_R=-\left[\frac14\log_2\left(\frac14\right)+\frac34\log_2\left(\frac34\right)\right]
\approx0.811278
$$

가중 엔트로피는 $(2/6)\times0+(4/6)\times0.811278\approx0.540852$다. 정보 이득은 $1-0.540852\approx0.459148$이다.

| 조건 | 가중 지니 | 가중 엔트로피 | 정보 이득 |
| --- | --- | --- | --- |
| `x2 <= 3.5` | 0.4444 | 0.9183 | 0.0817 |
| `x2 <= 2.5` | 0.2500 | 0.5409 | 0.4591 |

분할 후 지니와 엔트로피는 작을수록, 정보 이득은 클수록 좋다. 두 기준은 이 두 후보에서 같은 쪽을 선호하지만 다른 자료에서도 항상 같은 조건을 선택하는 것은 아니다.

## 9. 깊이 제한과 가지치기는 트리를 줄이는 방식이 다르다

**하이퍼파라미터**는 학습 방식과 제한 조건을 지정하는 설정이다. `max_depth`와 `ccp_alpha`가 여기에 해당한다. 실제 분할 특징, 기준값, 연결 구조와 클래스 분포는 `fit`이 데이터로 결정한다.

`max_depth`는 트리를 만들 때 허용할 깊이를 제한한다. **가지치기(pruning)**는 어떤 분할 노드 아래의 구조를 제거하고 그 노드를 리프로 만드는 작업이다. 원본 학습 데이터를 삭제하는 작업은 아니다.

`ccp_alpha`는 **비용-복잡도 가지치기**의 설정이다. 이 방법은 학습 자료의 불순도뿐 아니라 리프 수에도 비용을 부과한다. $T$는 비교할 트리, $R(T)$는 리프 불순도를 전체 학습 자료에서 차지하는 비중으로 가중 합산한 값, $L(T)$는 리프 수다. $\alpha$는 리프 하나당 더하는 복잡도 비용이다.[^pruning]

$$
\text{비용}(T)=R(T)+\alpha L(T)
$$

리프마다 같은 비용 $\alpha$를 더하므로 $\alpha L(T)$라는 곱셈이 생긴다. 여기에 학습 자료의 불순도 비용을 더해 트리를 비교한다. 같은 시작 트리에서 $\alpha$를 키우면 리프가 많은 구조에 더 큰 비용이 붙으므로 더 단순한 트리를 선호한다.

`ccp_alpha=0`은 기본적으로 이 방식의 가지치기를 수행하지 않는다. `0.01`은 가지를 1% 자른다는 뜻이 아니라 비용식의 알파를 0.01로 정한다는 뜻이다. 구조는 특정 경계값에서 바뀌므로 알파를 조금 늘려도 결과가 같을 수 있다.

**학습 중 검증 정확도를 보고 자를 가지를 선택하는 것은 아니다.** 가지치기는 학습 자료의 불순도와 리프 수를 기준으로 한다. 어떤 알파를 사용할지 검증 자료로 비교하는 작업은 그 바깥에서 수행한다.

## 10. 검증 정확도와 리프 수를 함께 비교한다

이제 계산용 여섯 샘플 대신 펭귄 분류 실험의 결과를 보자. 학습 자료는 204개, 검증 자료는 69개이며 특징은 네 개다. 데이터 분할과 `random_state=41`을 유지하고 설정만 바꾼 결과다.

이 절의 표는 기록된 실험 결과를 해석하는 사례다. 원본 행과 분할 정보는 포함하지 않으므로 12절의 가상 데이터 코드로 이 점수를 재현하는 예제는 아니다.

### 깊이 상한을 바꾼 결과

| 깊이 상한 | 실제 깊이 | 리프 수 | 검증 정확도 |
| --- | --- | --- | --- |
| 1 | 1 | 2 | 0.782609 |
| 2 | 2 | 4 | 0.913043 |
| 4 | 4 | 9 | 0.971014 |
| `None` | 4 | 9 | 0.971014 |

상한 4와 `None`이 시험한 후보 중 가장 높은 검증 정확도를 보였다. 깊이 제한을 없애도 실제 트리는 깊이 4에서 멈췄다. 이는 이 자료에서는 더 큰 깊이를 허용해도 더 깊어지지 않았다는 관찰이다. 모든 문제에서 깊이 4가 충분하다는 뜻은 아니다.

샘플·클래스 가중치를 사용하지 않는 단일 정답 분류에서 학습 정확도가 정확히 100%라면 각 리프에 속한 학습 샘플들을 하나의 클래스로 모두 맞힌 것이다. 이 경우 리프 안에 클래스가 섞여 있지 않다. 모델이 검증 정확도 약 97%를 보고 만족해서 멈춘 것이 아니라, 학습 자료와 중단 조건에 따라 분할을 멈춘다.

### 가지치기 알파를 바꾼 결과

| 알파 | 실제 깊이 | 리프 수 | 학습 정확도 | 검증 정확도 |
| --- | --- | --- | --- | --- |
| 0 | 4 | 9 | 1.000000 | 0.971014 |
| 0.005 | 4 | 9 | 1.000000 | 0.971014 |
| 0.01 | 4 | 6 | 0.980392 | 0.927536 |
| 0.02 | 2 | 4 | 0.965686 | 0.913043 |
| 0.05 | 2 | 3 | 0.955882 | 0.913043 |

알파를 0에서 0.01로 바꾸면 리프가 9개에서 6개로 줄었다. 검증 정확도도 개수로 바꾸어 볼 수 있다.

$$
0.971014\approx\frac{67}{69},\qquad
0.927536\approx\frac{64}{69}
$$

**리프는 세 개 줄었지만 검증에서 맞힌 샘플도 세 개 줄었다.** 정확도 차이는 $(3/69)\times100\approx4.35$%포인트다. 구조는 단순해졌지만 이 검증 자료의 정확도는 내려간 것이다.

알파 0과 0.005는 공동으로 가장 높은 검증 정확도를 보였다. 0만 단독 최적이라고 할 수 없다. 알파 0.02와 0.05는 검증 정확도가 같은데 0.05의 리프가 더 적다. 이 두 후보 사이에서는 같은 검증 성능에서 단순한 모델을 선호할 근거가 된다.

깊이·리프 수·정확도가 같더라도 모든 분할 조건까지 같다는 증거는 아니다. 결과표의 요약값과 트리의 전체 구조는 구분해서 확인한다.

### 한 번의 검증 점수로 결론을 넓히지 않는다

**과적합**은 학습 자료에 맞춘 세부 규칙이 새로운 자료에서는 잘 통하지 않는 문제다. 학습 정확도 100%가 새 자료에서도 100%를 보장하지 않는 이유다. 학습·검증 점수 차이만으로 원인을 확정할 수도 없다.

검증 샘플이 69개라면 한 개를 더 맞히는 것만으로 약 $(1/69)\times100=1.45$%포인트가 달라진다. 다른 적절한 분할에서도 결과가 유지되는지 확인할 필요가 있다.

**교차검증**은 학습 부분과 평가 부분을 바꾸어 가며 반복 평가하는 방법이다. `GridSearchCV`는 후보 설정 조합을 이런 방식으로 비교하는 도구다. 시간 순서가 중요하거나 같은 대상의 반복 기록이 있는 자료는 실제 사용 상황에 맞게 분리해야 한다. 테스트 점수를 보며 설정을 계속 바꾸면 테스트 자료도 설정 선택에 사용한 셈이 된다.[^selection]

알파 후보를 직접 얻는 방법도 있다. `cost_complexity_pruning_path(X_train, y_train)`는 학습 자료와 설정에 맞는 가지치기 경계값들을 계산한다. 반환 결과의 `ccp_alphas`가 후보 배열이다. 검증 정확도가 가장 높은 알파를 직접 반환하지는 않으므로 각 후보를 별도로 학습·평가해야 한다. 깊이 제한 등 다른 설정이 바뀌면 후보도 달라질 수 있다.[^pruning]

위 실험에서 검증 정확도를 우선하면 시험한 후보 중 알파 0 또는 0.005가 우선이다. 다만 이는 현재 분할과 후보 범위 안의 결과다. 가능한 모든 알파 중 최적이라는 결론은 아니다.

## 11. 특성 중요도는 현재 트리의 기여도다

`feature_importances_`는 **불순도 감소를 기준으로 계산한 특징별 중요도**다. 각 분할이 줄인 불순도에 그 노드의 학습 샘플 비중을 반영하고, 같은 특징을 사용한 분할들의 기여를 합친다. 이를 전체 특징의 기여 합으로 나누어 상대적인 비중으로 만든다.[^importance]

불순도 감소가 전혀 없다면 값이 모두 0일 수도 있다. 따라서 합이 언제나 1이라고 가정하지 않는다. 이 값은 메서드가 아닌 속성이므로 `model.feature_importances_`처럼 괄호 없이 읽는다.

예를 들어 `flipper_length_mm`이 가장 높다면 현재 트리에서 날개지느러미 길이를 사용한 분할이 가중 불순도 감소에 가장 크게 기여했다는 뜻이다. `mm`는 길이의 밀리미터 단위다.

| 해석 | 그렇게 읽을 수 없는 이유 |
| --- | --- |
| 중요도 0.55이므로 이 특징 하나로 55%를 맞힌다. | 이 값은 해당 특징만 사용한 검증 정확도가 아니다. |
| 이 특징을 삭제하면 정확도가 55% 떨어진다. | 삭제 후 재학습한 결과를 측정한 것이 아니다. |
| 값이 커지면 클래스 1이 된다. | 중요도에는 입력 증가에 따른 예측 방향이 담겨 있지 않다. |
| 이 특징이 펭귄 종류의 원인이다. | 중요도 계산으로 현실의 인과효과를 확인한 것이 아니다. |

모델의 조건과 입력별 예측을 살펴보면 모델이 어떻게 반응하는지는 알 수 있다. 그 반응도 현실의 인과관계와는 다르다.

중요도 0은 이 모델에서 그 특징에 배정된 불순도 감소 기여가 0이라는 뜻이다. 보통 사용하지 않은 특징일 수 있지만, 감소량이 0인 분할에 사용될 가능성도 있다. 실제 사용 여부는 `model.tree_.feature`의 특징 번호로 확인한다.

불순도 기반 중요도는 값의 종류가 많은 특징에 치우칠 수 있다. 비슷한 정보를 가진 특징끼리 기여가 나뉘거나 한쪽에 집중될 수도 있다. 검증 성능에 도움이 되는지 확인하려면 해당 컬럼을 제외하고 재학습하거나, 검증 자료에서 그 컬럼을 섞었을 때 점수 변화를 별도로 측정한다. 이런 검사도 인과관계를 자동으로 입증하지는 않는다.[^importance]

### 중요도와 특징 이름은 학습 컬럼 순서로 연결한다

`feature_importances_`의 값은 학습 컬럼 순서로 들어 있다. `zip(feature_names, importance)`는 같은 위치의 이름과 값을 **튜플**로 묶어 차례로 꺼내는 **반복자**를 만든다. `list(...)`로 모으면 `[(특징 이름, 중요도), ...]` 형태가 된다.

`zip`은 이름의 의미를 보고 연결하지 않는다. Python 3.10 이상에서 `strict=True`를 사용하면 길이가 다를 때 오류로 알려 주지만, 이름의 순서가 맞는지까지 확인해 주지는 않는다.[^python]

`sorted(pairs, key=lambda pair: pair[1], reverse=True)`는 중요도가 큰 순서의 새 리스트를 반환한다. `pair`는 튜플 하나이고, `pair[0]`은 이름, `pair[1]`은 중요도다. `lambda pair: pair[1]`은 정렬 기준으로 중요도를 꺼내는 짧은 함수다. 정렬된 결과의 순서와 원래 학습 컬럼 순서는 구분해야 한다.

## 12. 여섯 샘플로 분할 계산과 모델 조회를 실행한다

아래 코드는 5절의 가상 데이터부터 시작해 지니·엔트로피 계산, 기준값 비교, 모델 학습과 예측까지 실행한다. Python 3.10 이상에서 NumPy, pandas, scikit-learn이 필요하다.

`proportions`, `gini`, `entropy`, `compare_settings`는 아래에서 직접 정의하는 함수다. 입력과 반환값은 다음과 같다.

| 함수 | 입력 | 반환값 |
| --- | --- | --- |
| `proportions` | 클래스별 개수 | 같은 길이의 비율 배열 |
| `gini`, `entropy` | 클래스별 개수 | 불순도 숫자 |
| `compare_settings` | 학습 입력·정답과 검증 입력·정답 | 설정 하나당 한 행인 결과 DataFrame |

`compare_settings`는 실제로 분리한 학습·검증 자료를 전달받도록 정의했다. 함수 정의만으로 학습이 실행되지는 않는다. 아래의 여섯 샘플 실행에서는 전체 자료로 계산용 모델을 학습하므로 **출력되는 정확도는 학습 정확도이며 검증 성능이 아니다.**

설정 비교 함수의 `settings`는 `(실험 이름, 설정 딕셔너리)`를 묶은 목록이다. `**parameters`는 딕셔너리 내용을 `max_depth=...` 같은 이름 있는 인자로 전달하는 문법이다. 반복마다 새 모델을 학습하고 결과 딕셔너리를 `rows.append(...)`로 추가한다. 따라서 결과표의 한 행은 원본 샘플 한 개가 아니라 모델 설정 하나의 실험이다.

<details class="dt-code">
<summary>데이터와 전체 Python 코드</summary>

```python
import numpy as np
import pandas as pd
from sklearn.metrics import accuracy_score
from sklearn.tree import DecisionTreeClassifier, export_text


def proportions(counts):
    # 클래스별 개수를 실수 배열로 바꾼다. 순서는 그대로 유지한다.
    counts = np.asarray(counts, dtype=float)
    # ndim은 차원 수다. isfinite는 NaN·무한대가 아닌지 확인한다.
    if counts.ndim != 1 or not np.all(np.isfinite(counts)):
        raise ValueError("클래스별 개수는 유한한 1차원 숫자 목록이어야 합니다.")
    total = counts.sum()
    if np.any(counts < 0) or not np.isfinite(total) or total <= 0:
        raise ValueError("개수는 음수가 아니고 합은 유한한 양수여야 합니다.")
    return counts / total


def gini(counts):
    p = proportions(counts)
    return float(1 - np.sum(p ** 2))  # 클래스별 비율을 한 번씩 제곱한다.


def entropy(counts):
    p = proportions(counts)
    positive = p[p > 0]  # log2(0)을 계산하지 않는다.
    return float(-np.sum(positive * np.log2(positive)))


def compare_settings(X_train, y_train, X_val, y_val):
    # 전달한 네 자료로 후보를 비교한다. 함수 바깥의 데이터에 의존하지 않는다.
    rows = []
    settings = [(f"depth={depth}", {"max_depth": depth})
                for depth in [1, 2, 4, None]]
    settings += [(f"alpha={alpha}", {"ccp_alpha": alpha})
                 for alpha in [0, 0.005, 0.01, 0.02, 0.05]]
    for name, parameters in settings:
        # **는 딕셔너리의 설정을 이름 있는 인자들로 전달한다.
        candidate = DecisionTreeClassifier(random_state=41, **parameters)
        candidate.fit(X_train, y_train)
        train_accuracy = accuracy_score(y_train, candidate.predict(X_train))
        validation_accuracy = accuracy_score(y_val, candidate.predict(X_val))
        # append는 기존 리스트에 추가한다. 반환값을 rows에 대입하지 않는다.
        rows.append({"setting": name,
                     "depth": candidate.get_depth(),
                     "leaves": candidate.get_n_leaves(),
                     "train_accuracy": train_accuracy,
                     "validation_accuracy": validation_accuracy,
                     "gap": train_accuracy - validation_accuracy})
    return pd.DataFrame(rows)


# 한 행은 가상 샘플 하나다. sample_id는 식별 번호이며 입력 특징이 아니다.
samples = pd.DataFrame({
    "sample_id": [1, 2, 3, 4, 5, 6],
    "x1": [1, 2, 3, 4, 5, 6],
    "x2": [1, 2, 4, 3, 5, 6],
    "label": [0, 0, 0, 1, 1, 1],
})
left_gini, right_gini = gini([2, 0]), gini([1, 3])
weighted_gini = (2 / 6) * left_gini + (4 / 6) * right_gini
print("Gini:", left_gini, right_gini, weighted_gini)
# assert는 조건이 거짓이면 멈춘다. isclose는 실수를 허용 오차로 비교한다.
assert np.isclose(weighted_gini, 0.25)

# 행 전체를 정렬하므로 특징과 정답의 대응이 유지된다.
ordered = samples.sort_values("x2")
x_sorted = ordered["x2"].to_numpy()
y_sorted = ordered["label"].to_numpy()
left_counts, right_counts = [0, 0], [3, 3]
count = len(ordered)
parent_entropy = entropy(right_counts)
results = []
for i in range(count - 1):
    label = int(y_sorted[i])
    left_counts[label] += 1
    right_counts[label] -= 1
    if x_sorted[i] == x_sorted[i + 1]:
        continue  # 같은 특징값 사이에서는 나누지 않는다.
    threshold = (x_sorted[i] + x_sorted[i + 1]) / 2
    left_weight, right_weight = (i + 1) / count, (count - i - 1) / count
    weighted_gini = left_weight * gini(left_counts) + right_weight * gini(right_counts)
    weighted_entropy = left_weight * entropy(left_counts) + right_weight * entropy(right_counts)
    # copy로 현재 개수를 보관해 다음 반복의 변경과 분리한다.
    results.append({"threshold": threshold, "left": left_counts.copy(),
                    "right": right_counts.copy(), "weighted_gini": weighted_gini,
                    "weighted_entropy": weighted_entropy,
                    "information_gain": parent_entropy - weighted_entropy})
print(pd.DataFrame(results).to_string(index=False))
assert np.allclose([row["weighted_gini"] for row in results],
                   [0.4, 0.25, 4 / 9, 0.25, 0.4])

# 이 모델은 위 여섯 샘플을 학습한다. 3절의 경로 설명용 트리와 다르다.
X, y = samples[["x1", "x2"]], samples["label"]
model = DecisionTreeClassifier(max_depth=2, random_state=41)
model.fit(X, y)
pred = model.predict(X)
print("training accuracy:", accuracy_score(y, pred))
print("depth / leaves:", model.get_depth(), model.get_n_leaves())
print(export_text(model, feature_names=list(X.columns)))

# 두 번째 샘플을 2차원 입력 한 행으로 유지한다.
one_row = X.iloc[1:2]
print("input / prediction shape:", one_row.shape, model.predict(one_row).shape)
print("prediction:", model.predict(one_row))
print("leaf ID:", model.apply(one_row))
print("class order:", model.classes_)
print("class probabilities:", model.predict_proba(one_row))
indicator = model.decision_path(one_row)
print("node-use matrix:", indicator.toarray())  # 작은 한 행만 펼친다.

# 학습 컬럼 순서대로 이름과 중요도를 연결한 뒤 중요도순으로 정렬한다.
pairs = list(zip(X.columns, model.feature_importances_, strict=True))
print("feature importance:", sorted(pairs, key=lambda pair: pair[1], reverse=True))
probe = DecisionTreeClassifier(random_state=41)
print("candidate alphas:", probe.cost_complexity_pruning_path(X, y).ccp_alphas)
```

</details>

이 예제는 scikit-learn 1.8.0, NumPy 2.3.5, pandas 2.2.3에서 실행해 다음 결과를 확인했다.

```text
Gini: 0.0 0.375 0.25
training accuracy: 1.0
depth / leaves: 1 2

|--- x1 <= 3.50
|   |--- class: 0
|--- x1 >  3.50
|   |--- class: 1

input / prediction shape: (1, 2) (1,)
prediction: [0]
leaf ID: [1]
class order: [0 1]
class probabilities: [[1. 0.]]
node-use matrix: [[1 1 0]]
candidate alphas: [0.  0.5]
```

`max_depth=2`로 허용했지만 실제 깊이는 1이다. `x1 <= 3.5` 한 번으로 두 클래스가 완전히 나뉘었기 때문이다. 두 번째 샘플은 `x1=2`이므로 왼쪽 리프인 노드 1에 도착해 클래스 0으로 예측된다. 노드 3에 도착했던 4절의 예시와는 트리 구조가 다르다.

출력의 `[0, 0.5]`는 가지치기 경계값 후보이지 검증으로 선택한 최적 알파가 아니다. 마찬가지로 학습 정확도 1.0은 이 여섯 샘플을 모두 맞혔다는 뜻이다. 새로운 자료에서도 잘 맞히는지 판단하려면, 학습에 사용하지 않은 자료의 예측과 실제 정답을 비교해야 한다.
