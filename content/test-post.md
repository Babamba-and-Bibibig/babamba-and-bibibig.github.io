## 먼저 한 행의 의미부터 정한다

이 함수들을 이해할 때 먼저 정할 것은 **“최종적으로 한 행을 무엇으로 만들 것인가?”**다.

고객별로 분석한다면 한 행은 고객 한 명이 되고, 고객의 월별 소비를 분석한다면 한 행은 ‘고객 한 명의 한 달’이 된다. 이름이 `customer_id`라서 행의 기준이 되는 것이 아니라, **고객 단위로 데이터를 보고 싶어서** 선택하는 것이다.

그다음에는 **“컬럼에 무엇을 구분해서 놓을 것인가?”**를 생각하면 된다. 고객의 합계·평균·최댓값을 나란히 놓을 수도 있고, 식품·전자제품·의류의 소비액을 나란히 놓을 수도 있다. 한 행의 기준이 같아도 컬럼에 담는 정보는 달라진다.

여기서 필요한 용어는 간단하다. **DataFrame**은 행과 컬럼으로 구성된 표이고, **인덱스(index)**는 각 행에 붙은 이름표다. **컬럼(columns)**은 금액이나 카테고리 같은 데이터 항목을 구분한다. **집계**는 여러 기록을 합계·평균 같은 요약값으로 계산하는 일이다. 인덱스는 일반 데이터 컬럼과 구분되며, 아래 예제에서는 고객 ID를 인덱스로 사용한다.

집계표를 만드는 흐름은 다음과 같다.

**원본 기록 → 같은 기준으로 묶기 → 필요한 값 계산하기 → 목적에 맞게 행과 컬럼에 배치하기**

이 글에서는 같은 원본으로 `groupby().agg()` 결과와 `pivot_table()` 결과를 각각 만든다. 그다음 피벗 결과를 `melt()`로 풀어본다. 세 함수를 반드시 순서대로 실행해야 한다는 뜻은 아니다.

## agg()는 계산 지표를 나란히 만든다

다음과 같은 소비 기록이 있다고 하자. 현재 한 행은 고객 한 명이 아니라, **고객의 특정 카테고리에 대한 금액 기록 하나**다. 금액의 단위는 원이다.

| customer_id | category | amount |
| --- | --- | ---: |
| 101 | food | 10000 |
| 101 | electronics | 30000 |
| 101 | clothing | 5000 |
| 102 | food | 7000 |
| 102 | clothing | 20000 |

여기서 고객별로 **총얼마를 썼는지, 기록당 평균은 얼마인지, 가장 큰 금액은 얼마인지** 알고 싶다면 `groupby().agg()`를 사용한다.

`groupby("customer_id")`로 같은 고객의 기록을 묶고, `["amount"]`로 계산할 금액을 선택한 다음, `agg(["sum", "mean", "max"])`로 합계·평균·최댓값을 각각 구한다. `agg()`는 `aggregate()`의 줄임말이다.[^groupby]

| customer_id — 인덱스 | sum | mean | max |
| --- | ---: | ---: | ---: |
| 101 | 45000 | 15000.0 | 30000 |
| 102 | 27000 | 13500.0 | 20000 |

101번 고객의 기록은 세 개다. 합계는 `10000 + 30000 + 5000 = 45000`, 평균은 `45000 / 3 = 15000`, 최댓값은 `30000`이다.

여기서 `sum`, `mean`, `max`는 원본 데이터에 있던 카테고리가 아니다. **내가 요청한 계산 방법의 이름**이다.

> **이 예제처럼 groupby().agg()로 여러 통계를 만들면, “어떻게 계산한 결과인가?”를 컬럼으로 구분한다.**

이제 한 행은 기록 하나가 아니라 **고객 한 명의 요약 정보**다. 고객만 기준으로 묶었기 때문에 카테고리는 나누지 않았다.

또한 이 `mean`은 고객의 월평균 소비액이 아니라, **그 고객에게 있는 금액 기록들의 평균**이다. 월별로 묶거나 분석 기간을 정하지 않았는데 월평균이라고 해석하면 안 된다.

## pivot_table()은 데이터의 종류를 나란히 펼친다

이번에는 질문이 다르다.

고객의 합계·평균·최댓값이 아니라, **식품·전자제품·의류에 각각 얼마를 썼는지** 보고 싶다. 이때는 고객을 행의 기준으로 삼고, 카테고리를 컬럼으로 펼친다.

`index="customer_id"`는 한 행의 기준, `columns="category"`는 결과 컬럼으로 펼칠 종류, `values="amount"`는 계산할 값을 정한다. `aggfunc="sum"`은 같은 고객·카테고리에 속한 금액을 합산하라는 뜻이다.[^pivot]

| customer_id — 인덱스 | food | electronics | clothing |
| --- | ---: | ---: | ---: |
| 101 | 10000 | 30000 | 5000 |
| 102 | 7000 | 0 | 20000 |

이번 컬럼 이름인 `food`, `electronics`, `clothing`은 **원본 category 컬럼에 들어 있던 값**이다. 원본에서 행마다 구분하던 종류가 결과의 컬럼 이름으로 올라간 것이다.

> **pivot_table(columns=...)은 “어떤 종류의 값인가?”를 컬럼으로 구분하고, 각 칸의 값은 aggfunc로 계산한다.**

한 행은 고객 한 명이고, 한 칸은 **특정 고객의 특정 카테고리 총 소비액**이다. 고객의 소비 특성을 한 행에 모아서 비교할 수 있다.

지금 예제에는 같은 고객·카테고리 조합이 한 번씩만 있다. 하지만 101번 고객의 `food` 기록으로 5,000원이 하나 더 들어오면, `aggfunc="sum"`은 기존 10,000원과 합쳐 해당 칸을 15,000원으로 만든다. 따라서 `pivot_table()`은 단순히 표를 펼치는 함수가 아니라 **집계와 배치를 함께 처리하는 함수**다.

주의할 점은 `aggfunc`를 생략하면 기본 계산이 합계가 아니라 **평균(mean)**이라는 것이다. 총 소비액을 구하려면 `aggfunc="sum"`을 명시해야 한다.[^pivot]

위 표에서는 거래 기록이 빠짐없이 수집되었고, 기록이 없는 조합은 미구매라는 전제에서 `fill_value=0`으로 빈칸을 채웠다. **미구매라서 없는 값과 수집하지 못해서 모르는 값은 다르다.** 후자의 경우에는 근거 없이 0으로 바꾸면 안 된다.

## 둘의 차이는 ‘계산하느냐’가 아니다

앞의 두 결과를 비교하면 차이가 분명하다.

| 비교 | groupby().agg() — 위 예제 | pivot_table() — 위 예제 |
| --- | --- | --- |
| 한 행의 의미 | 고객 한 명 | 고객 한 명 |
| 컬럼으로 구분하는 것 | 합계·평균·최댓값 | 식품·전자제품·의류 |
| 컬럼 이름의 출처 | 지정한 계산 방법 | 원본 데이터의 종류 값 |
| 알고 싶은 것 | 고객의 소비 기록을 어떻게 요약할까? | 고객이 종류별로 얼마를 썼을까? |

다만 **“agg()는 무조건 계산 방법을 컬럼으로 만든다”라고 외우면 안 된다.** 위 설명은 그룹별로 여러 집계를 지정한 경우다.

일반 `DataFrame.agg()`에서는 계산 방법이 행에 나올 수도 있다. 예를 들어 `orders[["amount"]].agg(["sum", "mean"])`은 고객별로 묶지 않고 전체 금액을 계산하며, `amount`를 컬럼으로 유지한 채 `sum`과 `mean`을 행 이름으로 둔다. **어떤 객체에 agg()를 호출하고, 어떤 계산을 지정했는지**에 따라 결과 구조가 달라진다.[^dataframe-agg]

또한 `agg()`도 `groupby(["customer_id", "category"])`처럼 고객과 카테고리를 함께 묶으면 종류별 통계를 계산할 수 있다. 반대로 `pivot_table()`도 `aggfunc=["sum", "mean"]`을 지정하면, 위쪽에는 계산 방법을 놓고 그 아래에는 카테고리를 놓는 **여러 단계의 컬럼 이름**을 만들 수 있다.[^groupby][^pivot]

결국 둘은 반대 기능이 아니다.

**agg()는 무엇을 어떻게 집계할지에 초점이 있고, pivot_table()은 집계한 값을 어떤 행과 컬럼으로 나눌지까지 정한다.**

## melt()는 펼쳐진 종류를 다시 행으로 푼다

피벗 결과는 고객의 소비 특성을 한 행에서 비교하기 좋다. 반면 카테고리를 기준으로 필터링하거나 같은 계산을 적용하려면, 종류와 금액을 각각 하나의 컬럼에 모아두는 편이 편할 수 있다.

`melt()`는 이때 사용한다. 여러 컬럼에 나뉜 값을 **‘종류를 담는 컬럼 + 값을 담는 컬럼’**으로 모아, 여러 행으로 풀어낸다. 이 과정에서 합계나 평균을 새로 계산하지는 않는다.[^melt]

**고객별 카테고리 컬럼 → 고객 ID + 카테고리 이름 + 금액**

기존의 `food`, `electronics`, `clothing`이라는 **컬럼 이름은 category의 값**으로 들어가고, 각 셀의 금액은 **amount 컬럼**으로 모인다. 고객 ID는 각 금액이 누구의 것인지 알 수 있도록 유지한다.

위 피벗 결과를 풀면 다음과 같다. 아래 표는 뒤에 나오는 코드의 결과 순서와 같고, 자동으로 붙는 행 번호는 생략했다.

| customer_id | category | amount |
| --- | --- | ---: |
| 101 | food | 10000 |
| 102 | food | 7000 |
| 101 | electronics | 30000 |
| 102 | electronics | 0 |
| 101 | clothing | 5000 |
| 102 | clothing | 20000 |

이제 한 행은 **고객 한 명의 특정 카테고리 총 소비액**이다. 원본과 컬럼 이름이 같아도 한 행이 뜻하는 정보는 다를 수 있다.

여기서 두 가지를 구분해야 한다.

**첫째, 표를 다시 길게 만드는 것과 원본 기록을 복원하는 것은 다르다.** 앞에서 10,000원과 5,000원을 합쳐 15,000원으로 만들었다면, `melt()`를 해도 15,000원으로 남는다. 합계만 가지고 원래의 개별 금액이나 거래 횟수를 알아낼 수는 없다.

**둘째, 피벗 과정에서 채운 값도 그대로 행으로 나온다.** 원본에는 102번 고객의 전자제품 기록이 없었지만, 피벗 표에서는 그 칸을 0으로 채웠다. `melt()`는 그 0도 하나의 값으로 옮기므로 결과는 원본의 5행이 아니라 **고객 2명 × 카테고리 3개 = 6행**이 된다. 전자제품을 0원에 구매한 거래가 생긴 것이 아니다.

코드에서는 `melt()` 전에 `reset_index()`를 호출한다. 피벗 결과에서 `customer_id`는 일반 컬럼이 아니라 인덱스에 있기 때문이다. `reset_index()`로 고객 ID를 일반 컬럼으로 가져온 다음, `id_vars="customer_id"`로 유지할 식별 정보로 지정한다.[^reset-index][^melt]

## 전체 예제 코드

위 내용을 한 번에 실행하면 다음과 같다. `orders`에서 `stats`와 `wide`를 각각 만들고, `wide`를 풀어서 `long`을 만든다.

**소비 기록(orders) → 고객별 통계(stats)**  
**소비 기록(orders) → 고객별 카테고리 소비액(wide) → 고객·카테고리별 행(long)**

```python
import pandas as pd  # 표 형태의 데이터를 다루는 Pandas를 pd라는 이름으로 사용한다.

# 한 행 = 고객의 특정 카테고리에 대한 금액 기록 하나.
orders = pd.DataFrame({
    "customer_id": [101, 101, 101, 102, 102],
    "category": ["food", "electronics", "clothing", "food", "clothing"],
    "amount": [10000, 30000, 5000, 7000, 20000],
})

# 1. 같은 고객의 기록을 묶고 amount의 여러 통계를 계산한다.
# 한 행 = 고객 한 명, 컬럼 = 내가 지정한 계산 방법.
stats = orders.groupby("customer_id")["amount"].agg(
    ["sum", "mean", "max"]  # 합계, 기록당 평균, 최대 기록 금액.
)

# 2. 같은 원본에서 고객별 카테고리 총 소비액을 만든다.
# 한 행 = 고객 한 명, 컬럼 = 원본 category에 들어 있던 종류 값.
wide = orders.pivot_table(
    index="customer_id",   # 최종 한 행의 기준을 정한다.
    columns="category",    # 종류 값을 결과 컬럼 이름으로 펼친다.
    values="amount",       # 각 칸을 계산할 원본 금액 컬럼이다.
    aggfunc="sum",         # 같은 고객·카테고리의 금액을 합산한다.
    fill_value=0,          # 기록 없음 = 미구매라는 전제에서 빈칸을 채운다.
)

# 컬럼을 지정한 순서로 선택해서 본문의 예제 표와 순서를 맞춘다.
wide = wide[["food", "electronics", "clothing"]]

# 3. 카테고리별 컬럼을 다시 '종류 + 값' 형태의 행으로 푼다.
# reset_index(): 인덱스에 있는 customer_id를 일반 컬럼으로 가져온다.
# 한 행 = 고객 한 명의 특정 카테고리 총 소비액. 원본 거래 복원이 아니다.
long = wide.reset_index().melt(
    id_vars="customer_id",  # 풀지 않고 유지할 식별 컬럼이다.
    value_vars=["food", "electronics", "clothing"],  # 행으로 풀어낼 컬럼들이다.
    var_name="category",   # 원래 컬럼 이름들을 값으로 담을 새 컬럼 이름이다.
    value_name="amount",   # 각 셀의 금액을 담을 새 컬럼 이름이다.
)

print("고객별 합계·평균·최댓값")
print(stats)

print("\n고객별 카테고리 총 소비액")  # \n은 출력에서 줄을 바꾼다.
print(wide)

print("\n고객·카테고리별로 풀어낸 총 소비액")
print(long)
```

`stats`와 `wide`는 각각 고객 2명을 담은 **2행 × 3컬럼**이다. 여기서 인덱스인 `customer_id`는 컬럼 수에 포함하지 않는다. `long`은 고객 ID가 일반 컬럼으로 돌아온 **6행 × 3컬럼**이다.

## 정리

**agg()는 필요한 요약값을 계산하고, pivot_table()은 요약값을 행과 컬럼의 기준에 맞춰 펼친다. melt()는 여러 컬럼에 놓인 값을 종류와 값으로 나누어 행으로 풀어낸다.**

함수 이름부터 외우기보다 **“현재 한 행은 무엇인가 → 최종 한 행은 무엇이어야 하는가 → 컬럼에는 무엇을 나란히 둘 것인가”**를 먼저 정하면 어떤 함수를 써야 할지 판단하기 쉬워진다.

[^groupby]: Pandas 공식 문서 — [그룹별 agg()와 여러 집계 지정](https://pandas.pydata.org/docs/reference/api/pandas.api.typing.DataFrameGroupBy.agg.html), [그룹별 집계 가이드](https://pandas.pydata.org/docs/user_guide/groupby.html).
[^pivot]: Pandas 공식 문서 — [DataFrame.pivot_table(): 행·컬럼 기준, aggfunc, fill_value](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.pivot_table.html).
[^dataframe-agg]: Pandas 공식 문서 — [DataFrame.agg(): 호출 방식에 따른 결과 구조](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.agg.html).
[^melt]: Pandas 공식 문서 — [DataFrame.melt(): 식별 컬럼을 유지하며 여러 컬럼을 행으로 풀기](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.melt.html).
[^reset-index]: Pandas 공식 문서 — [DataFrame.reset_index(): 인덱스를 일반 컬럼으로 옮기기](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.reset_index.html).
