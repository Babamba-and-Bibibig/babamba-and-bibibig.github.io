## 질문 1

모델이 학습 데이터에서는 정확도 99%, 테스트 데이터에서는 70%가 나왔어요. 편향과 분산 중 어느 쪽 문제일까요? L1·L2 규제는 이 문제를 어떻게 줄이나요?

### 1) 구글링 리서치 메모

#### 편향(Bias)과 분산(Variance)의 작동 원리 {#research-bias-variance .research-topic}

- **편향:** 같은 문제에서 학습 데이터를 바꿔 가며 모델을 학습했을 때, 모델의 평균 예측이 실제 관계에서 얼마나 벗어나는지를 뜻한다. 모델이 너무 단순하면 필요한 관계를 표현하지 못해 편향이 커질 수 있다. 복잡한 곡선 형태의 관계를 직선으로만 예측하려는 경우가 여기에 해당한다. 이처럼 필요한 관계를 충분히 학습하지 못하는 현상을 **과소적합**(Underfitting)이라고 한다.
- **분산:** 학습 데이터가 달라졌을 때, 같은 입력에 대한 모델의 예측이 얼마나 달라지는지를 뜻한다. 복잡한 모델이 학습 데이터에만 있는 우연한 변동까지 따라가면 예측이 학습 데이터에 민감해질 수 있다. 학습 데이터는 잘 맞추지만 새로운 데이터에서는 성능이 떨어지는 **과적합**(Overfitting)과 관련이 있다.

회귀에서는 같은 데이터 생성 과정에서 학습 데이터와 새 데이터를 반복해서 뽑는다고 할 때, 제곱오차의 평균을 다음과 같이 나누어 살펴볼 수 있다.

**평균적인 제곱오차 = 편향² + 분산 + 노이즈**

노이즈는 현재 주어진 입력 정보만으로는 예측하기 어려운 무작위 변동을 뜻한다. 이 식은 제곱오차에 관한 분해이며, 분류 정확도를 세 항으로 그대로 나누는 식은 아니다.

참고: scikit-learn의 [편향·분산 분해 예제](https://scikit-learn.org/stable/auto_examples/ensemble/plot_bias_variance.html), [학습·검증 점수로 과소적합과 과적합을 살펴보는 문서](https://scikit-learn.org/stable/modules/learning_curve.html).

#### 편향과 분산 사이의 트레이드오프 {#research-tradeoff .research-topic}

트레이드오프는 한쪽을 개선하는 과정에서 다른 쪽이 나빠질 수 있는 관계를 뜻한다. 모델의 복잡도를 높이면 더 복잡한 관계를 표현할 수 있지만, 학습 데이터의 우연한 변동까지 따라갈 위험도 있다. 반대로 모델을 너무 단순하게 제한하면 예측이 덜 흔들리는 대신 필요한 관계를 놓칠 수 있다.

따라서 학습 데이터에 얼마나 잘 맞는지만 보고 복잡도를 정해서는 안 된다. 학습에 사용하지 않은 데이터에서도 잘 예측하는지 함께 확인해야 한다. 복잡도를 높일 때 편향과 분산이 언제나 일정한 방향으로 변한다는 뜻은 아니다.

참고: scikit-learn의 [모델 복잡도와 검증 곡선](https://scikit-learn.org/stable/modules/learning_curve.html).

#### L1·L2 규제가 과적합을 줄이는 원리 {#research-regularization .research-topic}

손실함수는 예측이 정답과 얼마나 다른지를 계산한다. 가중치는 입력에 곱하는 값으로, 모델은 학습하면서 이 값을 조정한다. L1·L2 규제는 손실에 가중치 크기에 따른 **페널티**, 즉 추가 비용을 더한다. 모델은 예측 오차와 이 비용의 합이 작아지도록 가중치를 정한다.

- **L1 규제:** 가중치 절댓값의 합에 규제 강도를 곱해 손실에 더한다. 일부 가중치가 정확히 0이 될 수 있어, 모델이 사용하는 특성이 줄어드는 효과가 있다.
- **L2 규제:** 가중치 제곱의 합에 규제 강도를 곱해 손실에 더한다. 가중치가 전반적으로 지나치게 커지지 않도록 제한한다.

규제 강도는 페널티를 얼마나 크게 반영할지 정하는 값이다. 가중치가 양수든 음수든 크기가 커지면 페널티가 커진다. 따라서 학습 데이터의 오차를 줄이기 위해 가중치를 크게 만드는 것이 항상 유리하지는 않다.

참고: scikit-learn의 [Ridge와 L2 규제](https://scikit-learn.org/stable/modules/linear_model.html#ridge-regression-and-classification), [Lasso와 L1 규제](https://scikit-learn.org/stable/modules/linear_model.html#lasso).

규제를 적절히 적용하면 학습 데이터에 과하게 맞추는 정도를 낮춰 분산을 줄이는 데 도움이 될 수 있다. 학습 성능이 조금 낮아져도 새로운 데이터의 예측 성능은 좋아질 수 있다. 다만 규제가 너무 강하면 필요한 관계도 학습하지 못해 과소적합이 생길 수 있다.

참고: scikit-learn의 [규제 강도에 따른 학습·검증 성능 변화](https://scikit-learn.org/stable/auto_examples/model_selection/plot_train_error_vs_test_error.html).

### 2) 내 답변

학습 데이터에서는 정확도가 99%인데 테스트 데이터에서는 70%가 나왔으니, 과적합을 먼저 의심할 것 같습니다. 학습한 데이터에는 잘 맞지만 새로운 데이터에는 잘 맞지 않는 것이므로, 편향과 분산 중에서는 분산에 더 가까운 문제라고 생각합니다.

이때 과적합을 줄이는 방법으로 L1·L2 규제를 배웠습니다. 모델이 복잡한 관계를 표현할 수 있어도 학습 데이터의 작은 변화까지 지나치게 맞추면 문제가 될 수 있으니, 규제로 그 정도를 제한하는 것입니다.

L1·L2 규제는 손실함수에 가중치 크기에 따른 페널티를 더합니다. L1은 가중치 절댓값의 합을, L2는 제곱의 합을 사용합니다. 모델은 학습 데이터의 오차만 줄이는 것이 아니라 이 페널티까지 고려해서 가중치를 찾아야 합니다. 그 과정에서 L1은 일부 가중치를 0으로 만들 수 있고, L2는 가중치가 지나치게 커지는 것을 제한한다고 이해했습니다.

다만 규제가 너무 강하면 필요한 관계까지 놓칠 수 있습니다. 학습 정확도가 조금 낮아지더라도 새로운 데이터에서 더 잘 맞는다면 도움이 되겠지만, 무조건 규제를 강하게 거는 것이 좋은 방법은 아닐 것 같습니다.

## 질문 2

랜덤 포레스트와 그레이디언트 부스팅은 둘 다 결정 트리 여러 개를 합친 모델이에요. 두 모델은 트리를 만들고 합치는 방식이 어떻게 다른가요? 트리 개수를 계속 늘리면 각 모델에 어떤 일이 생길지도 예상해 주세요.

### 1) 구글링 리서치 메모

#### 결합 방식의 핵심 차이 {#research-ensemble-comparison .research-topic}

**앙상블**(Ensemble)은 여러 모델의 예측을 합쳐 사용하는 방법이다. 여기서 트리 한 개는 내부에 여러 분할 지점인 노드와 예측값을 내는 끝 노드를 가진 결정 트리 전체를 뜻한다. 트리 개수를 늘리는 것과 한 트리 안의 노드를 늘리는 것은 구분해야 한다.

| 구분 | 랜덤 포레스트(Random Forest) | 그레이디언트 부스팅(Gradient Boosting) |
| --- | --- | --- |
| 결합 방식 | 배깅을 바탕으로 여러 트리의 결과를 모음 | 새 트리의 보정값을 순차적으로 더함 |
| 학습 순서 | 다른 트리의 학습 결과를 기다리지 않고 각각 학습 | 현재까지 만든 전체 모델의 예측을 바탕으로 다음 트리를 학습 |
| 학습 대상 | 각 트리가 원래 정답을 예측하도록 학습 | 현재 전체 모델의 오차를 줄이는 보정값을 학습 |
| 데이터 사용 | 기본적으로 행을 복원 추출하고, 분할마다 특성을 무작위로 선택 | 입력 특성을 사용하되, 단계마다 보정할 목표값을 새로 계산 |
| 결과 결합 | 회귀는 예측값 평균, 분류는 투표 또는 확률 평균 | 학습률을 곱한 보정값을 누적함. 분류에서는 누적 점수를 확률과 범주로 변환 |
| 주된 효과 | 여러 트리를 합쳐 예측의 분산을 줄임 | 남은 오차를 보완하면서 편향을 줄이는 데 유리 |

분류 결과를 합치는 방식에는 구현 차이가 있다. **scikit-learn의 랜덤 포레스트 분류기는 각 트리의 클래스별 예측 확률을 평균한 뒤, 평균 확률이 가장 높은 클래스를 선택한다.** 클래스는 모델이 구분할 범주를 뜻한다.

참고: scikit-learn의 [앙상블 모델 설명](https://scikit-learn.org/stable/modules/ensemble.html), [랜덤 포레스트의 분류 결과 계산](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.RandomForestClassifier.html#sklearn.ensemble.RandomForestClassifier.predict).

#### 랜덤 포레스트와 그레이디언트 부스팅의 장단점 {#research-ensemble-details .research-topic}

##### 1. 랜덤 포레스트: 따로 학습한 트리의 결과를 모은다 {.research-detail}

배깅(Bagging)은 **Bootstrap Aggregating**을 줄인 말이다. 원본 데이터에서 같은 행을 여러 번 뽑을 수 있는 **복원 추출**로 학습용 데이터를 만들고, 각각의 모델을 학습한 뒤 결과를 합친다.

랜덤 포레스트는 여기에 특성 선택의 무작위성도 더한다. 특성은 예측에 사용하는 입력 항목이다. 각 트리 안에서 데이터를 나눌 조건을 정할 때마다 일부 특성을 무작위로 골라 후보로 사용한다. 어떤 행과 특성을 보느냐가 달라지므로 트리들이 서로 다른 예측을 만들 수 있다. 사용하는 행과 특성의 범위는 설정에 따라 조절할 수 있다.

각 트리는 자신에게 주어진 데이터로 원래 정답을 예측하도록 학습한다. 새 입력이 들어오면 각 트리가 예측을 내놓고, 전체 모델은 그 결과를 평균하거나 투표로 모은다.

- **장점:** 서로 다른 트리의 결과를 합쳐 한 트리의 예측에 크게 좌우되는 정도를 줄일 수 있다. 트리끼리 앞선 학습 결과를 기다릴 필요가 없으므로 병렬 처리가 가능하다.
- **주의할 점:** 개별 트리는 여전히 학습 데이터에 과적합할 수 있다. 여러 트리가 비슷한 실수를 반복하면 평균을 내도 그 실수가 충분히 줄지 않을 수 있다. 트리 수와 각 트리의 크기가 커질수록 메모리와 계산량도 늘어난다.

참고: scikit-learn의 [랜덤 포레스트 원리와 병렬 처리](https://scikit-learn.org/stable/modules/ensemble.html#random-forests).

##### 2. 그레이디언트 부스팅: 전체 예측에 남은 오차를 보완한다 {.research-detail}

그레이디언트 부스팅은 지금까지 만든 트리들을 합친 **전체 모델의 예측**을 기준으로 새 트리를 학습한다. 바로 앞 트리 하나의 오차만 보는 방식은 아니다.

제곱오차를 사용하는 회귀에서는 초기 예측값에서 출발해 다음 과정을 반복한다. **잔차**는 실제값에서 현재 예측값을 뺀 값이다.

1. 현재 전체 모델로 학습 데이터의 값을 예측하고, 각 행의 잔차를 계산한다.
2. 원래 입력 특성을 사용해 이 잔차를 예측하는 **새 결정 트리 한 개**를 학습한다.
3. 새 트리의 예측값에 학습률을 곱해 기존 전체 예측에 더한다. 학습률은 새 트리의 보정값을 얼마나 반영할지 정한다.
4. 갱신된 전체 예측을 기준으로 잔차를 다시 계산하고, 다음 트리를 학습한다.

**새 전체 예측 = 기존 전체 예측 + 학습률 × 새 트리의 예측**

일반적으로는 손실함수에 따라 보정할 목표값을 계산한다. 이를 **손실의 음의 기울기**, 즉 현재 예측을 바꿔 손실을 줄이는 방향과 크기를 나타내는 값으로 구한다. 제곱오차 회귀에서는 이 과정이 잔차를 학습하는 방식으로 이어진다.

참고: scikit-learn의 [그레이디언트 부스팅 회귀](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.GradientBoostingRegressor.html).

- **장점:** 현재 전체 모델이 충분히 맞추지 못한 부분을 새 트리로 보완하면서 예측 성능을 높일 수 있다.
- **주의할 점:** 단계마다 앞선 전체 예측이 필요하므로, 랜덤 포레스트처럼 모든 트리를 서로 독립적으로 학습할 수는 없다. 학습률, 트리의 크기와 개수를 함께 조절해야 하며, 반복해서 보완하는 과정에서 학습 데이터의 우연한 변동까지 맞출 수 있다.

다만 순차적으로 학습한다는 이유만으로 부스팅이 항상 더 느리다고 볼 수는 없다. 실제 속도는 데이터 크기와 구현 방식에 따라 달라진다. 예측 성능도 어느 한쪽이 항상 더 좋다고 단정할 수 없다.

참고: scikit-learn의 [랜덤 포레스트와 히스토그램 기반 부스팅 비교](https://scikit-learn.org/stable/auto_examples/ensemble/plot_forest_hist_grad_boosting_comparison.html).

#### 트리 개수를 계속 늘리면 {#research-number-of-trees .research-topic}

##### 1. 랜덤 포레스트 {.research-detail}

각 트리의 깊이 등 다른 설정은 그대로 두고 트리 수만 늘리면, 더 많은 예측을 평균하므로 일부 트리의 결과에 좌우되는 정도가 줄어드는 경향이 있다. 다만 트리들이 공통으로 하는 실수까지 사라지는 것은 아니다.

트리가 충분히 모이면 더 추가해도 성능 개선 폭이 작아지는 경우가 많다. 그렇다고 실제 검증 점수가 매번 좋아지거나, 어느 순간부터 완전히 같은 값으로 고정된다는 뜻은 아니다. 트리 수가 늘어나는 동안 점수는 오르내릴 수 있다.

랜덤 포레스트 자체가 과적합에서 자유로운 것도 아니다. **트리 수를 늘리는 것과 개별 트리를 더 깊게 만드는 것은 다르다.** 성능 개선이 작아진 뒤에도 트리를 계속 추가하면 저장할 트리와 예측할 때 거쳐야 할 계산은 늘어난다.

참고: Probst·Boulesteix의 [랜덤 포레스트에서 트리 수를 조정해야 하는가](https://jmlr.org/papers/v18/17-269.html), scikit-learn의 [랜덤 포레스트 설정값 설명](https://scikit-learn.org/stable/modules/ensemble.html#parameters).

##### 2. 그레이디언트 부스팅 {.research-detail}

그레이디언트 부스팅에서 트리를 추가하는 것은 현재 예측에 대한 보정을 더 이어 가는 것이다. 이 과정에서 학습 오차를 더 줄일 수 있지만, 학습 데이터에만 있는 우연한 변화까지 맞추면 새로운 데이터의 예측 성능은 나빠질 수 있다.

따라서 트리 수를 늘릴 때는 학습 성능과 **검증 성능**을 함께 살펴본다. 검증 데이터는 학습에 직접 사용하지 않고 모델의 설정값을 고르는 데 쓰는 데이터다. 최종 평가용 테스트 데이터와는 역할이 다르다.

**조기 종료**(Early Stopping)는 검증 성능이 정해진 횟수 동안 충분히 개선되지 않으면 학습을 멈추는 방법이다. 불필요한 트리 추가와 과적합을 줄이는 데 사용할 수 있다. 트리 수와 학습률을 검증 성능에 맞춰 정하는 방법도 있으므로, 조기 종료만이 유일한 방법은 아니다.

트리를 많이 추가했다고 반드시 과적합하는 것은 아니다. 같은 트리 수라도 학습률과 각 트리의 크기에 따라 결과가 달라지므로, 이 설정들을 함께 봐야 한다.

참고: scikit-learn의 [그레이디언트 부스팅 조기 종료 예제](https://scikit-learn.org/stable/auto_examples/ensemble/plot_gradient_boosting_early_stopping.html), [학습률과 트리 수의 관계](https://scikit-learn.org/stable/modules/ensemble.html#shrinkage-via-learning-rate).

### 2) 내 답변

랜덤 포레스트는 여러 결정 트리가 각각 정답을 예측하도록 학습한 뒤 결과를 모으는 방식입니다. 회귀에서는 예측값의 평균을 쓰고, 제가 배운 scikit-learn의 분류에서는 클래스별 확률을 평균합니다. 트리들이 서로의 학습 결과를 기다릴 필요가 없어서 병렬로 학습할 수 있습니다.

트리 수가 늘어나면 평균에 참여하는 결과도 많아집니다. 한 트리의 결과만 사용하는 것이 아니니, 일부 트리가 학습 데이터에 과하게 맞춰져도 전체 결과는 그 영향을 덜 받을 것 같습니다.

그레이디언트 부스팅은 현재까지 만든 전체 모델의 오차를 새 트리가 보완하도록 순차적으로 학습합니다. 제곱오차를 쓰는 회귀에서는 남은 잔차를 새 트리가 배우고, 그 예측값에 학습률을 곱해 기존 예측에 더합니다. 이렇게 남은 오차를 계속 보완하니 학습 데이터에 더 잘 맞출 수 있겠지만, 너무 오래 반복하면 그 데이터에만 있는 우연한 변화까지 맞출 수 있을 것 같습니다. 그래서 부스팅에서는 트리를 계속 추가해도 되는지 더 신경 써야 한다고 생각합니다.
