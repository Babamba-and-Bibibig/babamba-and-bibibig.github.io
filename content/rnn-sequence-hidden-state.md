RNN(순환 신경망) 그림에는 비슷한 상자가 여러 개 나오고, 각 상자 안에는 여러 뉴런이 들어 있다. 이때 상자의 개수, 뉴런의 개수, 입력 숫자의 개수를 구별하지 않으면 실제 계산을 따라가기 어렵다.

먼저 계산의 기준을 정하자. <strong>기본 RNN은 현재 입력과 이전 은닉 상태로 새 은닉 상태를 계산한다.</strong> 은닉 상태는 앞선 입력을 처리해서 만든 숫자 묶음이다. 은닉 뉴런이 3개라면 한 시퀀스의 한 시점에서 숫자 3개를 만들고, 그 세 값을 함께 다음 시점으로 전달한다.

이 글에서는 입력 특징 4개, 은닉 뉴런 3개, 시점 5개를 사용한다. 서로 독립적인 시퀀스 2개를 묶어 계산한다. 처음에는 그림과 숫자로 구조를 확인하고, 뒤에서 같은 계산을 PyTorch 코드로 실행한다. 예제는 <strong>한 층·단방향·tanh를 사용하는 기본 RNN의 순전파</strong>다. 단방향은 앞에서 뒤로 한 방향으로 처리한다는 뜻이고, 순전파는 현재 가중치로 결과를 계산하는 과정이다. LSTM·GRU의 추가 구조와 학습 과정은 이번 계산에 포함하지 않는다.

[주석을 포함한 전체 Python 코드](/rnn-sequence-hidden-state/examples-ko.py)와 [Rust 수치 검산 코드](/rnn-sequence-hidden-state/recurrence-ko.rs)를 내려받을 수 있다. Python 코드는 PyTorch가 설치된 환경에서 CPU로 실행한다.

## 1. 현재 입력과 이전 결과가 함께 들어간다

그림을 읽기 전에 네 가지 이름만 정리하자.

| 이름 | 뜻 | 이번 예제 |
| --- | --- | --- |
| 특징 | 한 번의 입력을 구성하는 개별 정보 | 한 시점에 숫자 4개 |
| 시점 | 순서가 있는 데이터에서 현재 처리하는 단계 | 첫째부터 다섯째까지 |
| 시퀀스 | 여러 시점의 입력을 순서대로 묶은 데이터 | 입력 5개를 묶은 전체 |
| 은닉 상태 | 한 시점의 RNN 계산으로 만든 결과 묶음 | 뉴런 3개가 만든 숫자 3개 |

기온·습도·풍속·기압을 매시간 측정한다면 한 시점에는 네 특징이 들어간다. 다섯 시점의 측정값을 시간순으로 모으면 시퀀스 하나가 된다. 아래 수치 예제는 실제 기상 관측값이 아닌 계산 연습용 숫자다. 특징 이름은 `f0, f1, f2, f3`으로 표시한다.

첫 시점의 입력을 `x₁`, 그 입력을 처리한 은닉 상태를 `h₁`이라고 쓰자. 첫 계산에는 이전 결과가 없으므로 시작값 `h₀`를 준비한다. 이번에는 `[0, 0, 0]`으로 시작한다.

<img src="/rnn-sequence-hidden-state/time-flow-ko.svg" alt="한 층의 RNN이 다섯 시점을 처리한다. 각 시점은 자신의 입력 특징 4개와 이전 시점의 은닉값 3개를 받아 새로운 은닉값 3개를 만든다. 다섯 계산은 같은 가중치와 편향을 사용한다." loading="lazy">
<figcaption>h₁의 숫자 세 개가 다음 계산으로 함께 전달된다. x₂는 두 번째 시점의 새 입력이고, h₁은 첫 번째 시점의 계산 결과다.</figcaption>
</figure>

전체 흐름은 <strong>입력 준비 → 첫 시점 선택 → 현재 입력과 초기 상태로 계산 → 결과 3개를 새 상태로 저장 → 다음 입력과 새 상태로 반복</strong>이다.[^rnn]

두 번째 은닉 상태 `h₂`를 완성하려면 `h₁`이 필요하다. 다만 입력에 가중치를 곱하는 부분처럼 이전 상태를 사용하지 않는 연산은 미리 계산할 수 있다. 시간 순서가 필요한 대상은 <strong>새 은닉 상태를 완성하는 계산</strong>이다.

## 2. 입력 x에서 시퀀스 하나를 찾아보자

<strong>배치</strong>는 여러 데이터를 함께 처리하려고 묶은 것이다. 여기서는 시퀀스 2개를 배치 하나로 만든다. 두 시퀀스는 같은 가중치를 사용하지만, 각자 자신의 은닉 상태를 갖는다.

| 기호 | 무엇의 개수인가? | 값 |
| --- | --- | ---: |
| `B` | 배치에 들어 있는 시퀀스 | 2 |
| `T` | 시퀀스 하나의 시점 | 5 |
| `F` | 한 시점의 입력 특징 | 4 |
| `H` | 은닉 뉴런, 즉 한 시점에 만드는 은닉값 | 3 |
| `L` | 쌓아 놓은 RNN 층 | 1 |

은닉 뉴런은 A·B·C라고 부른다. 기호 `B=2`는 배치 크기를 뜻하고, 문장 속 ‘뉴런 B’는 세 뉴런 중 하나의 이름이다.

<figure class="rnn-figure">
<img src="/rnn-sequence-hidden-state/sequence-data-ko.svg" alt="전체 입력 x는 시퀀스 두 개로 구성된다. 각 시퀀스는 다섯 시점, 각 시점은 네 특징을 가진다. 첫 시퀀스의 두 번째 시점은 [3,8,12,6], 두 번째 시퀀스의 같은 시점은 [9,5,10,7]이다." loading="lazy">
<figcaption>한 시퀀스에는 숫자가 5×4=20개 있다. 시점이 5개라는 말과 특징이 4개라는 말을 구별해서 읽는다.</figcaption>
</figure>

이 글에서 `x`는 <strong>`torch.tensor(...)`로 만든 PyTorch 텐서</strong>다. 텐서는 숫자와 숫자 배열을 저장하고 계산하는 자료구조다. 그림의 중첩 배열을 일반 Python 리스트라고 생각하고 `x[0, 1, :]`를 적용하면 같은 방식으로 동작하지 않는다.

시퀀스는 반드시 시계상의 시간일 필요는 없다. 문장의 단어 순서도 시퀀스가 될 수 있다. RNN은 입력을 제공받은 순서대로 처리한다. 인덱스만 보고 실제 날짜나 시간 간격을 알아내거나, 섞인 관측값을 자동으로 시간순 정렬하지는 않는다. 실제 시간 간격이 필요한 과제라면 그 정보를 입력 특징 등으로 제공해야 한다.

## 3. 축 번호, 크기, 인덱스를 나누어 읽는다

<strong>shape</strong>는 각 축의 크기를 순서대로 적은 것이다. <strong>축</strong>은 배열에서 위치를 구분하는 기준이고, <strong>인덱스</strong>는 그 축에서 선택할 위치 번호다. Python과 PyTorch의 인덱스는 0부터 시작한다.

전체 입력의 shape는 `(B, T, F) = (2, 5, 4)`다.

| 축 번호 | 의미 | 크기 | 유효 인덱스 |
| ---: | --- | ---: | --- |
| 0 | 시퀀스 선택 | 2 | 0, 1 |
| 1 | 시점 선택 | 5 | 0, 1, 2, 3, 4 |
| 2 | 특징 선택 | 4 | 0, 1, 2, 3 |

‘축 1’은 두 번째 축의 번호다. 그 축의 크기는 5이고, 마지막 인덱스는 4다. 세 숫자는 서로 다른 정보를 나타낸다.

| 선택식 | 선택한 데이터 | 결과 shape |
| --- | --- | --- |
| `x[0]` | 첫 번째 시퀀스의 다섯 시점 전체 | `(5, 4)` |
| `x[0, 1, :]` | 첫 시퀀스의 둘째 시점 `[3, 8, 12, 6]` | `(4,)` |
| `x[0, 1, 2]` | 위 입력의 세 번째 특징, 숫자 `12` | `()` |
| `x[:, 1, :]` | 두 시퀀스의 둘째 시점 `[[3,8,12,6], [9,5,10,7]]` | `(2, 4)` |
| `x[:, 1:2, :]` | 같은 시점을 크기 1의 시간축을 유지하며 선택 | `(2, 1, 4)` |

`:`는 해당 축 전체를 고른다. 정수 인덱스 `1`로 고른 축은 결과에서 사라지고, 슬라이스 `1:2`로 고른 축은 크기 1로 남는다. `1:2`는 시작 인덱스 1을 포함하고 끝 인덱스 2를 제외한다.

숫자 하나를 <strong>스칼라</strong>, 숫자를 한 축에 나열한 것을 <strong>벡터</strong>, 두 축으로 배열한 것을 <strong>행렬</strong>이라고 한다. 벡터 `[3, 8, 12, 6]`에는 숫자가 4개 있지만 축은 1개다. 그래서 shape는 `(4,)`다. 숫자 하나를 담은 스칼라 텐서의 shape는 `()`다.[^tensor]

## 4. 층, 셀, 뉴런은 무엇을 계산하는가

<strong>가중치</strong>는 입력값에 곱하는 학습 가능한 숫자다. <strong>편향</strong>은 곱셈 결과를 더한 값에 추가로 더하는 학습 가능한 숫자다. 이 둘을 통틀어 모델의 <strong>파라미터</strong>라고 부른다.

<strong>뉴런</strong>은 자신에게 연결된 값들에 가중치를 곱한 결과를 모두 더하고, 편향을 더한 뒤 활성화 함수를 적용해 결과를 만드는 계산 단위다. 활성화 함수는 그 합을 다음 값으로 바꾸는 함수이며, 이번에는 `tanh`를 사용한다.

| 구성 단위 | 담당하는 범위 | 이번 예제 |
| --- | --- | --- |
| 뉴런 하나 | 현재 입력과 이전 은닉값을 이용해 자기 결과를 계산 | 한 시퀀스·한 시점에서 숫자 1개 |
| 셀 계산 하나 | 해당 시점의 은닉 상태 전체를 계산 | A·B·C의 결과를 모은 숫자 3개 |
| RNN 층 하나 | 같은 계산 규칙과 파라미터로 시퀀스를 처리 | 같은 셀 계산을 다섯 시점에 적용 |

<figure class="rnn-figure">
<img src="/rnn-sequence-hidden-state/cell-connections-ko.svg" alt="현재 입력 특징 네 개와 이전 은닉값 세 개가 현재 뉴런 A, B, C 각각의 계산으로 들어간다. 각 뉴런은 자신의 가중치와 편향을 사용한다. 세 결과는 [A_t,B_t,C_t]로 모이며 현재 A의 결과가 현재 B의 입력으로 들어가는 연결은 없다." loading="lazy">
<figcaption>뉴런 A·B·C는 모두 같은 현재 입력 전체와 같은 이전 은닉 상태 전체를 읽는다. 각 뉴런이 곱하는 가중치는 별도로 저장된다.</figcaption>
</figure>

한 시퀀스의 한 시점에서 A·B·C가 만든 숫자를 각각 `Aₜ`, `Bₜ`, `Cₜ`라고 하면, 셀의 결과는 `hₜ = [Aₜ, Bₜ, Cₜ]`다. <strong>셀의 출력에는 세 뉴런의 결과가 모두 들어 있다.</strong> 마지막 뉴런 C의 값만 출력하는 구조가 아니다.

뉴런 하나의 내부에서는 여러 곱셈 결과를 합산한다. 셀의 출력을 만들 때에는 세 뉴런의 결과를 각자 유지한 채 벡터로 모은다. 두 단계에서 하는 일이 다르다.

두 시퀀스를 함께 계산하면 상태의 shape는 `(B, H) = (2, 3)`이다. 축 0은 시퀀스 인덱스 `0~1`, 축 1은 뉴런 인덱스 `0~2`다. 각 시퀀스가 세 값을 가지므로 전체에는 숫자 6개가 들어 있다. 은닉 상태를 담는 텐서가 항상 한 축만 갖는 것은 아니다.

실제 PyTorch는 이런 계산을 가중치 행렬과 텐서 연산으로 수행한다. 그림에 그린 뉴런마다 별도의 Python 객체를 만드는 방식으로 이해할 필요는 없다.

## 5. 가중치 두 묶음은 곱하는 대상이 다르다

기본 RNN에는 현재 입력에 곱하는 가중치와 이전 은닉 상태에 곱하는 가중치가 있다. PyTorch에서는 각각 `weight_ih`, `weight_hh`라는 이름을 쓴다. `i`는 input, `h`는 hidden의 첫 글자다.[^cell]

| 이름 | 연결 | shape | 이번 크기 |
| --- | --- | --- | --- |
| `weight_ih` | 현재 입력 → 현재 은닉값 | `(H, F)` | `(3, 4)` |
| `weight_hh` | 이전 은닉값 → 현재 은닉값 | `(H, H)` | `(3, 3)` |

두 행렬 모두 축 0이 <strong>현재 결과를 계산할 뉴런</strong>을 고른다. `weight_ih`의 축 1은 입력 특징을 고르고, `weight_hh`의 축 1은 이전 은닉값을 고른다.

<figure class="rnn-figure">
<img src="/rnn-sequence-hidden-state/weight-layout-ko.svg" alt="weight_ih는 현재 뉴런 A,B,C별 네 입력 가중치를 저장한 3×4 행렬이다. weight_hh는 현재 뉴런별 이전 A,B,C 가중치를 저장한 3×3 행렬이다. 배치 입력 (2,4)에 전치한 (4,3) 행렬을 곱해 (2,3)을 만든다." loading="lazy">
<figcaption>PyTorch가 저장한 가중치의 첫 축은 현재 뉴런이다. 배치를 앞에 둔 입력과 행렬곱할 때에는 가중치 행렬을 전치한다.</figcaption>
</figure>

뉴런 A의 입력 가중치는 `[0.11, -0.07, 0.04, 0.02]`다. A도 입력 특징 4개를 전부 사용하고, B와 C도 같은 입력 특징 4개를 전부 사용한다. 각 뉴런은 자기 가중치로 계산한다.

뉴런 A의 이전 상태용 가중치는 `[0.21, -0.14, 0.07]`다. 따라서 현재 A를 계산할 때 <strong>이전 A·B·C를 모두 사용한다.</strong> B와 C도 이전 상태 전체를 읽는다. 이렇게 각 출력 계산이 입력 묶음의 모든 값에 연결된 구조를 완전 연결이라고 한다.

이전 은닉값은 앞선 계산의 결과이고, 순환 가중치는 그 결과에 곱하는 파라미터다. `이전 은닉값 × 순환 가중치`로 계산하며 두 종류의 숫자를 구별해서 저장한다.

### 왜 가중치 뒤에 .T를 붙이는가

`@`는 행렬곱이다. 왼쪽 행렬의 한 행과 오른쪽 행렬의 한 열에서 대응하는 값끼리 곱하고 합한다. `.T`는 여기서 2차원 행렬의 행과 열을 바꾸는 전치다.

| 계산 | 왼쪽 shape | 오른쪽 shape | 결과 shape |
| --- | --- | --- | --- |
| `xt @ weight_ih.T` | `(2, 4)` | `(4, 3)` | `(2, 3)` |
| `previous_state @ weight_hh.T` | `(2, 3)` | `(3, 3)` | `(2, 3)` |

첫 계산은 각 시퀀스의 입력 4개를 현재 뉴런별 가중치 4개와 맞춰 계산한다. 두 번째 계산은 각 시퀀스의 이전 값 3개를 현재 뉴런별 순환 가중치 3개와 맞춘다. `weight_hh`는 정사각 행렬이어서 전치 전후 shape가 같지만, 값의 위치는 바뀐다. `.T`를 빼도 shape 오류가 없을 수 있으므로 연결 방향을 확인해야 한다.

## 6. 뉴런당 가중치는 7개, 전체 파라미터는 27개다

은닉 뉴런 하나는 입력 특징 `F`개와 이전 은닉값 `H`개를 사용한다. 따라서 뉴런 하나의 가중치 수는 `F+H`다. 이 예제에서는 `4+3=7`개다.

뉴런이 3개이므로 전체 가중치 수는 `H×(F+H) = 3×7 = 21`개다. 여기에 편향을 따로 센다.

PyTorch의 `nn.RNNCell`은 `bias=True`일 때 두 편향 벡터를 저장한다. `bias_ih`는 입력 쪽 편향, `bias_hh`는 이전 상태 쪽 편향이다. 각각 shape가 `(H,)`이므로 뉴런마다 편향이 두 개씩 대응한다.[^cell]

| 뉴런 | `bias_ih` | `bias_hh` | 순전파에서 더해지는 합 |
| --- | ---: | ---: | ---: |
| A | 0.015 | -0.008 | 0.007 |
| B | -0.025 | 0.018 | -0.007 |
| C | 0.035 | -0.028 | 0.007 |

입력 경로가 두 개라고 편향도 반드시 두 개여야 하는 것은 아니다. 계산식에서는 `bias_ih + bias_hh`를 하나의 합쳐진 편향으로 쓸 수 있다. 다만 PyTorch에 저장된 학습 가능한 숫자를 셀 때에는 두 벡터를 모두 포함해야 한다.

| 파라미터 텐서 | shape | 숫자 개수 |
| --- | --- | ---: |
| `weight_ih` | `(3, 4)` | 12 |
| `weight_hh` | `(3, 3)` | 9 |
| `bias_ih` | `(3,)` | 3 |
| `bias_hh` | `(3,)` | 3 |
| 합계 | 텐서 객체 4개 | 27 |

가중치 21개, 편향 6개, 학습 가능한 숫자 27개다. ‘파라미터 텐서 객체 4개’와 ‘학습 가능한 숫자 27개’는 세는 단위가 다르다. `bias=False`라면 편향 두 벡터가 없어져 텐서 객체는 2개, 숫자는 21개가 된다.

시퀀스가 2개이거나 시점이 5개라고 파라미터 수에 2나 5를 곱하지 않는다. 여러 입력이 같은 파라미터를 재사용한다. 이 개수 식은 지금 다루는 기본 RNN 한 층을 기준으로 한다.

## 7. 첫 시점의 세 은닉값을 직접 계산한다

`tanh`는 합산한 숫자를 비선형적으로 바꾸는 활성화 함수다. 예를 들어 `tanh(0.377)`은 약 `0.360099`다. 벡터에 적용하면 각 원소를 각각 바꾼다. 수학적으로 유한한 입력의 결과는 −1과 1 사이이며, 컴퓨터에서는 반올림 때문에 ±1로 표시되기도 한다.

첫 시퀀스의 첫 입력은 `x₁ = [2, 5, 7, 11]`이고, 초기 상태는 `h₀ = [0, 0, 0]`이다. 초기 상태가 0이라고 가중치도 0인 것은 아니다. 앞에서 정한 가중치를 그대로 사용한다. PyTorch의 기본 RNNCell과 RNN은 초기 상태를 생략하면 0으로 시작한다.[^cell][^rnn]

뉴런 A의 계산을 세 부분으로 나누면 다음과 같다.

| 부분 | 계산 | 결과 |
| --- | --- | ---: |
| 현재 입력 | `2×0.11 + 5×(-0.07) + 7×0.04 + 11×0.02` | 0.370 |
| 이전 상태 | `0×0.21 + 0×(-0.14) + 0×0.07` | 0 |
| 편향 | `0.015 + (-0.008)` | 0.007 |

이 세 결과를 더한 `0.377`에 `tanh`를 적용하면 A의 새 은닉값은 약 `0.360099`다. B와 C도 같은 입력과 초기 상태를 사용하되 자기 가중치로 계산한다.

| 뉴런 | 현재 입력 부분 | 이전 상태 부분 | 편향 합 | tanh 결과 |
| --- | ---: | ---: | ---: | ---: |
| A | 0.370 | 0 | 0.007 | 0.360099 |
| B | 0.560 | 0 | -0.007 | 0.502765 |
| C | 1.310 | 0 | 0.007 | 0.866036 |

세 결과를 모으면 `h₁ ≈ [0.360099, 0.502765, 0.866036]`이다. 첫 시점에도 이전 상태를 사용하는 계산 항은 존재한다. 이번에는 초기 상태가 0이라서 그 곱셈 결과가 0이 된다.

## 8. 두 번째 시점에서는 이전 세 값이 모두 쓰인다

두 번째 입력은 `x₂ = [3, 8, 12, 6]`이다. 이번 계산은 방금 만든 `h₁`을 이전 은닉 상태로 받는다. 뉴런 A가 읽는 값은 입력 숫자 4개와 이전 은닉값 3개, 총 7개다.

| 부분 | 계산 | 결과 |
| --- | --- | ---: |
| 현재 입력 | `3×0.11 + 8×(-0.07) + 12×0.04 + 6×0.02` | 0.370 |
| 이전 상태 | `A₁×0.21 + B₁×(-0.14) + C₁×0.07` | 약 0.065856 |
| 편향 | `0.015 + (-0.008)` | 0.007 |

따라서 A의 새 결과는 `tanh(0.370 + 0.065856… + 0.007) ≈ 0.416009`다. 첫 시점과 입력 부분의 합이 우연히 같아도, 이전 상태 부분이 달라져 최종 결과는 바뀐다.

| 뉴런 | 현재 입력 부분 | 이전 상태 부분 | 편향 합 | 새 은닉값 |
| --- | ---: | ---: | ---: | ---: |
| A | 0.370 | 0.065856 | 0.007 | 0.416009 |
| B | 1.310 | 0.172000 | -0.007 | 0.900527 |
| C | 0.250 | 0.306724 | 0.007 | 0.510735 |

새 상태는 `h₂ ≈ [0.416009, 0.900527, 0.510735]`다. 표는 소수 여섯 자리로 반올림했으며, 다음 계산에는 반올림 전 값을 사용한다.

이 흐름을 배치 전체의 식으로 쓰면 다음과 같다. `xₜ`는 이번 시점에 고른 `(B,F)` 입력, `hₜ₋₁`은 `(B,H)` 이전 상태다. `Wᵀ`는 가중치 행렬을 전치한 것이며, 편향은 각 시퀀스의 같은 뉴런 위치에 더해진다.

<div class="rnn-math">
$$
h_t=\tanh\left(x_tW_{ih}^{\mathsf T}+b_{ih}+h_{t-1}W_{hh}^{\mathsf T}+b_{hh}\right)
$$
</div>

첫 입력 `x₁`의 원본이 두 번째 시점의 현재 입력 자리에 다시 들어가지는 않는다. 첫 입력을 처리한 결과 `h₁`이 다음 계산에 사용된다. 그래서 과거 입력의 영향이 이어질 수 있다. 은닉 상태가 과거 입력 원본을 모두 저장하거나, 모든 정보를 손실 없이 보존한다는 뜻은 아니다.

## 9. 시점의 순서와 뉴런의 계산 순서를 구별한다

같은 시퀀스에서는 `h₁ → h₂ → h₃`의 의존관계가 있다. 하지만 같은 시점의 뉴런 A·B·C는 <strong>모두 이전 시점의 상태</strong>를 읽는다.

| 계산할 결과 | 사용하는 이전 은닉값 | 사용하는 현재 뉴런의 결과 |
| --- | --- | --- |
| `A₂` | `A₁, B₁, C₁` | 없음 |
| `B₂` | `A₁, B₁, C₁` | 없음 |
| `C₂` | `A₁, B₁, C₁` | 없음 |

`B₂`를 계산할 때 방금 만든 `A₂`를 `A₁` 자리에 넣으면 다른 계산이 된다. 직접 반복문으로 구현하더라도 <strong>이전 상태를 유지한 채 새 A·B·C를 계산하고, 완성된 세 결과로 상태 전체를 교체</strong>해야 한다.

같은 시점의 뉴런 계산과 서로 다른 시퀀스의 계산은 행렬 연산으로 묶을 수 있다. 실제 병렬 실행 방식은 장치와 구현에 따라 달라진다. 코드가 A·B·C 순서로 계산하도록 작성되었다는 사실과, B가 현재 A의 결과를 필요로 한다는 사실은 같지 않다.

### 그림에 셀이 다섯 개 있으면 객체도 다섯 개인가

`nn.RNNCell` 객체 하나를 만들고 배치 전체를 매 시점 전달하는 코드에서는 다음 개수를 구별한다.

| 세는 대상 | 개수 | 이유 |
| --- | ---: | --- |
| RNNCell 객체 | 1 | 한 번 만들고 재사용 |
| 시간축 그림의 계산 위치 | 5 | 다섯 시점에 같은 계산 적용 |
| Python의 `cell(...)` 호출 | 5 | 한 호출이 시점 하나 담당 |
| 개별 시퀀스·시점의 조합 | 10 | `B×T = 2×5` |
| 모든 시점의 출력 숫자 | 30 | `B×T×H = 2×5×3` |
| 공유하는 학습 파라미터 숫자 | 27 | 가중치 21개와 편향 6개 |

출력 숫자 30개는 계산으로 만든 결과의 수다. 모델에 새로운 뉴런 객체 30개가 생긴다는 뜻이 아니다.

시점이 늘면 계산 횟수와 모든 시점을 저장한 출력의 크기가 늘어난다. 파라미터 수는 그대로다. 메모리 사용량은 모든 결과와 자동 미분 기록을 보관하는지에 따라서도 달라진다. 마지막 상태만 유지하는 순전파와 학습을 위한 전체 기록 보관을 같은 조건으로 비교하면 안 된다.

## 10. RNNCell은 한 시점을 계산한다

`torch`는 PyTorch 패키지이고, `torch.nn`은 신경망 구성요소를 제공하는 모듈이다. `from torch import nn`은 `torch.nn`을 `nn`이라는 이름으로 가져온다.

`nn.RNNCell`은 셀 객체를 만드는 클래스다. `cell = nn.RNNCell(input_size=4, hidden_size=3)`은 파라미터를 가진 객체를 만든다. 이후 `cell(xt, state)`로 그 객체에 입력을 주어 계산한다.[^cell]

| 인자 | 정하는 것 | 이번 값 |
| --- | --- | --- |
| `input_size` | 한 시점의 입력 특징 수 `F` | 4 |
| `hidden_size` | 은닉 뉴런 수 `H` | 3 |
| `bias` | 편향 사용 여부 | `True` |
| `nonlinearity` | 합산 결과에 적용할 활성화 함수 | `"tanh"` |

배치 크기 2나 시점 수 5를 `input_size`에 넣지 않는다. 이 둘은 전달하는 데이터의 구조로 결정된다.

| 한 번의 호출 | `xt` | 이전 `state` | 반환값 |
| --- | --- | --- | --- |
| 배치 크기 2 | `(2, 4)` | `(2, 3)` | `(2, 3)` 텐서 |
| 배치 축 없는 시퀀스 하나 | `(4,)` | `(3,)` | `(3,)` 텐서 |

한 번의 RNNCell 호출에는 시간축이 없다. 개발자가 `x[:, t, :]`로 현재 시점을 골라 반복 호출한다. 매 시점 `(2,4)` 입력이 들어오고 `(2,3)` 상태가 나온다.

### state = cell(xt, state)는 어떤 순서로 실행되는가

대입문은 오른쪽 계산을 끝낸 뒤 왼쪽 이름에 결과를 연결한다.[^python]

1. 오른쪽 `state`가 가리키는 이전 텐서를 읽는다.
2. `xt`와 이전 상태로 새 상태 텐서를 계산한다.
3. 반환된 새 텐서를 왼쪽의 `state`라는 이름으로 가리킨다.

같은 변수명이 양쪽에 있어도 무한 재귀가 아니다. 설명할 때에는 `previous_state = state`로 이전 상태에 이름을 하나 더 붙이고, `state = cell(xt, previous_state)`로 써도 된다. 첫 대입 자체는 텐서의 복사본을 만들지 않는다. 이번 코드는 이전 텐서의 값을 직접 덮어쓰지 않는다.

`cell_scalar` 같은 이름을 보더라도 이름에 특별한 PyTorch 기능이 있는 것은 아니다. 작성자가 붙인 변수명이다. 실제 입력·출력 크기는 객체 생성에 사용한 인자와 텐서 shape로 확인한다.

## 11. reshape는 숫자를 늘리지 않고 축 구성을 바꾼다

첫 시퀀스의 둘째 시점 `x[0, 1, :]`를 고르면 `[3, 8, 12, 6]`이 나오며 shape는 `(4,)`다. 이를 배치 크기 1의 입력으로 주려면 `.reshape(1, 4)`로 `[[3, 8, 12, 6]]`을 만들 수 있다.[^reshape]

| 구분 | 실제 값 | shape | 축의 의미 |
| --- | --- | --- | --- |
| 배치 축 생략 | `[3, 8, 12, 6]` | `(4,)` | 특징 4개 |
| 배치 축 유지 | `[[3, 8, 12, 6]]` | `(1, 4)` | 시퀀스 1개, 특징 4개 |

두 경우 모두 원소는 4개다. 바뀐 것은 배열의 축 구성이다. 입력을 `(1,4)`로 주었다면 짝이 되는 이전 상태도 `(1,3)`으로 준비한다. 첫 시점부터 시작하는 경우라면 `torch.zeros(1, 3, dtype=torch.float64)`를 사용할 수 있다. `torch.zeros`는 지정한 shape를 0으로 채운 텐서를 만든다. `dtype`은 저장할 숫자의 자료형을 정하며, `torch.float64`는 64비트 실수형이다. 입력과 모델도 같은 자료형으로 맞춘다.

RNNCell은 `(4,)` 입력과 `(3,)` 상태도 지원하므로 항상 reshape가 필요한 것은 아니다. 입력과 상태를 둘 다 배치 축이 있는 방식으로 맞출지, 둘 다 생략할지를 일관되게 선택하면 된다.

이번 전체 배치 코드는 `xt = x[:, t, :]`가 이미 `(2,4)`를 반환한다. 그래서 reshape를 추가하지 않는다. 숫자 개수만 같다고 `(4,)`를 `(2,2)`로 바꾸면 시퀀스 수와 특징 수의 의미가 달라진다. `input_size=4`인 셀에는 그런 입력을 전달할 수 없다.

## 12. 상태를 저장하고 모으는 코드부터 읽는다

전체 실습 코드를 보기 전에 값의 자료형과 기록 방법을 정리하자. <strong>float64</strong>는 실수를 64비트로 표현하는 자료형이다. 이 예제에서는 수치 검산을 위해 모델·입력·초기 상태를 모두 float64로 맞춘다.

| 표현 | 종류와 하는 일 | 결과 또는 효과 |
| --- | --- | --- |
| `cell.double()` | 모듈 메서드. 실수형 파라미터 등을 float64로 변경 | 같은 모듈 반환 |
| `torch.tensor(..., dtype=DTYPE)` | 함수. 주어진 값으로 텐서 생성 | 지정 자료형의 텐서 |
| `torch.zeros(B, H, dtype=DTYPE)` | 함수. 0으로 채운 상태 생성 | `(2,3)` 텐서 |
| `with torch.no_grad():` | 해당 블록의 자동 미분 기록을 끄는 문맥 | 계산은 수행하고 기울기 기록은 생략 |
| `weight.copy_(values)` | 텐서 메서드. 준비한 값을 기존 텐서에 복사 | 기존 텐서의 값 변경 |
| `weight.fill_(value)` | 텐서 메서드. 모든 원소를 같은 값으로 채움 | 기존 텐서의 값 변경 |
| `state[0].tolist()` | 텐서 메서드. 첫 시퀀스의 상태를 Python 리스트로 변환 | 숫자 3개의 리스트 |
| `state[0, 0].item()` | 텐서 메서드. 원소 하나를 Python 숫자로 변환 | 숫자 하나 |

자동 미분은 계산을 기록했다가 기울기를 구하는 기능이다. 이번에는 가중치를 직접 설정하고 순전파 결과를 확인하므로 `no_grad`를 사용한다. 이 블록이 끝났다고 모델의 학습 기능이 영구적으로 꺼지는 것은 아니다.[^no-grad]

PyTorch 텐서 메서드 이름 끝의 `_`는 기존 텐서 값을 직접 수정한다는 관례다. 모든 가중치를 같은 숫자로 만들 규칙은 없다. 이번에는 연결별 값을 구별하려고 `fill_` 대신 `copy_`로 서로 다른 값을 넣는다.[^module][^tensor]

`item()`은 원소가 정확히 하나일 때 사용한다. 숫자 3개를 가진 `state[0]`에는 `tolist()`를 사용한다. `tolist()`는 다차원 텐서에는 중첩 리스트를, 스칼라 텐서에는 Python 숫자를 반환한다. 계산을 이어갈 때에는 텐서를 사용하고, 리스트 변환은 출력 확인용으로 사용한다.[^item]

### trace.append와 stack은 값을 더하는 연산이 아니다

`trace`는 시점별 결과를 보관할 Python 리스트다. `trace.append(state)`는 현재 상태 텐서를 리스트 끝에 추가한다. RNNCell이 다음 호출에서 새 결과 텐서를 반환하면 `state` 이름은 새 결과를 가리키지만, 리스트에는 앞서 넣은 텐서가 남는다. 저장한 텐서 자체를 직접 수정하면 그 내용은 바뀔 수 있다.

`torch.stack(trace, dim=1)`은 같은 shape의 텐서들을 <strong>새 축을 만들어 모은다.</strong> 이번에는 `(2,3)` 텐서 5개를 결과의 축 1에 나열하여 `(2,5,3)`으로 만든다. `dim=1`의 1은 새 시간축의 번호다. 시점별 값을 합하거나 평균 내는 연산이 아니다.[^stack]

배치 축을 생략한 함수에서는 `(3,)` 상태 5개를 `dim=0`으로 모아 `(5,3)`을 만든다. 어느 방식이든 시점별 결과 5개를 따로 보관한다.

## 13. nn.RNN의 output과 h_n은 서로 다른 범위를 담는다

`nn.RNN`은 전체 시퀀스를 받아 처리하는 클래스다. `nn.RNNCell`을 사용하면 개발자가 시점별 반복을 쓰고, `nn.RNN`을 사용하면 한 번의 호출로 전체 시퀀스를 전달한다. 둘은 제공하는 사용 방식이 다르다. `nn.RNN`이 반드시 Python 반복문으로 RNNCell 객체를 호출한다는 뜻은 아니다.[^rnn]

이 글의 설정은 `input_size=4`, `hidden_size=3`, `num_layers=1`, `batch_first=True`, `bidirectional=False`다. `num_layers`는 RNN 층 수이고, `bidirectional=False`는 정방향만 사용한다는 뜻이다.

`output, h_n = rnn(x)`는 텐서 두 개를 반환한다. 아래 설명은 한 층·단방향이며, 모든 시퀀스의 길이가 5인 현재 예제를 기준으로 한다.

| 텐서 | 담는 내용 | 축별 의미 | shape |
| --- | --- | --- | --- |
| `x` | 전체 입력 | 시퀀스, 시점, 입력 특징 | `(2,5,4)` |
| `output` | 모든 시점의 은닉 상태 | 시퀀스, 시점, 은닉값 | `(2,5,3)` |
| `h_n` | 층·방향별 마지막 은닉 상태 | 층·방향, 시퀀스, 은닉값 | `(1,2,3)` |
| `output[:, -1, :]` | 마지막 시점의 상태 | 시퀀스, 은닉값 | `(2,3)` |
| `h_n[0]` | 유일한 층·방향의 마지막 상태 | 시퀀스, 은닉값 | `(2,3)` |

`-1`은 해당 축의 마지막 인덱스다. `h_n`의 축 0 크기가 1인 이유는 이번 모델이 한 층·한 방향이기 때문이다. 배치 크기가 1이어서가 아니다. 축 1의 크기는 시퀀스 수 2이며 유효 인덱스는 `0~1`, 축 2의 크기는 은닉값 수 3이며 유효 인덱스는 `0~2`다.

### batch_first는 입력과 output의 축 순서를 정한다

| 설정 | 입력의 축 순서 | output의 축 순서 | h_n의 축 순서 |
| --- | --- | --- | --- |
| `batch_first=True` | `(B,T,F)` | `(B,T,H)` | `(L,B,H)` |
| `batch_first=False` | `(T,B,F)` | `(T,B,H)` | `(L,B,H)` |

`batch_first=False`가 기본값이다. <strong>`batch_first=True`로 설정해도 `h_n`의 축 순서는 바뀌지 않는다.</strong> 위 표의 `L`은 단방향일 때의 층 수이며, 양방향 모델에서는 첫 축에 층 수와 방향 수를 함께 반영한다.[^rnn]

전체 입력을 한 번에 전달해도 은닉 상태 사이의 시간 의존관계는 유지된다. 함수 호출 횟수 1회와, 그 내부에서 처리하는 시점 수 5개는 다른 개수다.

## 14. 호출을 나누거나 층을 쌓으면 무엇을 이어야 하는가

### 호출을 나누어 같은 시퀀스를 이어갈 때

RNNCell과 RNN은 이전 호출의 마지막 상태를 다음 호출에 자동으로 넣지 않는다. 같은 시퀀스를 나누어 처리하려면 반환된 상태를 직접 전달한다.

| 순서 | 실행 표현 | 의미 |
| --- | --- | --- |
| 첫 호출 | `out1, h1 = rnn(x[:, 0:1, :])` | 첫 시점을 0 상태에서 처리 |
| 다음 호출 | `out2, h2 = rnn(x[:, 1:2, :], h1)` | 둘째 시점을 첫 호출의 마지막 상태로 처리 |

여기서 슬라이스 `0:1`, `1:2`는 길이 1의 시간축을 유지한다. 입력 shape는 각각 `(2,1,4)`이고, 전달하는 `h1`은 `(1,2,3)`이다. 서로 독립적인 새 시퀀스를 시작할 때에는 앞선 시퀀스의 상태를 실수로 이어 붙이지 않도록 한다.

### 같은 층의 다음 시점과 위층은 다르다

`h₂`의 아래 숫자 2는 두 번째 시점을 뜻한다. 두 번째 은닉층을 뜻하지 않는다. 같은 층은 시간이 바뀌어도 자신의 가중치를 공유하고, 은닉 크기 `H`도 유지한다.

여러 RNN 층을 쌓으면 각 층이 자기 가중치와 자기 은닉 상태를 갖는다. 위층은 <strong>같은 시점의 아래층 출력</strong>과 <strong>위층 자신의 이전 시점 상태</strong>를 사용한다.

| 연결 방향 | 입력으로 전달하는 것 | 파라미터 관계 |
| --- | --- | --- |
| 같은 층의 이전 시점 → 현재 시점 | 그 층의 이전 은닉 상태 | 시간에 걸쳐 같은 파라미터 사용 |
| 같은 시점의 아래층 → 위층 | 아래층의 현재 은닉 상태 | 각 층은 별도의 파라미터 사용 |

하나의 `nn.RNN`에서 `num_layers`를 늘리면 모든 층이 같은 `hidden_size`를 사용한다. 층별 은닉 크기를 다르게 설계하려면 별도 모듈을 연결하고 위층의 입력 크기를 아래층 출력 크기와 맞춰야 한다. 여러 층을 사용한 `nn.RNN`의 `output`에는 <strong>맨 위층의 모든 시점</strong>이 들어가고, `h_n`에는 <strong>각 층·방향의 마지막 상태</strong>가 들어간다.[^rnn]

### 은닉 상태와 과제의 예측값도 구별한다

은닉값 3개가 자동으로 기온 예측값이나 분류 결과가 되는 것은 아니다. 과제에 필요한 출력 크기를 `K`라고 하면, 마지막 상태 `(B,H)`에 `nn.Linear(H,K)`를 적용하여 `(B,K)`를 만들 수 있다. `Linear`는 마지막 축의 입력값에 가중치를 곱하고 편향을 더하는 계층이다.[^linear]

모든 시점의 예측이 필요하면 `(B,T,H)`의 각 시점에 같은 출력 계층을 적용해 `(B,T,K)`를 만든다. `H`는 내부 은닉 상태의 크기이고, `K`는 과제가 요구하는 출력 크기다. 분류에서는 이 결과를 곧바로 확률이라고 부르지 않고, 사용하는 손실 함수와 예측 방식에 맞춰 해석한다.

## 15. 같은 숫자로 전체 Python 실습을 실행한다

아래 코드는 모델을 학습시키지 않는다. 정해 둔 가중치로 계산한 결과가 RNNCell·수동 행렬 계산·RNN에서 일치하는지 확인한다. 코드 전체를 위에서부터 이어서 실행하면 된다.

`assert`는 조건이 거짓일 때 오류를 발생시키는 Python 문법이다. 여기서는 예제 결과를 확인하는 데 사용한다. `torch.allclose`는 대응하는 원소들이 허용 오차 안에서 같은지 검사한다. `rtol`은 값의 크기에 비례하는 상대 허용 오차이고, `atol`은 절대 허용 오차다. 실수 계산은 연산 순서에 따라 작은 반올림 차이가 생길 수 있어서 사용한다.[^allclose]

코드의 흐름은 <strong>셀 생성 → 파라미터 설정 → 배치 입력 준비 → 시점별 수동 계산과 셀 결과 비교 → 출력 모으기 → 순서·길이 실험 → RNN과 비교</strong>다. 모든 파라미터 값을 직접 지정하므로 모델 생성 때 임의로 초기화된 값은 이후 계산에 쓰이지 않는다.

```python
# RNN 시퀀스·은닉 상태 실습: CPU / float64 / 순전파만 실행
import torch
from torch import nn

# B: 배치 크기, T: 시점 수, F: 입력 특징 수, H: 은닉 뉴런 수
B, T, F, H = 2, 5, 4, 3

# 수치 계산을 확인하기 위해 64비트 실수형을 사용한다.
DTYPE = torch.float64

# 하나의 셀 객체를 만든다.
# bias=True: 두 종류의 편향을 사용한다.
# nonlinearity="tanh": 합산 결과에 tanh를 적용한다.
cell = nn.RNNCell(
    input_size=F,
    hidden_size=H,
    bias=True,
    nonlinearity="tanh",
).double()

# 모델 생성 후 우리가 정한 가중치와 편향으로 바꾼다.
# 이 수정 과정은 자동 미분 기록에 넣지 않는다.
with torch.no_grad():
    cell.weight_ih.copy_(torch.tensor([
        [ 0.11, -0.07,  0.04,  0.02],  # 현재 뉴런 A
        [-0.09,  0.13,  0.06, -0.03],  # 현재 뉴런 B
        [ 0.05,  0.08, -0.12,  0.15],  # 현재 뉴런 C
    ], dtype=DTYPE))

    cell.weight_hh.copy_(torch.tensor([
        [ 0.21, -0.14,  0.07],  # 이전 A, B, C → 현재 A
        [-0.16,  0.25,  0.12],  # 이전 A, B, C → 현재 B
        [ 0.19, -0.06,  0.31],  # 이전 A, B, C → 현재 C
    ], dtype=DTYPE))

    cell.bias_ih.copy_(torch.tensor(
        [0.015, -0.025, 0.035], dtype=DTYPE
    ))

    cell.bias_hh.copy_(torch.tensor(
        [-0.008, 0.018, -0.028], dtype=DTYPE
    ))

# shape = (B, T, F) = (2, 5, 4)
x = torch.tensor([
    [
        [2., 5., 7., 11.],
        [3., 8., 12., 6.],
        [4., 6., 9., 13.],
        [8., 3., 5., 10.],
        [7., 9., 2., 14.],
    ],
    [
        [6., 4., 8., 3.],
        [9., 5., 10., 7.],
        [12., 11., 6., 4.],
        [5., 14., 3., 8.],
        [11., 7., 13., 2.],
    ],
], dtype=DTYPE)

# 파라미터 객체의 식별값을 기록한다.
ids_before = tuple(id(p) for p in cell.parameters())

# 파라미터 값도 별도로 복사한다.
# detach(): 자동 미분 기록과 분리한다.
# clone(): 별도 데이터 복사본을 만든다.
values_before = [p.detach().clone() for p in cell.parameters()]

# 두 시퀀스가 각각 은닉값 3개를 가진다.
# shape = (B, H) = (2, 3)
state = torch.zeros(B, H, dtype=DTYPE)

# 매 시점의 (B, H) 결과 텐서를 저장한다.
trace = []

with torch.no_grad():
    for t in range(T):
        # t는 0, 1, 2, 3, 4다.
        # 두 시퀀스에서 같은 순서의 시점을 선택한다.
        # shape: (B, F) = (2, 4)
        xt = x[:, t, :]

        # 이번 시점의 모든 뉴런이 사용할 이전 상태다.
        # 이 텐서를 뉴런별 계산 도중 직접 수정하지 않는다.
        previous_state = state

        # @는 행렬곱이다.
        # .T는 여기서 2차원 가중치 행렬을 전치한다.
        #
        # 입력:       (B, F) = (2, 4)
        # weight_ih:  (H, F) = (3, 4)
        # 전치 결과:  (F, H) = (4, 3)
        # 곱셈 결과:  (B, H) = (2, 3)
        input_part = xt @ cell.weight_ih.T

        # 이전 상태:  (B, H) = (2, 3)
        # weight_hh.T:(H, H) = (3, 3)
        # 곱셈 결과:  (B, H) = (2, 3)
        #
        # 정사각 행렬이어도 전치하면 값의 위치가 바뀐다.
        previous_part = previous_state @ cell.weight_hh.T

        # 편향 shape는 (H,)다.
        # 각 시퀀스의 동일한 뉴런 위치에 같은 편향이 더해진다.
        manual_state = torch.tanh(
            input_part
            + cell.bias_ih
            + previous_part
            + cell.bias_hh
        )

        # 같은 계산을 PyTorch RNNCell로 실행한다.
        # 반환 shape: (B, H) = (2, 3)
        state = cell(xt, previous_state)

        # allclose: 모든 대응 원소가 허용 오차 안에서 같은지 검사한다.
        # rtol: 값의 크기에 비례하는 상대 허용 오차
        # atol: 절대 허용 오차
        assert torch.allclose(
            state, manual_state, rtol=1e-10, atol=1e-12
        )

        trace.append(state)

        # 첫 번째 시퀀스의 새 은닉 상태만 출력한다.
        # state[0]의 shape는 (3,)다.
        print(f"시점 {t + 1}: {state[0].tolist()}")

    # (2, 3) 텐서 5개를 시간축으로 모은다.
    # 결과 shape: (B, T, H) = (2, 5, 3)
    output = torch.stack(trace, dim=1)

print("전체 입력:", tuple(x.shape))
print("전체 출력:", tuple(output.shape))
print("마지막 상태:", tuple(state.shape))

# 첫 번째 시퀀스의 출력: 소수점 여섯 자리 반올림
#
# 시점 1: [0.360099,  0.502765, 0.866036]
# 시점 2: [0.416009,  0.900527, 0.510735]
# 시점 3: [0.567644,  0.654344, 0.940266]
# 시점 4: [0.824405, -0.150259, 0.956839]
# 시점 5: [0.645847,  0.176484, 0.997772]


# -------------------------------------------------------------------
# 하나의 시퀀스를 실행하는 함수
# 입력: (T, F), 반환: (T, H)
# -------------------------------------------------------------------

def run_given_cell(values: torch.Tensor) -> torch.Tensor:
    # ndim은 텐서의 축 개수다.
    # 여기서는 배치 축 없는 시퀀스 (T, F)를 받는다.
    if values.ndim != 2 or values.shape[1] != F or values.shape[0] == 0:
        raise ValueError("values는 비어 있지 않은 (T, F) 텐서여야 합니다.")

    # 모델과 입력의 자료형 및 계산 장치가 맞는지 검사한다.
    if (
        values.dtype != cell.weight_ih.dtype
        or values.device != cell.weight_ih.device
    ):
        raise ValueError("values와 cell의 자료형 및 장치가 같아야 합니다.")

    # 함수 호출마다 초기 상태를 새로 만든다.
    # 따라서 앞선 함수 호출의 마지막 상태를 이어받지 않는다.
    # 배치 축을 생략했으므로 shape는 (H,)다.
    state = torch.zeros(
        H,
        dtype=values.dtype,
        device=values.device,
    )

    trace = []

    with torch.no_grad():
        # 2차원 values를 반복하면 각 시점의 (F,) 텐서를 받는다.
        for xt in values:
            # 이전 state를 입력으로 사용한 뒤 새 state를 받는다.
            state = cell(xt, state)
            trace.append(state)

    # (H,) 텐서 T개를 모아 (T, H)로 만든다.
    return torch.stack(trace, dim=0)


# -------------------------------------------------------------------
# 실험 A: 입력 순서를 바꾸면?
# -------------------------------------------------------------------

original = run_given_cell(x[0])

# 첫 번째 시퀀스의 시점 순서만 바꾼다.
# [2, 0, 1, 3, 4]는 사용할 시점 인덱스의 순서다.
reordered = run_given_cell(x[0, [2, 0, 1, 3, 4], :])

print("원래 순서의 마지막 상태:", original[-1].tolist())
print("바꾼 순서의 마지막 상태:", reordered[-1].tolist())

# 원래 순서:
# [0.645847, 0.176484, 0.997772]
#
# 바꾼 순서:
# [0.638208, 0.188234, 0.997711]

# 이 예제에서는 순서 변경으로 마지막 상태가 달라진다.
assert not torch.allclose(original[-1], reordered[-1])

# 이유:
# 앞선 시점의 입력 순서가 바뀌면 이전 은닉 상태가 달라지고,
# 그 상태가 다음 시점의 계산에 사용되기 때문이다.
#
# 단, 모든 가중치와 입력에서 순서를 바꾸면 반드시 서로 다른
# 결과가 나온다는 보장은 아니다. 여기서는 실제 차이를 확인한다.


# -------------------------------------------------------------------
# 실험 B: 시점 수를 줄이면?
# -------------------------------------------------------------------

# 처음 3개 시점만 처리한다.
short = run_given_cell(x[0, :3, :])

# 5개 시점 전체를 처리했을 때의 앞 3개 결과와 비교한다.
assert torch.allclose(
    short, original[:3], rtol=1e-10, atol=1e-12
)

# 이유:
# 초기 상태, 앞부분 입력, 가중치가 같기 때문이다.
# 단방향 RNN에서 나중 시점의 입력은 이미 계산한 앞 시점의
# 은닉 상태를 거꾸로 바꾸지 않는다.


# -------------------------------------------------------------------
# 실험 C: 파라미터 객체와 값은 그대로인가?
# -------------------------------------------------------------------

# 객체 식별값 비교
assert ids_before == tuple(id(p) for p in cell.parameters())

# 실제 숫자 값 비교
# zip: 현재 파라미터와 저장한 복사본을 순서대로 짝지음
# torch.equal: shape와 각 원소 값이 같은지 검사
# all: 모든 비교가 True인지 검사
assert all(
    torch.equal(p, before)
    for p, before in zip(cell.parameters(), values_before)
)

print("파라미터 텐서 개수:", len(tuple(cell.parameters())))
print("학습 가능한 숫자 개수:", sum(p.numel() for p in cell.parameters()))

# 출력:
# 파라미터 텐서 개수: 4
# 학습 가능한 숫자 개수: 27


# -------------------------------------------------------------------
# 실험 D: nn.RNN에 전체 시퀀스를 넣어도 같은가?
# -------------------------------------------------------------------

rnn = nn.RNN(
    input_size=F,
    hidden_size=H,
    num_layers=1,          # RNN 층 하나
    nonlinearity="tanh",
    bias=True,
    batch_first=True,     # 입력·output: (B, T, 특징)
    bidirectional=False,  # 정방향만 처리
).double()

with torch.no_grad():
    # 공정하게 비교하기 위해 같은 파라미터 값을 넣는다.
    # _l0는 첫 번째 RNN 층, 즉 층 인덱스 0을 의미한다.
    rnn.weight_ih_l0.copy_(cell.weight_ih)
    rnn.weight_hh_l0.copy_(cell.weight_hh)
    rnn.bias_ih_l0.copy_(cell.bias_ih)
    rnn.bias_hh_l0.copy_(cell.bias_hh)

    # 전체 시퀀스를 한 번에 전달한다.
    # 초기 은닉 상태를 생략했으므로 0에서 시작한다.
    rnn_output, h_n = rnn(x)

# RNNCell을 반복 호출한 결과와 비교한다.
assert torch.allclose(
    rnn_output, output, rtol=1e-10, atol=1e-12
)

# 마지막 시점의 상태 비교
assert torch.allclose(
    h_n[0], output[:, -1, :], rtol=1e-10, atol=1e-12

# 배치로 계산한 첫 번째 시퀀스와
# 그 시퀀스를 따로 계산한 결과도 비교한다.
assert torch.allclose(
    output[0], original, rtol=1e-10, atol=1e-12
)

print("nn.RNN output:", tuple(rnn_output.shape))  # (2, 5, 3)
print("nn.RNN h_n:", tuple(h_n.shape))            # (1, 2, 3)
print("모든 검증을 통과했습니다.")
```

## 16. 실행 결과에서 네 가지를 확인한다

### 첫 시퀀스의 매 시점에 결과 세 개가 남는다

| 시점 | 은닉값 A | 은닉값 B | 은닉값 C |
| ---: | ---: | ---: | ---: |
| 1 | 0.360099 | 0.502765 | 0.866036 |
| 2 | 0.416009 | 0.900527 | 0.510735 |
| 3 | 0.567644 | 0.654344 | 0.940266 |
| 4 | 0.824405 | -0.150259 | 0.956839 |
| 5 | 0.645847 | 0.176484 | 0.997772 |

다섯 시점 모두 A·B·C의 결과가 함께 나온다. 각 행은 첫 번째 시퀀스의 한 시점이고, 배치 전체 출력에는 두 번째 시퀀스의 결과도 따로 들어 있다.

### 입력 순서를 바꾸면 이번 예제의 마지막 상태가 달라진다

`x[0, [2, 0, 1, 3, 4], :]`는 첫 시퀀스의 시점을 인덱스 2, 0, 1, 3, 4 순서로 고른다. 각 시점 안의 특징 순서는 유지한다.

| 시점 인덱스 순서 | 마지막 상태 |
| --- | --- |
| 원래 `[0,1,2,3,4]` | `[0.645847, 0.176484, 0.997772]` |
| 변경 `[2,0,1,3,4]` | `[0.638208, 0.188234, 0.997711]` |

두 실행의 마지막 입력 자체는 같아도 앞부분을 처리하며 만든 은닉 상태가 달라져 마지막 계산에 영향을 준다. 다만 모든 가중치·입력 조합에서 순서 변경이 반드시 다른 결과를 만든다는 보장은 아니다. 이 실습은 실제 차이가 나는 예제를 확인한다.

### 앞 세 시점만 계산하면 전체 실행의 앞 세 결과와 같다

`run_given_cell(x[0, :3, :])`는 처음 세 시점만 처리한다. 이 결과는 다섯 시점을 처리한 결과의 앞 세 시점과 같다. 초기 상태, 앞부분 입력, 가중치가 같기 때문이다. 이번 단방향 RNN에서 나중 입력은 이미 계산된 앞 시점의 상태를 거꾸로 바꾸지 않는다.

`run_given_cell`은 호출할 때마다 내부에서 0 상태를 만든다. 그래서 앞선 함수 호출의 마지막 상태를 이어받지 않는다. 함수 안의 흐름은 <strong>초기 상태 생성 → 입력 하나 선택 → 이전 상태와 계산 → 결과 저장 → 반복 → 모든 결과 반환</strong>이다. 함수 호출 자체와 상태를 이어 쓰는 설계는 별개다.

### 파라미터 객체와 값은 따로 확인한다

| 코드 | 확인하는 것 |
| --- | --- |
| `cell.parameters()` | 모듈에 등록된 파라미터를 순서대로 제공하는 반복자 |
| `id(p)` | Python 객체의 식별값 |
| `p.numel()` | 텐서 안의 숫자 개수 |
| `p.detach().clone()` | 자동 미분 기록과 분리한 별도 데이터 복사본 |
| `torch.equal(p, before)` | shape와 대응하는 값이 같은지 여부 |

`detach()`는 자동 미분 기록과 분리하지만 원래 텐서와 데이터를 공유한다. 뒤의 `clone()`이 별도의 데이터 복사본을 만든다. 따라서 순전파 전의 값을 보관할 수 있다.[^tensor]

객체 식별값이 같아도 객체 내부의 숫자는 바뀔 수 있다. 예제는 객체 식별값과 실제 숫자를 각각 비교한다. `zip`은 현재 파라미터와 저장한 복사본을 순서대로 짝짓고, `all`은 모든 비교 결과가 참인지 검사한다.[^python]

이 실습에서는 매 시점의 `state`가 달라지는 동안 파라미터 27개의 값은 유지된다. 상태가 달라지는 것과 모델이 학습되는 것을 구별할 수 있다.

## 17. MLP·CNN과 비교하면 어느 개수를 봐야 하는가

<strong>MLP</strong>는 완전 연결 층 등을 쌓은 신경망이고, <strong>CNN</strong>은 합성곱으로 공간 범위의 값을 계산하는 신경망이다. 앞서 배운 구조와 비교할 때에는 같은 종류의 개수끼리 비교해야 한다.

| 구조 | 한 출력 계산이 읽는 입력 | 가중치의 구조 | 반복해서 사용하는 범위 |
| --- | --- | --- | --- |
| MLP의 완전 연결 층 | 해당 층의 입력 특징 전체 | 출력 뉴런마다 입력 특징 수만큼 | 여러 데이터에 같은 층 적용 |
| 일반 `Conv2d`, `groups=1` | 모든 입력 채널의 커널 범위 | 필터 하나에 `입력 채널×커널 높이×커널 너비` | 여러 공간 위치와 데이터 |
| 기본 RNN | 현재 입력 전체와 이전 은닉 상태 전체 | 은닉 뉴런마다 `F+H`개 | 여러 시점과 시퀀스 |

CNN의 필터 하나는 공간의 여러 위치에서 같은 가중치를 사용하여 출력 채널 하나를 만든다. 필터 하나가 항상 숫자 하나만 출력한다고 이해하면 안 된다. `groups=1`은 각 필터가 모든 입력 채널을 사용하는 기본 설정이다.[^conv]

MLP의 뒤쪽 층에서 입력 특징 수는 바로 앞 층의 출력 수다. 입력 특징 수와 출력 뉴런 수는 같을 필요가 없다. MLP에도 순서에 관한 정보를 입력으로 줄 수 있지만, 기본 완전 연결 층에는 RNN처럼 이전 시점의 상태를 이어 주는 순환 연결이 없다.[^linear]

RNN에서 입력 특징 수에 대응하는 것은 <strong>각 뉴런의 입력 가중치 수</strong>다. 시간축에 그린 셀 상자의 수는 시점 수에 대응한다. 이 두 대응 관계를 따로 읽어야 한다.

행렬곱의 기본 구조는 [신경망 행렬 계산 글](/neural-network-matrix-basics/)에서, 채널·필터의 연결은 [합성곱 기초 글](/cnn-convolution-basics/)에서 이어서 확인할 수 있다.

## 18. 순전파에서 상태가 바뀌는 것과 학습은 다르다

이번 실습에서 `state`는 입력을 처리할 때마다 새로 계산된다. 가중치와 편향은 바꾸지 않는다. `backward()`와 `optimizer.step()`도 호출하지 않는다.

학습까지 수행하는 일반적인 흐름은 다음과 같다.

1. 새 시퀀스에 사용할 초기 상태를 준비한다.
2. 시점별 순전파로 은닉 상태를 계산한다.
3. 과제에 맞는 출력 계층 등으로 예측값을 만든다.
4. 예측과 정답을 비교해 손실을 계산한다. 손실은 예측이 정답과 얼마나 다른지 나타내는 값이다.
5. 역전파로 각 파라미터의 기울기를 구한다. 기울기는 파라미터를 조금 바꿀 때 손실이 어느 방향으로 얼마나 달라지는지를 나타낸다.
6. 옵티마이저가 기울기를 사용해 가중치와 편향을 갱신한다. 옵티마이저는 파라미터를 수정하는 규칙을 적용하는 객체다.

시간축으로 다음 입력을 처리하는 단계와 파라미터를 갱신하는 단계는 다르다. 한 번의 일반적인 시퀀스 순전파에서는 같은 파라미터를 여러 시점에 사용한다. 학습할 때에는 그 계산에 대한 자동 미분 기록이 필요하므로, 이번 확인용 `no_grad` 블록을 학습용 순전파에 그대로 사용하지 않는다.[^autograd]

이 예제의 초기 상태는 0으로 만든 일반 텐서다. 별도의 학습 파라미터로 등록하지 않았다. 초기 상태 자체를 학습하도록 설계할 수도 있지만, 여기서는 고정된 시작값으로 사용한다.

## 19. 결과가 예상과 다르면 이 지점을 확인한다

| 관찰한 문제 또는 해석 | 원인 | 확인할 부분 |
| --- | --- | --- |
| 셀의 결과를 숫자 하나라고 해석한다. | 반환된 텐서 하나와 그 안의 원소 수를 혼동했다. | 한 시퀀스의 상태는 은닉값 3개다. |
| 현재 B를 계산할 때 새 A를 넣었다. | 이전 상태를 완성 전에 덮어썼다. | 모든 뉴런이 같은 이전 상태를 읽어야 한다. |
| 시점마다 가중치가 새로 생긴다. | 반복문 안에서 셀 객체를 다시 만들었다. | 셀은 반복문 밖에서 만들고 재사용한다. |
| 첫 시점처럼 매번 0에서 계산된다. | 각 호출에 이전 결과를 전달하지 않았다. | `state = cell(xt, state)`의 전달 관계를 확인한다. |
| 입력 shape 오류가 난다. | `F`, `T`, `B`를 혼동했거나 배치 축 사용이 다르다. | 현재 입력 `(2,4)`, 이전 상태 `(2,3)`인지 본다. |
| shape는 맞는데 수동 계산값이 다르다. | 순환 가중치의 전치나 두 편향을 빠뜨렸을 수 있다. | `weight_hh.T`, `bias_ih`, `bias_hh`를 확인한다. |
| `state[0].item()`에서 오류가 난다. | 원소 3개에서 숫자 하나를 꺼내려 했다. | 전체는 `tolist()`, 원소 하나는 인덱싱 후 `item()`을 쓴다. |
| `h_n`을 `(B,L,H)`로 읽었다. | `batch_first`가 상태 축도 바꾼다고 생각했다. | 여기서는 `(L,B,H)=(1,2,3)`이다. |
| 입력을 만들었는데 결과가 달라지지 않는다. | 새 변수가 실제 셀 호출에 사용되지 않았을 수 있다. | `cell(...)`이나 `rnn(...)`에 전달한 변수를 확인한다. |
| 독립적인 시퀀스의 결과가 앞 실행에 따라 달라진다. | 앞 실행의 마지막 상태를 이어 쓰고 있을 수 있다. | 새 시작인지 연속 처리인지 정하고 상태를 준비한다. |

오류를 볼 때에는 먼저 <strong>실제로 전달한 입력·이전 상태의 값과 shape</strong>를 확인한다. 그다음 셀의 인자, 가중치 연결, 상태를 갱신하는 위치를 차례로 확인하면 원인을 좁힐 수 있다.

## 20. 같은 두 시점의 계산을 Rust로 확인한다

Rust에서도 현재 입력에 가중치를 곱한 합, 이전 상태에 가중치를 곱한 합, 편향을 더한 뒤 `tanh`를 적용한다. 아래 코드는 다섯 시점 중 첫 시퀀스의 앞 두 시점만 골라 수치를 검산한다.

Python 예제는 PyTorch의 텐서 연산과 파라미터 관리 기능을 사용했다. 아래 Rust 예제는 표준 배열과 반복문으로 순전파 수치만 계산한다. 자동 미분이나 파라미터 학습 기능은 구현하지 않았다. 이는 이 예제의 범위에 대한 차이이며, Rust라는 언어에서 학습 기능을 사용할 수 없다는 뜻은 아니다.

| 의미 | Python/PyTorch | 아래 Rust 코드 |
| --- | --- | --- |
| 실수 자료형 | `torch.float64` | `f64` |
| 특징 4개 | shape `(4,)`인 텐서 | `[f64; 4]` |
| 뉴런별 입력 가중치 | shape `(3,4)`인 텐서 | `[[f64; 4]; 3]` |
| 이전 상태로 계산 | 행렬곱 | 배열 인덱싱과 반복문 |
| 모든 새 결과를 만든 뒤 교체 | 반환된 텐서를 `state`에 대입 | `next_state`를 만든 뒤 대입 |

`[f64; 4]`는 실수 4개가 들어가는 고정 크기 배열이다. `[[f64; 4]; 3]`은 그런 배열 3개를 담는다. `mut`는 변수에 새 값을 대입할 수 있게 하고, `0..3`은 0부터 시작해 3을 제외한 `0,1,2`를 제공한다. `iter()`는 항목을 참조로 읽고, `enumerate()`는 0부터 시작하는 순서 번호를 함께 제공한다.[^rust]

```rust
// 첫 번째 시퀀스의 앞 두 시점을 표준 Rust로 검산한다.
fn main() {
    // 현재 입력용 가중치: 뉴런 3개 × 특징 4개
    let w_ih: [[f64; 4]; 3] = [
        [ 0.11, -0.07,  0.04,  0.02],
        [-0.09,  0.13,  0.06, -0.03],
        [ 0.05,  0.08, -0.12,  0.15],
    ];

    // 이전 은닉 상태용 가중치: 현재 뉴런 3개 × 이전 은닉값 3개
    let w_hh: [[f64; 3]; 3] = [
        [ 0.21, -0.14,  0.07],
        [-0.16,  0.25,  0.12],
        [ 0.19, -0.06,  0.31],
    ];

    let b_ih = [0.015, -0.025, 0.035];
    let b_hh = [-0.008, 0.018, -0.028];

    // 첫 번째 시퀀스의 앞 두 시점
    let inputs: [[f64; 4]; 2] = [
        [2.0, 5.0, 7.0, 11.0],
        [3.0, 8.0, 12.0, 6.0],
    ];

    // mut: 다음 시점으로 넘어갈 때 새 상태를 대입할 수 있게 한다.
    let mut state = [0.0_f64; 3];

    // iter(): 각 시점의 배열을 참조로 차례대로 읽는다.
    // enumerate(): 0부터 시작하는 순서 번호를 함께 제공한다.
    for (t, xt) in inputs.iter().enumerate() {
        let mut next_state = [0.0_f64; 3];

        // 코드에서는 반복문으로 계산하지만,
        // 뉴런들은 서로의 현재 결과를 입력으로 사용하지 않는다.
        for neuron in 0..3 {
            let mut input_sum = 0.0;
            let mut previous_sum = 0.0;

            for feature in 0..4 {
                input_sum += xt[feature] * w_ih[neuron][feature];
            }

            for previous_neuron in 0..3 {
                previous_sum +=
                    state[previous_neuron] * w_hh[neuron][previous_neuron];
            }

            next_state[neuron] = (
                input_sum
                + previous_sum
                + b_ih[neuron]
                + b_hh[neuron]
            ).tanh();
        }

        // 모든 뉴런이 같은 이전 state를 사용한 뒤,
        // 완성된 새 상태 전체로 교체한다.
        state = next_state;

        // {:?}: 배열 등을 확인하는 디버그 출력 형식
        println!("시점 {}: {:?}", t + 1, state);
    }
}
```

이 Rust 코드는 반복문 때문에 뉴런 A부터 차례대로 계산한다. 그래도 세 뉴런 모두 바뀌지 않은 이전 `state`를 읽고, 결과는 별도 `next_state`에 쓴다. 모든 결과가 완성된 뒤 상태 전체를 교체하므로 RNNCell과 같은 연결을 유지한다.

첫 출력은 `[0.360099…, 0.502765…, 0.866036…]`, 두 번째 출력은 `[0.416009…, 0.900527…, 0.510735…]`다. 현재 입력 4개와 이전 상태 3개로 새 상태 3개를 만들고, 같은 가중치로 다음 시점을 계산하는 과정을 두 언어에서 확인할 수 있다.
