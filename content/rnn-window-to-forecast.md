지난 14일 동안의 방문자 수를 보고 내일의 방문자 수를 예측한다고 하자. 먼저 정해야 할 것은 신경망의 이름이 아니다. **입력 한 건에 어느 날짜의 기록을 넣고, 그 입력의 정답을 어느 날짜의 값으로 정할지**부터 결정해야 한다.

그다음에는 날짜 순서를 처리하는 계산이 필요하다. 순환 신경망(Recurrent Neural Network, RNN)은 현재 입력과 앞선 계산의 결과를 함께 사용해 새 결과를 만든다. 이때 다음 시점으로 전달하는 중간 결과를 <strong>은닉 상태(Hidden State)</strong>라고 한다. 은닉 상태는 입력을 처리하면서 계산되는 값이고, 가중치는 그 값을 계산하는 데 사용하는 학습 대상이다.

이 글은 하나의 예측 문제를 데이터 표, 그림, 배열 구조, 코드로 차례로 살펴본다. 먼저 짧은 기록에서 입력과 정답을 연결하고, 84일 기록으로 같은 작업을 확장한다. 이어서 RNN의 계산, 다음 날 예측, 학습, 미래 날짜 평가까지 실행한다. 본문은 **한 층·단방향·동일한 길이의 입력창**을 사용하는 기본 RNN을 기준으로 한다. 단방향은 입력을 앞에서 뒤로 처리한다는 뜻이다.

[전체 Python 실행 파일](/rnn-window-to-forecast/examples-ko.py), [수동 역전파 검산 파일](/rnn-window-to-forecast/bptt-ko.py), [Rust 비교 예제](/rnn-window-to-forecast/recurrence-ko.rs)를 내려받을 수 있다. 처음 읽을 때는 본문을 따라가고, 더 확인하고 싶은 계산은 뒤의 참고 항목을 펼쳐 보면 된다. API 설명은 2026년 11월 2일의 PyTorch 공식 문서와 대조했다.

## 1. 먼저 전체 작업을 연결한다

<strong>샘플(Sample)</strong>은 모델에 넣는 입력 한 건이다. 여기서는 14일 기록을 묶은 입력창 하나가 샘플 하나다. <strong>배치(Batch)</strong>는 여러 샘플을 한 번에 처리하려고 묶은 것이며, `B`는 이번 호출에서 처리할 샘플 수다.

그림에서 `RNN`은 시점마다 은닉값 네 개를 계산한다. `Linear`는 마지막 은닉값 네 개로 다음 날 예측값 하나를 만드는 층이다. <strong>손실(Loss)</strong>은 예측과 정답의 차이를 측정한 숫자이고, <strong>기울기(Gradient)</strong>는 특정 값의 작은 변화에 손실이 얼마나 반응하는지를 나타낸다. <strong>옵티마이저(Optimizer)</strong>는 계산된 기울기를 이용해 학습 대상 숫자를 수정한다.

신경망을 볼 때에는 아래 다섯 대상을 구분하면 된다.

| 확인할 대상 | 이번 모델에서의 역할 |
| --- | --- |
| 입력(Input) | 샘플마다 지난 14일의 방문자 수를 순서대로 넣는다. |
| 뉴런·구조(Neuron, Structure) | RNN의 은닉 뉴런 네 개가 매 시점 계산하고, 마지막에 Linear가 예측한다. |
| 중간값(Intermediate Value) | 시점마다 새로 계산한 은닉값 네 개를 다음 계산에 사용한다. |
| 가중치(Weight) | RNN과 Linear가 각자 보관하며 학습으로 수정하는 숫자다. |
| 최종 출력(Output) | 입력창 하나에 다음 날 방문자 수 예측 하나가 대응한다. |

방문 기록을 평균 하나로 바꾸면 순서 정보가 사라진다. 예를 들어 `10 → 20 → 30`과 `30 → 20 → 10`의 평균은 같지만 마지막 값과 처음에서 끝으로의 변화는 다르다. RNN에서는 앞서 계산한 상태가 다음 계산에 들어가므로 순서에 따라 결과가 달라질 수 있다. 모든 가중치 설정에서 반드시 다른 결과가 나온다는 뜻은 아니다.

## 2. 입력창 하나와 정답 하나를 정확하게 짝짓는다

처음에는 7일 기록만 보자. 방문자 수를 `10, 20, 30, 40, 50, 60, 70`으로 정했다. 이 숫자들은 위치를 쉽게 확인하기 위한 예제다. 목표는 **앞선 3일로 바로 다음 날을 예측하는 것**이다.

<strong>인덱스(Index)</strong>는 값을 선택하는 위치 번호다. Python에서는 0부터 시작하므로 첫째 날의 인덱스는 0이고, 일곱째 날의 인덱스는 6이다. 전체 기록의 <strong>길이(Length)</strong>는 7이다. 길이와 마지막 인덱스는 서로 다르다.

| 샘플 번호 | 입력 인덱스 | 입력값 | 정답 인덱스 | 정답 |
| ---: | --- | --- | ---: | ---: |
| 0 | 0, 1, 2 | `[10, 20, 30]` | 3 | 40 |
| 1 | 1, 2, 3 | `[20, 30, 40]` | 4 | 50 |
| 2 | 2, 3, 4 | `[30, 40, 50]` | 5 | 60 |
| 3 | 3, 4, 5 | `[40, 50, 60]` | 6 | 70 |

<img src="/rnn-window-to-forecast/windows-ko.svg" alt="7일 기록에서 3일 입력창을 한 칸씩 이동한다. 입력창 네 개 각각에 바로 다음 인덱스의 정답이 대응한다." loading="lazy">
<figcaption>입력의 마지막 값과 정답은 서로 다른 날짜다. 처음 세 날짜도 이후 날짜를 예측하는 입력으로 사용한다.</figcaption>
</figure>

`[50, 60, 70]`이라는 입력창도 만들 수는 있다. 그러나 그다음 날짜의 기록이 없으므로 학습용 정답을 붙일 수 없다. 그래서 **정답까지 있는 샘플은 네 개**다. 이 관계를 확인한 뒤에 개수 식을 쓸 수 있다.

`정답이 있는 창의 개수 = 전체 기록 길이 − 입력창 길이`

이 식은 창을 한 칸씩 이동하고, 바로 다음 값 하나를 정답으로 삼는 경우에 적용한다. 여러 날을 한꺼번에 예측하거나 창의 이동 간격을 바꾸면 개수도 달라진다.

Python의 `range(4)`는 `0, 1, 2, 3`을 제공한다. 슬라이싱(Slicing)인 `data[0:3]`도 끝 경계 3을 제외하고 인덱스 0, 1, 2를 선택한다. 따라서 창의 시작을 `i`라고 하면 입력은 `data[i:i+3]`, 정답은 `data[i+3]`이다.[^python-sequence]

```python
data = [10, 20, 30, 40, 50, 60, 70]
seq_len = 3  # 입력에 사용할 날짜 수.

for i in range(len(data) - seq_len):  # range(4): 시작 번호 0~3.
    window = data[i:i + seq_len]     # 시작 포함, 끝 제외.
    target = data[i + seq_len]       # 입력 바로 다음 위치 하나.
    print(window, "->", target)

# [10, 20, 30] -> 40
# [20, 30, 40] -> 50
# [30, 40, 50] -> 60
# [40, 50, 60] -> 70
```

### 같은 작업을 84일 기록으로 확장한다

실습에서는 일주일의 가상 방문 패턴을 12번 반복하고 작은 무작위 변동을 더한다. 실제 매장에서 수집한 자료는 아니다. 방문자 수를 100으로 나누는 것은 계산에 쓰는 숫자 크기를 줄이기 위한 선택이다. 확률로 바꾸는 작업이 아니므로 값이 1보다 클 수도 있다.

```python
import torch
from torch import nn  # torch.nn에 있는 신경망 클래스를 nn으로 사용한다.

torch.manual_seed(1)  # 이번 데이터의 난수 생성 시작 설정.
weekly = torch.tensor(
    [62, 55, 58, 60, 75, 118, 105],
    dtype=torch.float32,  # 32비트 실수로 저장한다.
)
value_scale = 100.0  # 예측값에 다시 곱하면 원래 방문자 단위로 돌아간다.
repeated = weekly.repeat(12)  # 일주일 묶음 전체를 반복: (7,) -> (84,).
noise = torch.randn(len(repeated)) * 3.0  # 가상 일별 변동.
visitors = (repeated + noise) / value_scale  # shape (84,).
```

<strong>텐서(Tensor)</strong>는 숫자와 숫자의 배열 구조를 함께 관리하는 PyTorch 자료형이다. **shape**는 각 축의 크기를 순서대로 나타낸다. `visitors`의 shape `(84,)`는 축이 하나이고 그 축에 값이 84개 있다는 뜻이다.

이제 입력창 길이를 14로 정한다. 처음 14일은 앞선 14일 기록을 갖지 않으므로 정답 날짜가 될 수 없다. 15일째부터 84일째까지는 앞선 기록이 있으므로, 정답이 있는 입력창은 70개다.

| 샘플 번호 | 입력 날짜 | Python 입력 선택 | 정답 |
| ---: | --- | --- | --- |
| 0 | 1~14일째 | `visitors[0:14]` | `visitors[14]`, 15일째 |
| 1 | 2~15일째 | `visitors[1:15]` | `visitors[15]`, 16일째 |
| 69 | 70~83일째 | `visitors[69:83]` | `visitors[83]`, 84일째 |

아래 함수는 이 선택을 반복한다. 함수의 <strong>인자(Argument)</strong>에는 실제 기록 텐서와 창 길이를 전달하고, <strong>반환값(Return Value)</strong>으로 입력 `X`와 정답 `y`를 받는다. `append()`는 리스트 끝에 항목을 추가한다.

```python
def make_windows(values, seq_len):
    windows = []
    for i in range(len(values) - seq_len):
        windows.append(values[i:i + seq_len])  # 각각 (14,)인 텐서.

    # stack은 같은 크기의 텐서를 새 축으로 묶는다.
    X_2d = torch.stack(windows, dim=0)  # 70개 묶음 -> (70,14).
    # unsqueeze는 숫자 개수를 유지하며 크기 1인 축을 추가한다.
    X = X_2d.unsqueeze(-1)  # 마지막에 특징 축 추가 -> (70,14,1).
    y = values[seq_len:].unsqueeze(-1)  # 다음 날 값들 -> (70,1).
    return X, y

seq_len = 14
X, y = make_windows(visitors, seq_len)
print(tuple(X.shape), tuple(y.shape))  # (70,14,1) (70,1)
```

`visitors[14:]`는 인덱스 14부터 끝까지 선택한다. 마지막 인덱스가 83이므로 `visitors[14:84]`와 같다. 끝을 생략했기 때문에 별도로 `+1`을 붙일 필요가 없다.

`unsqueeze(-1)`은 하루의 방문자 수를 `[방문자 수]`처럼 특징 목록에 넣는 구조 변경이다. 관측값을 추가하지 않는다. 정답도 샘플마다 예측 숫자 하나와 비교하도록 `(70,1)`로 준비했다.[^stack][^unsqueeze]

## 3. 샘플 수, 시점 수, 특징 수를 서로 다른 축으로 읽는다

<strong>시퀀스(Sequence)</strong>는 순서가 있는 데이터 묶음이다. 이번에는 입력창 하나가 시퀀스 하나이자 샘플 하나다. <strong>시점(Time Step)</strong>은 그 시퀀스 안의 순서 위치이고, <strong>특징(Feature)</strong>은 한 시점에 관측하는 정보의 종류다.

| 기호 | 뜻 | 이번 예제 |
| --- | --- | --- |
| `N` | 만들어 둔 전체 샘플 수 | 입력창 70개 |
| `B` | 이번 모델 호출에 넣는 샘플 수 | 설명용으로 두 창을 고르면 2 |
| `T` | 샘플 하나의 시점 수 | 창마다 14일 |
| `F` | 시점 하나의 입력 특징 수 | 방문자 수 한 종류 |
| `H` | 시점마다 계산하는 은닉값 수 | 개발자가 선택한 4개 |

`F=1`은 방문자 수만 입력하기 때문에 나온다. RNN의 입력이 항상 숫자 하나라는 뜻은 아니다. 방문자 수·기온·강수량·광고비를 함께 입력한다면 `F=4`가 된다. 이때도 14일을 관측했다면 `T=14`는 그대로다. 은닉값 수 `H`는 특징 수나 날짜 수에서 자동으로 정해지지 않는다.

전체 `X`의 shape는 `(N,T,F)=(70,14,1)`이다. 여기에서 앞의 두 창만 고른 `xb = X[:2]`는 `(B,T,F)=(2,14,1)`이다. **전체 데이터셋의 크기와 현재 배치의 크기는 서로 다른 정보다.**

| `xb`의 축 번호 | 의미 | 축 크기 | 유효 인덱스 |
| ---: | --- | ---: | --- |
| `dim=0` | 어느 샘플인가? | 2 | 0, 1 |
| `dim=1` | 그 샘플의 어느 시점인가? | 14 | 0~13 |
| `dim=2` | 그 시점의 어느 특징인가? | 1 | 0 |

축 번호 1, 축 크기 14, 마지막 인덱스 13을 구분하자. 이 텐서는 축이 세 개이므로 **3차원 텐서**다. 70개 샘플이 있다는 이유로 70차원이 되는 것은 아니다.

```python
xb = X[:2]  # 앞의 두 입력창을 배치로 선택한다.
print(tuple(xb.shape), xb.ndim, xb.numel())
# (2,14,1) 3 28
# shape: 축별 크기 / ndim: 축 개수 / numel(): 전체 숫자 개수.
```

인덱싱(Indexing)은 새로운 예측을 계산하는 작업이 아니다. 이미 있는 값 중에서 필요한 부분을 선택한다.

| 선택식 | 선택한 내용 | 결과 shape |
| --- | --- | --- |
| `xb[0]` | 첫 샘플의 14일 | `(14,1)` |
| `xb[:1]` | 첫 샘플을 배치 축까지 유지해 선택 | `(1,14,1)` |
| `xb[:, 0, :]` | 두 샘플 각각의 첫 시점 | `(2,1)` |
| `xb[:, -1, :]` | 두 샘플 각각의 마지막 입력 시점 | `(2,1)` |
| `xb[:, -1:, :]` | 같은 마지막 시점을 시간 축까지 유지해 선택 | `(2,1,1)` |

`:`는 그 축 전체를 뜻한다. 정수 하나로 선택한 축은 결과에서 제외되고, 슬라이싱으로 선택한 축은 유지된다. 따라서 `xb[0]`을 이 글의 모델에 다시 넣으려면 `unsqueeze(0)`으로 배치 축을 붙이거나, 처음부터 `xb[:1]`로 선택하면 된다.

## 4. RNN은 현재 입력과 이전 상태를 함께 계산한다

<strong>가중치(Weight)</strong>는 입력에 곱하는 학습 대상 숫자이고, <strong>편향(Bias)</strong>은 곱셈 결과를 더한 값에 추가하는 학습 대상 숫자다. 둘을 통틀어 <strong>매개변수(Parameter)</strong>라고 한다. <strong>뉴런(Neuron)</strong>은 연결된 값들의 가중합을 계산하고 활성화 함수를 적용해 결과 하나를 만든다.

<strong>가중합(Weighted Sum)</strong>은 각각의 값에 대응하는 가중치를 곱한 뒤 모두 더한 값이다. <strong>활성화 함수(Activation Function)</strong>는 그 합을 다음 결과로 바꾸는 함수다. 여기서는 쌍곡탄젠트 `tanh`를 사용한다. `tanh`는 각 숫자에 독립적으로 적용되며 결과가 −1과 1 사이에 놓인다. 삼각함수 `tan`과는 다른 함수다.[^tanh]

RNN 셀(Cell)은 한 시점의 은닉 상태 전체를 계산하는 단위다. 이번 셀에는 은닉 뉴런이 네 개 있다. 각 뉴런은 **현재 입력 전체와 이전 은닉값 네 개 전체**를 읽고 자기 가중치로 결과 하나를 만든다. 네 결과를 합쳐 숫자 하나로 줄이지 않고, 네 값을 유지한 채 새 은닉 상태로 사용한다.

표기의 기준도 고정하자. 본문에서 `t`는 코드와 같은 0부터 시작하는 시점 인덱스다. `h_init`은 첫 입력을 처리하기 전의 초기 상태이고, `h_0`은 인덱스 0의 입력을 처리한 상태다. 마지막 입력 인덱스는 13이고 마지막 상태는 `h_13`이다.

| 처리 단계 | 현재 입력 | 이전에 준비된 상태 | 새로 계산할 상태 |
| --- | --- | --- | --- |
| 첫 시점 `t=0` | 각 샘플의 첫 날짜 | `h_init`, 샘플마다 0 네 개 | `h_0`, 샘플마다 은닉값 네 개 |
| 둘째 시점 `t=1` | 각 샘플의 둘째 날짜 | 방금 계산한 `h_0` | `h_1` |
| 마지막 시점 `t=13` | 각 샘플의 열넷째 날짜 | 앞서 계산한 `h_12` | `h_13` |

<figcaption>시간 순서는 각 샘플 내부에서 이어진다. 여러 시점에 그린 셀은 같은 RNN 층의 반복 계산이며, 서로 다른 층을 뜻하지 않는다.</figcaption>
</figure>

첫 번째 창은 원본 인덱스 0에서 시작하고, 두 번째 창은 인덱스 1에서 시작한다. 따라서 두 샘플의 `t=0`은 서로 다른 원본 날짜다. 배치에서 “같은 시점”을 골랐다는 말은 **각 입력창 안에서 같은 순번**을 골랐다는 뜻이다.

두 샘플의 상태는 `(B,H)=(2,4)`에 저장된다. 샘플 0의 네 값은 다음 시점의 샘플 0 계산에, 샘플 1의 네 값은 샘플 1 계산에 쓰인다. 두 샘플의 은닉 상태를 합치거나 서로 전달하지 않는다. 원본 날짜가 겹치는 두 입력창도 이 모델에서는 별도의 샘플로 처리한다.

### 은닉 상태는 새로 계산하고, 가중치는 재사용한다

| 구분 | 은닉 상태 | 가중치·편향 |
| --- | --- | --- |
| 정체 | 입력과 이전 상태에서 계산한 중간 결과 | 모델 객체가 보관하는 학습 대상 |
| 한 시점을 처리하면 | 새 상태가 계산된다. | 현재 값을 그대로 사용한다. |
| 다음 시점에서는 | 앞 시점에서 얻은 상태를 입력으로 사용한다. | 같은 파라미터를 다시 사용한다. |
| 일반적인 학습에서 바뀌는 지점 | 셀의 순전파 계산 | `optimizer.step()` |

<strong>가중치 공유(Weight Sharing)</strong>는 시점마다 별도의 가중치를 만들고 같은 값으로 맞춘다는 뜻이 아니다. 저장된 같은 파라미터를 여러 시점의 계산에서 반복해 사용한다는 뜻이다.

현재 입력용 가중치를 `W_ih`, 이전 은닉 상태용 가중치를 `W_hh`라고 쓰자. `i`는 input, `h`는 hidden을 가리킨다. PyTorch는 다음 구조로 값을 저장한다.[^rnncell]

| 파라미터 | shape | 이번 개수와 이유 |
| --- | --- | --- |
| `weight_ih` | `(H,F)=(4,1)` | 뉴런 네 개가 입력 특징 하나씩 사용하므로 4개 |
| `weight_hh` | `(H,H)=(4,4)` | 현재 뉴런 네 개가 이전 은닉값 네 개씩 사용하므로 16개 |
| `bias_ih`, `bias_hh` | 각각 `(H,)=(4,)` | PyTorch가 두 편향 묶음을 보관하므로 8개 |

RNN의 학습 숫자는 `4+16+8=28`개다. 14일을 28일로 늘려도 같은 구조의 RNN 파라미터는 28개다. 처리할 시점과 계산량, 저장할 중간값은 늘어난다. **파라미터 개수와 실제 연산량을 같은 숫자로 세면 안 된다.**

<details>
<summary>현재 입력과 이전 상태가 더해지는 계산을 식으로 확인하기</summary>

`x_t`는 현재 입력 `(B,F)`, `h_prev`는 이전 상태 `(B,H)`, `a_t`는 활성화 전 가중합 `(B,H)`다. `h_t`는 새 상태 `(B,H)`다. 다음은 셀 내부의 계산을 직접 표현한 것이다.

```python
# @는 행렬곱, .T는 여기서 2차원 가중치의 두 축을 바꾸는 연산이다.
a_t = (
    x_t @ cell.weight_ih.T       # (B,F) @ (F,H) -> (B,H).
    + h_prev @ cell.weight_hh.T  # (B,H) @ (H,H) -> (B,H).
    + cell.bias_ih              # 뉴런별 입력 편향.
    + cell.bias_hh              # 뉴런별 상태 편향.
)
h_t = torch.tanh(a_t)  # 각 가중합을 은닉값으로 바꾼다.
```

`W_ih[j,k]`는 입력 특징 `k`에서 현재 뉴런 `j`로 연결되는 가중치다. `W_hh[j,q]`는 이전 은닉값 `q`에서 현재 뉴런 `j`로 연결되는 가중치다. 첫 인덱스는 현재 뉴런, 둘째 인덱스는 그 뉴런이 읽는 값의 위치다.

입력 특징 네 개와 은닉 뉴런 세 개라면 한 뉴런에 입력용 가중치 네 개, 상태용 가중치 세 개가 있다. 전체 파라미터는 `3×4 + 3×3 + 2×3 = 27`개다. 앞의 방문자 모델과 구조 원리는 같고 `F`, `H`만 다르다. [다변량 RNN의 연결 그림](@/rnn-sequence-hidden-state.md)에서 이 경우를 더 자세히 볼 수 있다.

두 편향을 더해 순전파에서 하나의 유효 편향으로 표현할 수는 있다. 실제 PyTorch 객체는 두 개의 별도 파라미터로 관리하므로, 편향 하나인 다른 구현과 학습 과정까지 같다고 단정하지 않는다.

</details>

## 5. 한 시점을 처리하는 RNNCell과 전체를 받는 RNN

클래스(Class)는 객체의 구조와 동작을 정의한다. `nn.RNNCell(...)`은 그 클래스로 **모델 객체를 만드는 호출**이다. 만들어진 객체를 `cell(x_t, state)`처럼 호출하면 실제 데이터로 계산한다. 이 두 호출의 인자는 역할이 다르다.

| 단계 | 코드 | 전달하는 것 |
| --- | --- | --- |
| 객체 생성 | `nn.RNNCell(input_size=1, hidden_size=4)` | 입력 특징 수와 은닉값 수 |
| 데이터 계산 | `cell(x_t, state)` | 현재 입력 텐서와 이전 상태 텐서 |

가중치를 `cell()`의 인자로 넣지 않는 이유는 셀 객체가 내부에 가중치를 보관하기 때문이다. `state`는 가중치가 아니라 이전 계산 결과다.

```python
cell = nn.RNNCell(input_size=1, hidden_size=4)
xb = X[:2]  # (B=2,T=14,F=1).
state = xb.new_zeros(xb.shape[0], cell.hidden_size)
# new_zeros: xb와 같은 자료형·장치에서 0 생성. 초기 상태는 (2,4).

states = []
for t in range(xb.shape[1]):  # 0~13: 샘플이 아니라 시점을 순회한다.
    x_t = xb[:, t, :]        # 두 샘플의 현재 입력, (2,1).
    next_state = cell(x_t, state)  # (2,1)과 (2,4) -> (2,4).
    states.append(next_state)
    state = next_state      # 다음 반복에서 사용할 상태를 바꾼다.

cell_output = torch.stack(states, dim=1)  # 모든 시점 상태, (2,14,4).
```

`state = cell(x_t, state)`라고 줄여 써도 같다. 먼저 오른쪽의 기존 `state`로 새 결과를 계산하고, 그 결과를 왼쪽 이름 `state`에 연결한다. 자기 자신을 다시 부르는 재귀 호출이 아니다. 가중치를 수정하는 코드도 아니다.

`h_1`을 완성하려면 `h_0`이 필요하다. 이 의존성 때문에 상태 계산은 시간 순서를 따른다. 다만 입력에 가중치를 곱하는 부분처럼 이전 상태에 의존하지 않는 연산은 미리 처리할 수 있다. “모든 연산이 하드웨어에서 하나씩만 실행된다”는 의미로 이해할 필요는 없다.

### unbind는 어떤 축을 순회할지 지정한다

`xb.unbind(dim=1)`은 시간 축에서 항목을 하나씩 선택한 텐서들의 튜플을 반환한다. 선택한 시간 축은 각 결과에서 제외된다. 따라서 위 반복문은 다음과 같이 쓸 수 있다.[^unbind]

```python
state = xb.new_zeros(xb.shape[0], cell.hidden_size)
for x_t in xb.unbind(dim=1):  # 14개 텐서, 각각 (2,1).
    state = cell(x_t, state)  # 두 샘플 각각의 상태를 갱신한다.
```

원본 기록의 `visitors[k]`를 `v_k`라고 적으면, 첫 반복의 입력은 `[[v_0],[v_1]]`, 둘째 반복은 `[[v_1],[v_2]]`다. 각 창 안의 시점이 한 칸 진행한 것이다. 반면 `for row in xb`는 맨 앞의 샘플 축을 순회하므로 `(14,1)`인 창을 두 번 꺼낸다.

### RNN은 시간 반복을 내부에서 수행한다

```python
rnn = nn.RNN(
    input_size=1,       # 한 시점의 입력 특징 수.
    hidden_size=4,      # 한 시점의 은닉값 수.
    num_layers=1,       # RNN 층 수.
    nonlinearity="tanh",  # 가중합에 적용할 활성화 함수.
    batch_first=True,  # 입력·output의 축 순서를 (B,T,특징)으로 정한다.
)
output, h_n = rnn(xb)  # 전체 14일을 한 번의 호출로 전달한다.
```

`rnn(xb)`를 한 번 호출해도 내부에서는 14개 시점의 상태를 계산한다. 초기 상태를 생략하면 0에서 시작한다. 앞선 호출의 마지막 상태를 다음 호출에 자동으로 이어 붙이지 않는다.[^rnn]

위에서 따로 생성한 `cell`과 `rnn`은 가중치도 따로 초기화되었다. 따라서 구조와 shape가 같다는 이유만으로 실제 출력 숫자까지 같지는 않다. 내려받는 실행 파일에서는 가중치와 편향을 동일하게 복사한 뒤 두 계산 결과가 허용 오차 안에서 같은지 검사한다.

## 6. 모든 상태에서 마지막 상태를 고르고, 예측을 계산한다

먼저 RNN이 반환하는 두 텐서를 구분하자. 본문의 단층·단방향 설정에서는 다음과 같다.

| 반환값 | 저장한 내용 | 두 샘플을 넣었을 때 shape |
| --- | --- | --- |
| `output` | 마지막 RNN 층의 모든 시점 은닉 상태 | `(2,14,4)` |
| `h_n` | 각 층·방향의 마지막 은닉 상태 | `(1,2,4)` |

`h_n`의 첫 번째 1은 샘플 수가 아니다. 층·방향 묶음이 하나라는 뜻이다. 그 뒤의 2가 샘플 수다. `batch_first=True`는 입력과 `output`에 적용되고, `h_n`의 축 순서는 바꾸지 않는다.

<figure class="rnn-guide-figure">
<img src="/rnn-window-to-forecast/outputs-ko.svg" alt="output (2,14,4)에서 두 샘플의 마지막 시점 은닉값 네 개를 모두 선택하면 (2,4)가 된다. h_n (1,2,4)에서 h_n[0]을 선택해도 같은 상태다. Linear는 이 상태로 샘플당 예측 하나를 계산한다." loading="lazy">
<figcaption>마지막 시점 선택은 이미 계산된 값을 고르는 작업이다. Linear는 선택한 값들로 새로운 예측 숫자를 계산한다.</figcaption>
</figure>

`output[:, -1, :]`를 왼쪽부터 읽으면 **모든 샘플에서, 마지막 시점의, 은닉값 전부를 선택한다**는 뜻이다. 마지막 뉴런 한 개를 고르는 코드가 아니다. 시간 축만 사라지고 샘플마다 네 값은 그대로 남는다.

```python
last = output[:, -1, :]  # (2,14,4) -> (2,4).
last_from_hn = h_n[0]    # (1,2,4) -> (2,4).
assert torch.allclose(last, last_from_hn)
# allclose는 대응 원소들이 허용 오차 안에서 같은지 bool로 반환한다.
```

`h_n[0]`의 0은 층·방향 묶음을 고른다. 샘플 0만 고르는 것이 아니다. `output` 전체와 `h_n` 전체는 저장 범위가 다르지만, 위와 같이 선택한 마지막 상태는 같다.

이 상태의 숫자 네 개는 아직 방문자 수 예측이 아니다. <strong>예측층(Prediction Head)</strong>으로 사용할 `nn.Linear(4,1)`이 네 은닉값을 입력으로 받아 예측값 하나를 만든다. `Linear`는 마지막 축을 변환하면서 앞의 축을 유지한다.[^linear]

| 전달할 텐서 | Linear에 넣은 결과 | 의미 |
| --- | --- | --- |
| 마지막 상태 `(B,4)` | `(B,1)` | 샘플마다 다음 날 예측 하나 |
| 모든 상태 `(B,14,4)` | `(B,14,1)` | 시점마다 예측 하나씩 |

이번 목표는 입력창 하나로 다음 날 하나를 예측하는 것이므로 첫 번째를 사용한다. 은닉 크기 4는 예시로 선택한 구조 설정이며 날짜 수 14에서 계산해 낸 값이 아니다.

### 모델을 만드는 코드와 실제 계산 코드를 나눈다

`nn.Module`은 PyTorch 모델을 정의할 때 사용하는 기본 클래스다. `__init__`는 모델을 만들 때 실행되어 내부 층을 준비한다. `forward`는 만들어진 모델에 입력을 넣었을 때 수행할 계산이다.

```python
class VisitorRNN(nn.Module):
    def __init__(self, hidden_size=4):
        super().__init__()  # nn.Module의 초기화를 실행한다.
        self.rnn = nn.RNN(
            input_size=1,
            hidden_size=hidden_size,
            batch_first=True,
        )
        self.head = nn.Linear(
            in_features=hidden_size,  # 전달받을 마지막 은닉값 개수.
            out_features=1,          # 샘플마다 다음 날 값 하나.
        )

    def forward(self, x):
        output, _ = self.rnn(x)  # (B,14,1) -> (B,14,4).
        # _는 여기서 사용하지 않는 h_n을 받는 관례적 이름이다.
        last = output[:, -1, :]  # (B,4): 값 선택.
        prediction = self.head(last)  # (B,1): 새 값 계산.
        return prediction

model = VisitorRNN(hidden_size=4)  # 구조와 파라미터 준비.
prediction = model(X[:2])          # 실제 데이터로 forward 수행.
print(tuple(prediction.shape))     # (2,1).
```

`model.rnn(X)`는 내부 RNN만 실행하고 두 텐서를 반환한다. `model(X)`는 `forward`에 쓴 RNN·마지막 시점 선택·Linear를 모두 실행하고 예측 텐서 하나를 반환한다. 두 호출을 연달아 실행하면 RNN을 두 번 계산한다. 앞에서 계산한 `output`을 재사용하려면 `model.head(output[:, -1, :])`라고 명시해야 한다.

이 모델은 RNN 파라미터 28개와 Linear의 가중치 네 개·편향 한 개를 합쳐 **학습 숫자 33개**를 가진다. 입력창 70개나 시점 14개가 각각 별도의 모델 가중치를 갖는 구조가 아니다.

## 7. 예측, 손실, 기울기, 가중치 갱신을 구분한다

예측과 정답을 비교할 때에는 같은 샘플끼리 대응시켜야 한다. 이번에는 각 샘플에 예측값과 정답이 하나씩 있으므로 둘 다 `(B,1)`로 맞춘다.

<strong>오차(Error)</strong>는 예측값에서 정답을 뺀 값이다. 오차를 제곱하면 <strong>제곱오차(Squared Error)</strong>가 된다. 모든 제곱오차를 더하면 제곱오차합이고, 그 평균을 구하면 <strong>평균제곱오차(Mean Squared Error, MSE)</strong>다. 손실이 반드시 평균이어야 하는 것은 아니다. 이 글이 평균을 사용하는 이유는 MSE를 선택했기 때문이다.

```python
xb, yb = X[:2], y[:2]  # 같은 두 샘플의 입력과 정답.
prediction = model(xb)  # (2,1).
assert prediction.shape == yb.shape  # 대응 관계를 확인한다.

errors = prediction - yb         # 샘플별 오차, (2,1).
squared_errors = errors.square() # 원소별 제곱, (2,1).
loss = squared_errors.mean()    # 전체 원소 평균, shape ().

loss_fn = nn.MSELoss()          # 기본 reduction='mean'.
same_loss = loss_fn(prediction, yb)  # 위와 같은 MSE 계산.
```

shape `()`는 숫자 하나를 담은 0차원 텐서다. Python의 `float`로 바뀐 것은 아니다. 텐서인 손실은 자신을 만든 연산과 연결되어 있으므로 역전파의 시작점이 될 수 있다. 기본 `MSELoss`는 모든 출력 원소에 대해 평균을 구한다. 이번에는 샘플당 출력이 하나여서 평균의 원소 수가 `B`와 같다.[^mse]

여기서 `prediction`을 `(B,1)`, 정답을 `(B,)`로 두고 그대로 빼면 의도하지 않은 `(B,B)` 비교가 생길 수 있다. 이는 크기를 자동으로 맞추는 **브로드캐스팅(Broadcasting)** 규칙 때문이다. 둘을 `(B,1)`로 유지하거나 둘 다 `(B,)`로 맞추면 된다.[^broadcast]

### 한 번의 학습은 다섯 단계로 구분한다

<strong>순전파(Forward Pass)</strong>는 입력에서 예측까지 값을 계산하는 과정이다. <strong>역전파(Backpropagation)</strong>는 그 계산 연결을 따라 손실의 기울기를 구하는 과정이다. 일반적인 학습 한 스텝은 다음과 같다.[^optimization]

```python
optimizer = torch.optim.Adam(
    model.parameters(),  # RNN과 Linear의 학습 파라미터 모두 등록.
    lr=0.01,             # 학습률. 이 예제에서 선택한 설정값이다.
)

optimizer.zero_grad(set_to_none=True)  # 1. 이전 기울기 저장값 비우기.
prediction = model(xb)                # 2. 현재 가중치로 예측 계산.
loss = loss_fn(prediction, yb)        # 3. 예측과 정답으로 손실 계산.
loss.backward()                      # 4. 파라미터별 손실 기울기 계산.
optimizer.step()                     # 5. 기울기를 사용해 파라미터 갱신.
```

`zero_grad()`는 은닉 상태나 가중치를 0으로 만드는 함수가 아니다. 파라미터에 남아 있는 이전 기울기를 비운다. `set_to_none=True`는 그 저장값을 0 배열 대신 `None`으로 비우겠다는 뜻이다. 다음 `backward()`가 필요한 기울기를 다시 만든다.[^zero-grad]

`loss.backward()`는 각 파라미터의 `.grad`에 기울기를 저장한다. 이 예제의 순환 가중치가 `(4,4)`라면 그 기울기도 `(4,4)`다. 각 가중치 숫자에 대응하는 기울기 숫자가 하나씩 필요하기 때문이다. 가중치 33개를 학습하는 이 모델에는 전체적으로 33개 스칼라 파라미터에 대한 기울기가 대응한다. 이 숫자가 실제 미분 계산을 33번만 한다는 뜻은 아니다.

`optimizer.step()`은 준비된 기울기로 파라미터를 수정한다. 이때부터 다음 순전파에 사용하는 가중치가 달라진다. `step()` 전에 계산한 `loss`를 출력하면 그 값은 **갱신 전 예측의 손실**이다. 가중치를 갱신했다고 이미 계산해 둔 손실 숫자까지 자동으로 바뀌지는 않는다.

가장 단순한 경사하강법인 SGD의 기본 갱신은 `새 가중치 = 현재 가중치 − 학습률 × 해당 가중치의 기울기`다. 가중치 자체에 학습률을 곱해 빼는 규칙이 아니다. 기울기는 현재 위치 주변의 손실 변화율이며, 최적 가중치나 최적 이동 거리를 직접 알려주는 값은 아니다. 위에서 선택한 Adam은 과거 기울기 정보도 이용하므로 단순 SGD 식과 같은 알고리즘으로 설명해서는 안 된다.[^sgd][^adam]

## 8. 마지막 손실이 왜 앞 시점의 가중치까지 학습시키는가

마지막 상태는 바로 앞 상태를 이용해 만들었다. 그 앞 상태도 더 앞의 상태를 이용해 만들었다. 따라서 마지막 예측의 손실에는 앞선 시점에서 수행한 계산들이 연결되어 있다. 이 연결을 시간 역순으로 따라 기울기를 계산하는 과정을 <strong>시간 역전파(Backpropagation Through Time, BPTT)</strong>라고 한다.

먼저 “기울기”가 어떤 두 값 사이의 관계인지 구별하자. 한 샘플의 은닉 뉴런 하나를 기준으로 `a`는 활성화 전 가중합, `h`는 `tanh(a)`의 결과, `L`은 최종 손실이다.

| 구하는 기울기 | 정확히 묻는 것 |
| --- | --- |
| `h`의 `a`에 대한 기울기 | 가중합 `a`를 조금 바꾸면 은닉값 `h`가 얼마나 변하는가? |
| `L`의 `h`에 대한 기울기 | 은닉값 `h`를 조금 바꾸면 최종 손실 `L`이 얼마나 변하는가? |
| `L`의 `a`에 대한 기울기 | 가중합 `a`를 조금 바꾸면 최종 손실 `L`이 얼마나 변하는가? |

첫 번째만 알아서는 세 번째를 알 수 없다. **`a`의 변화가 `h`를 얼마나 바꾸는지와, 바뀐 `h`가 손실을 얼마나 바꾸는지를 함께 연결해야 한다.** 이 두 변화율을 곱하는 규칙을 연쇄법칙(Chain Rule)이라고 한다. 작은 변화량을 연결하는 계산은 뒤의 참고에서 확인한다.

<img src="/rnn-window-to-forecast/gradients-ko.svg" alt="손실의 현재 은닉 상태 기울기에서 tanh의 미분을 거쳐 가중합 기울기를 구한다. 그 값에서 파라미터 사용분의 기울기와 이전 은닉 상태의 기울기가 갈라진다. 같은 파라미터를 사용한 시점들의 항을 더해 최종 grad를 만든다." loading="lazy">
<figcaption>파라미터에 대한 기울기와 이전 상태에 대한 기울기는 서로 다른 결과다. 이전 상태의 기울기는 그 상태를 만들었던 앞 시점의 계산으로 계속 전달된다.</figcaption>
</figure>

현재 시점의 가중합에는 이전 은닉 상태에 순환 가중치를 적용한 결과가 들어 있다. 이 연결에서 두 질문을 할 수 있다.

1. **지금 사용한 가중치를 바꾸면 손실이 어떻게 변하는가?** 이 계산은 해당 가중치의 최종 기울기에 더할 항을 만든다.
2. **지금 사용한 이전 은닉 상태를 바꾸면 손실이 어떻게 변하는가?** 이 계산은 앞 시점으로 전달할 기울기를 만든다.

두 번째 결과를 구한 다음에는 그 이전 상태를 만들었던 `tanh`와 가중합을 계속 미분한다. 이전 상태의 기울기를 현재 단계에서 계산할 수 없어서 뒤로 돌아가는 것이 아니다. **이미 구한 이전 상태의 기울기를 이용해, 그 상태를 만든 연산을 더 거슬러 가는 것**이다. 입력 가중치·편향·현재 입력에도 해당 연결의 기울기가 있으므로 “기울기가 두 종류만 있다”는 뜻은 아니다.

역전파는 과거 입력값을 복원하지 않는다. `tanh`를 없애거나 이전 은닉값을 다시 예측하지도 않는다. 구하는 대상은 계속해서 **손실이 각 계산값과 각 가중치에 반응하는 변화율**이다.[^autograd]

### 같은 가중치를 여러 번 썼으므로 사용 위치들의 영향을 더한다

순환 가중치 하나를 고르자. 예를 들어 `W_hh[0,1]`은 이전 은닉값 1을 현재 뉴런 0의 계산에 반영하는 숫자다. 이 **동일한 숫자**를 입력창의 14개 시점에서 반복해서 사용한다.

그 가중치를 바꾸면 그 값을 사용한 여러 시점의 계산에 영향을 줄 수 있다. 따라서 마지막 시점에서 직접 사용한 부분만 계산하면 전체 손실 변화율을 설명할 수 없다. 값이 0인 항이 생길 수도 있지만, 각 사용 위치에서 계산한 항을 모두 반영해 더해야 그 가중치 하나의 최종 기울기가 된다.

여기서 <strong>시점별 기여분(Contribution)</strong>이라는 말은 “같은 가중치의 최종 기울기를 만드는 덧셈에서, 해당 시점의 사용으로 나온 항 하나”라는 뜻이다. 시점별로 새 가중치나 새 손실을 만든 것이 아니다. 각 항에는 해당 시점 이후의 계산을 거쳐 최종 손실에 미친 영향이 반영되어 있다.

현재 시점의 항을 구할 때는 그 곱셈에 들어온 이전 상태를 주어진 값으로 본다. 그 이전 상태도 과거에 같은 가중치를 사용해 만들었다는 사실은, **이전 상태 쪽으로 전달한 기울기로 앞선 연산을 계속 미분하면서** 반영한다. 이 두 경로를 나눠 계산하고 파라미터 쪽 결과를 모으는 것이다.

가중치 행렬이 `(4,4)`이면 시점별 항도 `(4,4)`이고, 대응하는 위치끼리 더한 최종 `.grad`도 `(4,4)`다. 시점이 늘수록 합산할 계산은 많아지지만 최종 기울기의 원소 수는 가중치 원소 수와 같다.

또한 **한 번의 `backward()` 안에서 공유 가중치의 사용분을 합치는 일**과 **여러 `backward()` 호출 사이에서 `.grad`가 누적되는 일**은 구별해야 한다. `zero_grad()`는 이전 호출에서 남은 저장값을 비운다. 이번 `backward()` 안의 정상적인 합산을 없애지 않는다. 평균 손실에서 출발했다면 평균을 내는 계수도 이미 미분에 포함되므로, 완성된 기울기를 배치 크기로 임의로 한 번 더 나누지 않는다.

## 9. 과거 날짜로 학습하고, 뒤쪽 날짜로 평가한다

입력창을 만들었다고 아직 모델을 학습한 것은 아니다. 이제 70개 창을 실제 학습과 평가에 사용할 구간으로 나눈다.

<strong>학습 집합(Training Set)</strong>은 가중치를 수정하는 데 쓴다. <strong>검증 집합(Validation Set)</strong>은 학습 도중 어떤 가중치 상태를 선택할지 판단하는 데 쓴다. <strong>테스트 집합(Test Set)</strong>은 그 선택이 끝난 뒤 성능을 확인할 때 쓴다.

미래 날짜를 예측하는 문제이므로, **정답이 속한 원본 날짜의 인덱스**를 기준으로 분리한다. 시계열(Time Series)은 시간 순서로 관측한 기록이다. 미래 예측 성능을 평가할 때는 학습에 쓴 과거보다 뒤쪽 관측으로 확인해야 한다.[^time-split]

| 구분 | 정답의 원본 인덱스 | 정답 날짜 | 입력창 수 |
| --- | --- | --- | ---: |
| 학습 | 14~55 | 15~56일째 | 42 |
| 검증 | 56~69 | 57~70일째 | 14 |
| 테스트 | 70~83 | 71~84일째 | 14 |

<figure class="rnn-guide-figure">
<img src="/rnn-window-to-forecast/split-ko.svg" alt="84일 기록에서 정답 인덱스 14부터 55까지를 학습, 56부터 69까지를 검증, 70부터 83까지를 테스트로 나눈다. 각 정답의 입력에는 그 날짜 이전 14일의 실제 관측값만 사용한다." loading="lazy">
<figcaption>첫 검증 정답 인덱스 56의 입력은 42~55다. 앞서 관측한 날짜를 입력으로 사용하는 것과 미래 정답을 학습에 넣는 것은 다르다.</figcaption>
</figure>

```python
target_positions = torch.arange(seq_len, len(visitors))  # 14~83.
train_mask = target_positions < 56
valid_mask = (target_positions >= 56) & (target_positions < 70)
test_mask = target_positions >= 70
# 마스크(Mask)는 각 샘플을 선택할지 나타내는 True/False 배열이다.

X_train, y_train = X[train_mask], y[train_mask]  # 42개.
X_valid, y_valid = X[valid_mask], y[valid_mask]  # 14개.
X_test, y_test = X[test_mask], y[test_mask]     # 14개.
```

인접한 창은 과거 기록을 공유한다. 70개 창은 독립적으로 수집한 시계열 70개가 아니다. 그러나 학습 창과 검증 창이 과거 입력 일부를 공유한다는 이유만으로 곧바로 <strong>데이터 누수(Data Leakage)</strong>가 되는 것은 아니다. 여기서 확인할 것은 **예측할 당시 알 수 없던 미래 정보가 입력이나 학습에 들어갔는가**다.

이 평가는 매일 실제 방문자 수를 관측한 뒤 다음 날을 예측하는 방식이다. 테스트 첫날의 실제 값을 관측한 뒤에는 그 값을 다음 날 예측의 과거 입력으로 사용할 수 있다. 아직 오지 않은 14일 전체를 오늘 한꺼번에 예측하는 평가와는 다르다. 그 문제에서는 미래에 실제로 관측할 값을 중간 입력으로 넣을 수 없다.

숫자를 고정 상수 100으로 나눈 것은 전체 데이터의 평균이나 표준편차를 학습한 전처리가 아니다. 나중에 평균·표준편차를 이용하는 전처리로 바꾼다면, 그 통계량은 학습 구간에서만 계산해야 한다.

### DataLoader는 샘플들을 묶는다

`TensorDataset(X_train, y_train)`은 같은 위치의 입력과 정답을 한 쌍으로 묶는 데이터셋 객체다. `DataLoader`는 이 쌍들을 <strong>미니배치(Minibatch)</strong>로 묶어 반환한다.[^data]

```python
from torch.utils.data import DataLoader, TensorDataset

generator = torch.Generator().manual_seed(7)  # 샘플 섞기용 난수 설정.
train_loader = DataLoader(
    TensorDataset(X_train, y_train),
    batch_size=16,     # 한 호출에 최대 16개 입력창.
    shuffle=True,     # 완성된 학습창들의 순서만 섞는다.
    drop_last=False,  # 마지막에 16개 미만으로 남은 샘플도 사용한다.
    generator=generator,
)
```

학습 샘플 42개는 `16,16,10`의 세 묶음으로 나뉜다. `shuffle=True`는 창 안의 날짜 순서를 섞지 않는다. 이 모델은 각 창의 상태를 별도로 시작하므로 완성된 창들의 처리 순서를 섞을 수 있다. 연속된 조각 사이에 상태를 이어 전달하는 모델이라면 같은 설정을 그대로 적용해서는 안 된다.

<strong>에포크(Epoch)</strong>는 학습 샘플 전체를 한 번 처리하는 단위다. <strong>학습 스텝(Training Step)</strong>은 여기서 미니배치 하나의 손실로 가중치를 한 번 갱신하는 단위다.

| 반복 | 이번 예제에서 반복하는 대상 | 횟수 |
| --- | --- | --- |
| 한 샘플 안의 시간 처리 | 창의 시점 0~13 | 14시점 |
| 한 에포크 안의 미니배치 처리 | 샘플 16개, 16개, 10개 | 3스텝 |
| 전체 학습 | 같은 학습 집합 다시 처리 | 300에포크 |

따라서 이 코드의 전체 가중치 갱신 횟수는 900번이다. 한 창이 14시점이라는 이유로 `step()`을 시점마다 호출하지 않는다. 만약 전체 70개를 분할 없이 크기 16으로 묶었다면 `16,16,16,16,6`의 다섯 묶음이지만, 이번 학습에는 분리해 둔 42개만 사용한다.

## 10. 학습·검증을 실행하고 간단한 예측과 비교한다

학습 코드를 쓰기 전에 모드 두 종류를 구분하자. `model.train()`과 `model.eval()`은 Dropout처럼 학습·평가에서 동작이 달라지는 모듈의 모드를 정한다. `torch.no_grad()`는 블록 안에서 역전파용 기록을 만들지 않도록 한다. **`eval()`만 호출한다고 자동미분이 꺼지는 것은 아니다.** 이번 작은 모델에는 Dropout이 없지만 학습과 평가의 역할을 분리해 작성한다.[^grad-modes]

학습에서는 새 순전파로 만든 예측과 손실을 사용한다. 앞에서 `no_grad()`로 계산했던 관찰용 예측을 그대로 학습에 재사용하지 않는다.

아래 코드는 앞에서 정의한 `VisitorRNN`, 데이터, `train_loader`를 사용한다. <strong>자료형(dtype)</strong>은 숫자의 저장 형식이고, <strong>장치(device)</strong>는 CPU·GPU처럼 계산할 위치다. 이 실행에서는 모델·입력·정답을 모두 CPU의 `float32`로 맞춘다.

```python
import copy  # 가장 좋았던 가중치를 독립 복사하는 데 사용한다.

torch.manual_seed(7)  # 학습 모델의 초기 가중치 설정을 재현한다.
device = torch.device("cpu")  # 이 글의 결과를 측정한 계산 장치.
model = VisitorRNN(hidden_size=4).to(device)
loss_fn = nn.MSELoss()
optimizer = torch.optim.Adam(model.parameters(), lr=0.01)
best_valid_loss = float("inf")  # 처음에는 어떤 유한 손실도 더 작다.
best_state = None
best_epoch = 0

for epoch in range(1, 301):  # 1~300. 끝 경계 301은 제외한다.
    model.train()
    loss_sum = 0.0
    sample_count = 0

    for xb, yb in train_loader:
        xb, yb = xb.to(device), yb.to(device)
        optimizer.zero_grad(set_to_none=True)
        prediction = model(xb)  # 현재 B는 16, 16, 10 중 하나.
        assert prediction.shape == yb.shape
        loss = loss_fn(prediction, yb)
        loss.backward()
        optimizer.step()

        # 각 배치 평균을 샘플 수로 가중해 전체 평균을 준비한다.
        loss_sum += loss.item() * len(xb)
        sample_count += len(xb)

    train_loss = loss_sum / sample_count
    model.eval()
    with torch.no_grad():  # 숫자 계산은 수행하되 역전파 기록은 만들지 않는다.
        valid_prediction = model(X_valid.to(device))
        valid_loss = loss_fn(valid_prediction, y_valid.to(device)).item()

    if valid_loss < best_valid_loss:
        best_valid_loss = valid_loss
        best_epoch = epoch
        best_state = copy.deepcopy(model.state_dict())
        # state_dict는 이름별 파라미터·버퍼를 담는다.
        # 독립 복사를 해야 이후 학습에 저장값이 따라 바뀌지 않는다.

model.load_state_dict(best_state)  # 검증에서 선택한 가중치로 복원한다.
model.eval()
with torch.no_grad():
    test_prediction = model(X_test.to(device)).cpu()
```

`loss.item()`은 숫자 하나인 텐서에서 표시·기록용 Python 숫자를 꺼낸다. 학습에 쓰는 `loss` 자체를 `loss.item()`으로 대체한 뒤 `backward()`를 호출하면 안 된다.

에포크의 손실을 세 배치 손실의 단순 평균으로 계산하지 않은 이유도 확인하자. 앞의 두 배치는 16개씩, 마지막 배치는 10개다. 각 배치 평균에 샘플 수를 곱해 합산한 뒤 42로 나눠야 샘플별 비중이 같아진다. 이 기록은 학습 중 매 스텝의 서로 다른 가중치에서 관측한 손실의 평균이다. 에포크 마지막 가중치로 전체 학습 데이터를 다시 평가한 손실과는 구분한다.

검증에서는 가중치를 수정하지 않는다. 검증 손실이 가장 낮았던 가중치를 선택하고, 그 상태를 복원한 다음 테스트를 수행한다. 테스트 결과를 보고 다시 설정을 고르는 과정은 이 실행에 포함하지 않았다.

### 결과는 방문자 수 단위로 해석한다

<strong>평균절대오차(Mean Absolute Error, MAE)</strong>는 예측과 정답의 차이에 절댓값을 취해 평균한 값이다. 데이터에 적용했던 `/100`을 되돌리면 방문자 수 단위로 읽을 수 있다. 학습에는 MSE를 사용했고, 아래 성능 비교에는 해석하기 쉬운 MAE를 사용했다.

비교할 **기준선(Baseline)** 두 가지도 정했다. 하나는 “내일은 오늘과 같다”이고, 다른 하나는 “내일은 지난주 같은 요일과 같다”다. 둘 다 예측일 이전에 관측한 값만 사용한다.

```python
test_positions = target_positions[test_mask]  # 정답 인덱스 70~83.
yesterday = visitors[test_positions - 1].unsqueeze(-1)
previous_week = visitors[test_positions - 7].unsqueeze(-1)

def mae_in_visitors(prediction):
    return (prediction - y_test).abs().mean().item() * value_scale

print("RNN", mae_in_visitors(test_prediction))
print("어제값", mae_in_visitors(yesterday))
print("지난주값", mae_in_visitors(previous_week))
```

Python 3.12.14, PyTorch 2.15.0+cpu, CPU `float32`에서 실행한 결과다. 데이터 생성 시드는 1, 모델 초기화와 학습창 섞기 시드는 7로 고정했다. 최대 300에포크 중 검증 손실이 가장 낮았던 시점은 289에포크였다. 숫자는 내려받는 실행 파일에서 확인할 수 있다.

| 방법 | 테스트 MAE, 방문자 수 단위 |
| --- | ---: |
| 학습한 RNN | 5.649 |
| 어제 방문자 수를 그대로 사용 | 19.324 |
| 지난주 같은 요일의 방문자 수를 사용 | 2.726 |

**이 실행의 RNN은 어제값 기준선보다 좋았지만 지난주값 기준선보다 부정확했다.** 데이터 자체를 주간 패턴의 반복과 작은 잡음으로 만들었으므로 지난주값이 강한 비교 대상이다. 이것은 이번 생성 조건에서의 해석이며, 실제 서비스 성능에 대한 결론은 아니다. 신경망을 학습했다는 사실과 문제에 유용한 예측을 얻었다는 사실은 별도로 확인해야 한다.

84일 기록의 마지막 14일을 넣으면 아직 정답이 없는 85일째를 예측할 수도 있다. 입력 형태는 `(1,14,1)`이고 위 실행의 예측은 약 59.58명이다. 실제 85일째 값을 갖고 있지 않으므로 이 예측의 오차는 계산할 수 없다.

## 11. 구현 확인과 실제 성능 확인은 서로 다른 검사다

같은 입력창을 하나씩 넣은 결과와 한 배치로 넣은 결과가 같은지 비교하면, 배치 처리에서 샘플이 섞이지 않았는지 확인할 수 있다. 같은 가중치·초기 상태를 쓰고, 샘플 간 계산이 독립적이며, 평가 시 무작위 동작 차이가 없다는 조건에서 비교한다.

```python
model.eval()
with torch.no_grad():
    check = X_test[:4]  # 비교할 네 입력창, (4,14,1).
    one_pred = model(check[:1])  # 첫 창 하나의 예측, (1,1).
    individual = torch.cat(
        [model(row.unsqueeze(0)) for row in check],
        dim=0,  # 각각 (1,1)인 예측의 기존 샘플 축을 연결 -> (4,1).
    )
    together = model(check)  # 네 창을 한 번에 계산 -> (4,1).

assert torch.allclose(individual, together, atol=1e-6, rtol=1e-6)
# atol: 절대 허용 오차 / rtol: 기준값의 크기에 비례하는 허용 오차.
```

`one_pred`는 첫 샘플 하나의 결과이고, `individual`은 모든 샘플을 하나씩 계산한 뒤 모은 결과다. 변수 이름에 individual이 있다고 샘플 하나만 담는 것은 아니다.

실수 연산은 계산 순서에 따라 작은 차이가 날 수 있다. `allclose`는 정상적인 유한 값에 대해 `abs(a-b) <= atol + rtol*abs(b)`인지 확인한다. 위 허용 오차는 이 예제의 검사용 설정이며 모든 모델·자료형·장치에 적용할 고정 기준은 아니다.[^allclose]

전체 실행 파일의 구조 검증에서는 70개 창을 사용했다. 개별 호출과 배치 호출의 최대 차이는 약 `4.47×10⁻⁸`, 같은 가중치를 복사한 `RNNCell`과 `RNN`의 최대 차이는 약 `5.96×10⁻⁸`였다. 모두 해당 검사에서 설정한 허용 오차 안에 있었다. 이 검사는 두 구현이 같은 계산을 수행하는지 확인한다. **실제 정답과 비교한 예측 정확도를 뜻하지는 않는다.**

### 출력용 detach와 학습 연결을 끊는 detach를 구분한다

<strong>계산 그래프(Computation Graph)</strong>는 어떤 연산이 어떤 값을 만들어 냈는지 연결한 기록이다. 자동미분은 이 연결을 이용한다. `detach()`는 같은 숫자를 가지면서 이전 미분 연결에서 분리된 텐서를 반환한다.[^detach]

```python
print(state.detach())  # 출력에 사용할 분리된 텐서를 만든다.
# 원래 state가 다음 계산에 쓰일 때의 미분 연결을 바꾸지 않는다.

# state = state.detach()
# 이렇게 다시 대입하면 이후 계산은 분리된 상태를 사용한다.
```

시간 반복문에서 매번 `state = state.detach()`를 실행하면 이후 손실이 그 상태를 거쳐 앞선 시점으로 전달되는 경로가 끊긴다. 앞선 입력의 숫자 정보가 순전파에서 당장 사라지는 것은 아니지만, 그 연결을 통과하는 역전파가 잘린다. 이 글처럼 14일 전체의 연결을 학습하려는 루프에는 넣지 않는다.

`detach()`는 복사가 아니며 원본과 저장 공간을 공유한다. 숫자까지 독립적으로 보관하려면 `detach().clone()`을 사용한다. `clone()`만 사용하면 복사된 숫자도 원래 계산의 미분 연결을 유지할 수 있다.

### 긴 시퀀스에서 확인할 문제

앞 시점으로 갈수록 손실 기울기가 매우 작아지는 현상을 **기울기 소실(Vanishing Gradient)**, 지나치게 커지는 현상을 <strong>기울기 폭발(Exploding Gradient)</strong>이라고 한다. RNN에서는 `tanh`의 국소 미분값과 반복된 순환 가중치 연산이 함께 영향을 준다. `tanh`의 미분값만 보고 전체 기울기가 항상 작아진다고 단정할 수 없다.[^rnn-training]

<strong>기울기 클리핑(Gradient Clipping)</strong>은 기울기의 크기를 제한하는 방법이다. 필요할 때는 `backward()` 뒤, `step()` 전에 적용한다. 아래의 노름(Norm)은 여러 파라미터의 기울기를 함께 보았을 때의 전체 크기다. 각 원소를 무조건 −1과 1 사이로 자르는 코드가 아니다.[^clip]

```python
# 위 학습 루프에서 큰 기울기를 제한할 필요가 있을 때 넣을 위치다.
loss.backward()
nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
# max_norm=1.0은 설명용 설정이다. 문제에 맞게 결정해야 한다.
optimizer.step()
```

클리핑은 이미 작아진 기울기를 복구하지 않는다. 긴 기간의 의존성을 다뤄야 한다면 입력 길이와 학습 상태를 먼저 점검하고, 정보의 유지·갱신을 조절하는 구조가 있는 GRU나 LSTM도 검토할 수 있다. 어느 구조든 실제 미래 구간과 기준선 비교가 필요하다.

여기까지 실행했다면 다음 다섯 질문에 답해 보자.

1. `X[i]`의 정답은 원본 기록의 어느 위치에 있는가?
2. `output[:, -1, :]`는 어떤 축을 선택하고 어떤 값들을 남기는가?
3. `state = cell(x_t, state)`와 `optimizer.step()`은 각각 무엇을 바꾸는가?
4. 14시점과 한 에포크의 3스텝은 각각 무엇을 세는가?
5. 배치 계산이 개별 계산과 일치하는 것만으로 미래 예측이 정확하다고 말할 수 있는가?

각 질문을 설명하고 학습·평가 코드를 실행할 수 있으면 기본 RNN으로 다음 날 예측 모델을 만드는 데 필요한 연결을 익힌 것이다. 수동 미분 전체를 외우는 일은 다음 실습으로 넘어가기 위한 조건이 아니다.

<summary>A. 배열을 선택하거나 구조를 바꾸는 코드</summary>

함수(Function)는 `torch.stack(...)`처럼 호출하고, 메서드(Method)는 `X.unsqueeze(...)`처럼 객체에 붙여 호출한다. 클래스인 `nn.RNN(...)`은 모델 객체를 만든다. 아래 표는 이 글에 나온 표현을 작업 종류별로 구분한 것이다.

| 표현 | 작업 | 결과 예시 |
| --- | --- | --- |
| `len(X)` | 맨 앞 축의 길이 확인 | 전체 데이터에서는 70 |
| `X.shape` | 축별 크기 확인 | `torch.Size([70,14,1])` |
| `tuple(X.shape)` | shape를 일반 튜플 형태로 표시 | `(70,14,1)` |
| `X.ndim` | 축 개수 확인 | 3 |
| `X.numel()` | 전체 원소 개수 확인 | 980 |
| `torch.stack(windows, dim=0)` | 같은 크기 텐서를 새 축으로 묶기 | `(14,)` 70개 → `(70,14)` |
| `torch.cat(predictions, dim=0)` | 기존 축을 이어 붙이기 | `(1,1)` 70개 → `(70,1)` |
| 같은 예측들을 `stack(dim=0)` | 새 축으로 묶기 | `(1,1)` 70개 → `(70,1,1)` |
| `row.unsqueeze(0)` | 맨 앞에 크기 1인 축 추가 | `(14,1)` → `(1,14,1)` |
| `X_2d.unsqueeze(-1)` | 맨 뒤에 크기 1인 축 추가 | `(70,14)` → `(70,14,1)` |
| `y.squeeze(-1)` | 마지막 축의 크기가 1이면 제거 | `(70,1)` → `(70,)` |
| `state.flatten()` | 기본값으로 모든 축을 한 축에 펼치기 | `(2,4)` → `(8,)` |

`squeeze()`에 축을 지정하지 않으면 크기가 1인 모든 축이 없어질 수 있다. 배치 크기가 1일 때 배치 축도 사라질 수 있으므로 목적에 맞게 `squeeze(-1)`처럼 지정한다.

`reshape()`는 전체 원소 수를 유지하며 모양을 바꾼다. 샘플 축과 시간 축의 순서를 바꾸려는 목적이라면 `transpose(0,1)`처럼 축 교환을 사용해야 한다. `(B,T,F)`를 무조건 `reshape(T,B,F)`로 바꾸면 같은 의미의 축 교환이 되지 않는다. 또한 `flatten()`으로 `[샘플0의 네 값, 샘플1의 네 값]`을 한 줄에 펼치면 원래 샘플 경계는 shape에서 사라진다.[^tensor-views]

shape `(3,)`의 쉼표는 항목 하나짜리 튜플을 적는 Python 문법이다. 쉼표가 새 축을 만드는 것은 아니다. `[10,20,30]`을 텐서로 만들면 `(3,)`, `[[10],[20],[30]]`을 텐서로 만들면 `(3,1)`이다. 둘 다 숫자는 세 개지만 배열 구조가 다르다.

짧은 <strong>리스트 컴프리헨션(List Comprehension)</strong>은 반복하며 리스트를 만드는 문법이다. 본문의 반복문을 아래처럼 줄일 수 있다. 익숙하지 않다면 본문의 `for`와 `append`를 그대로 사용하면 된다.

```python
X = torch.stack([
    visitors[i:i + seq_len]
    for i in range(len(visitors) - seq_len)
]).unsqueeze(-1)
y = visitors[seq_len:].unsqueeze(-1)
```

`X = y = None`은 두 이름에 아직 값이 없다는 표시를 넣는 문장이다. 바로 다음에 `X`, `y`를 모두 새로 만들면 필요하지 않다. 함수에 적는 `values: torch.Tensor`, `seq_len: int`, `-> tuple[torch.Tensor, torch.Tensor]`는 기대하는 인자·반환 자료형을 표시하는 <strong>타입 힌트(Type Hint)</strong>다. 이 표기만으로 실행 중 입력 검사가 자동 수행되는 것은 아니다. 다운로드 파일은 1차원 텐서인지, 창 길이가 양수이며 다음 날 정답이 남는지 실제 조건문으로 확인한다.[^typing]

출력용 변환도 구분하자.

| 표현 | 실제로 하는 일 |
| --- | --- |
| `tensor.item()` | 원소가 정확히 하나인 텐서를 Python 숫자 하나로 바꾼다. |
| `tensor.tolist()` | 텐서를 Python 숫자 또는 중첩 리스트로 바꾼다. 필요한 경우 CPU로 옮긴다. |
| `state.detach().flatten().tolist()` | 미분 연결에서 분리 → 한 축으로 펼침 → Python 리스트로 변환한다. |
| `tensor.detach().cpu().numpy()` | 미분 연결에서 분리 → CPU 이동 → NumPy 배열로 변환한다. |

`tolist()` 자체가 미분 가능한 연산이 아니므로 단순 리스트 출력에 `detach()`가 반드시 필요한 것은 아니다. 다만 출력용 데이터의 분리를 드러내는 표현으로 사용할 수 있다. 숫자를 확인하려고 변환한 Python 값과, 학습 계산에 사용하는 텐서를 구분한다.[^tensor-convert]

<summary>B. 가상 데이터, 숫자의 크기, 그래프 좌표</summary>

`repeat(12)`는 일주일의 일곱 숫자 묶음을 순서대로 12번 반복한다. 첫 번째 숫자만 12번 적은 뒤 두 번째 숫자를 12번 적는 연산이 아니다. 기존 `(7,)`의 길이가 `(84,)`로 늘어나며 축은 여전히 하나다.

`torch.randn()`은 평균 0, 표준편차 1인 <strong>표준정규분포(Standard Normal Distribution)</strong>에서 난수를 뽑는다. 평균은 값들의 합을 개수로 나눈 중심값이고, 표준편차는 평균 주변의 퍼짐을 나타내는 수치다. 유한하게 뽑힌 84개 숫자의 실제 평균·표준편차가 정확히 0·1이라는 뜻은 아니다. 난수에 3을 곱하면 분포의 표준편차도 3배가 된다. 3은 RNN의 필수 상수가 아니라 가상 변동 크기를 정한 값이다.[^randn]

`torch.manual_seed()`는 같은 환경과 실행 순서의 난수 결과를 재현하는 데 도움을 준다. 서로 다른 버전·장치에서 모든 계산 결과까지 같게 만드는 보장은 아니다. 그래서 본문에 실행 버전·장치·시드를 함께 적었다.[^reproducibility]

Matplotlib으로 방문 기록을 그릴 수도 있다. `plt`는 `matplotlib.pyplot`의 별칭이다. 다음 코드는 Matplotlib과 NumPy가 설치된 환경에서 실행한다.

```python
import matplotlib.pyplot as plt

plt.figure(figsize=(9, 3))  # 그림의 가로·세로 크기. 단위는 인치.
plt.plot(visitors.numpy())  # CPU이고 미분 추적이 없는 현재 텐서.
plt.xlabel("day index")     # 가로좌표 이름.
plt.ylabel("visitors / 100")  # 세로좌표 이름.
plt.show()
```

`plot(y_values)`는 가로좌표를 생략했을 때 `0,1,...,len(y_values)-1`을 사용한다. Matplotlib이 날짜라는 의미를 알아낸 것은 아니다. 가로·세로 좌표로 그림을 그렸어도 원본 `visitors`는 `(84,)`인 1차원 텐서다. 그래프의 두 좌표와 텐서의 축 개수는 별개의 개념이다. 실제 2차원 배열을 전달하면 기본적으로 각 열이 별도 선으로 그려지는 동작도 RNN의 축 규칙과는 별개다.[^plot]

위 조건의 `numpy()` 변환은 원본 텐서와 메모리를 공유할 수 있다. 자료형과 장치도 shape와 분리해서 봐야 한다. `float32`와 `float64`는 실수 저장 정밀도의 차이이고, 모델의 `.double()`은 부동소수점 파라미터 등을 `float64`로 바꾼다. 입력도 같은 자료형·장치로 준비해야 RNN 계산이 맞게 이어진다.

<summary>C. tanh의 기울기와 손실의 기울기를 연결하기</summary>

이 설명에서는 **같은 샘플, 같은 시점, 같은 은닉 뉴런의 원소 하나**를 본다. `a`는 활성화 전 가중합이고 `h=tanh(a)`는 은닉값이다. `L`은 그 이후 계산을 거쳐 얻는 최종 손실이다. `Δa`, `Δh`, `ΔL`은 각각의 작은 변화량을 뜻한다.

`tanh`를 미분한다는 것은 저장된 숫자 하나를 미분한다는 뜻이 아니다. **입력 `a`에 따라 출력 `h`가 달라지는 함수 관계**에서 변화율을 구하는 것이다. 현재 위치에서 그 변화율은 `1-h²`다. 이를 <strong>국소 기울기(Local Derivative)</strong>라고 부르는 이유는 이 함수와 현재 계산 위치 사이의 관계를 나타내기 때문이다.

가중합을 조금 바꾸면 은닉값의 변화는 다음처럼 근사된다.

<div class="rnn-guide-math">
$$
\Delta h \approx (1-h^2)\Delta a
$$
</div>

이 식은 `h=(1-h²)×a`라는 값 자체의 계산식이 아니다. 작은 변화량 사이의 관계다. `tanh`는 직선이 아니므로 위치가 달라지면 변화율도 달라진다.

이제 `grad_h`를 **최종 손실의 은닉값에 대한 기울기**라고 정의하자. 앞의 변화가 이후 손실에 미치는 관계를 연결할 수 있다.

<div class="rnn-guide-math">
$$
\Delta L \approx \mathrm{grad}_h\,\Delta h
\approx \mathrm{grad}_h(1-h^2)\Delta a
$$
</div>

그래서 가중합에 대한 손실 기울기 `grad_a`는 다음 코드가 된다.

```python
grad_a = grad_h * (1 - h**2)
# grad_h: L의 h에 대한 기울기.
# 1-h**2: h의 a에 대한 기울기.
# grad_a: L의 a에 대한 기울기.
```

`h` 자체에 `1-h²`를 곱하는 것이 아니다. `tanh`의 국소 기울기만 알아서는 손실이 그 은닉값에 얼마나 민감한지 알 수 없으므로 `grad_h`도 필요하다. 이 계산으로 `tanh`의 원래 입력 `a`를 복원하지 않는다. 원래 입력을 찾는 <strong>역함수(Inverse Function)</strong>와 미분(Differentiation)은 서로 다른 작업이다.

수동 검산 코드의 `adj_h`, `adj_a`는 각각 위의 `grad_h`, `grad_a`에 해당한다. `adj`는 Python이나 PyTorch 예약어가 아니라 작성자가 고른 변수 이름이다. 같은 원리는 MLP의 역전파에도 쓰인다. RNN만 별도의 미분 법칙을 사용하는 것은 아니다.

<summary>D. 행렬 역전파에서 정확히 무엇을 합산하는가</summary>

먼저 곱셈 하나를 보자. `z=w×u`에서 `u`를 고정하고 `w`를 조금 바꾸면 `z`의 변화량은 `u×Δw`다. 반대로 `w`를 고정하고 `u`를 바꾸면 변화량은 `w×Δu`다. **같은 곱셈도 어느 입력에 대한 기울기를 구하느냐에 따라 함께 곱할 값이 다르다.**

이제 한 시점의 RNN 가중합으로 돌아가자. `grad_a`는 가중합의 각 원소에 대한 최종 손실 기울기 `(B,H)`다. `x_t`는 현재 입력 `(B,F)`, `h_prev`는 이전 상태 `(B,H)`다. `G_ih_t`와 `G_hh_t`는 현재 시점에서 사용한 각 가중치의 기울기 항이다. `grad_h_prev`는 앞 시점으로 전달할 이전 상태의 손실 기울기다.

```python
G_ih_t = grad_a.T @ x_t          # 입력 가중치의 이번 시점 사용분.
G_hh_t = grad_a.T @ h_prev       # 순환 가중치의 이번 시점 사용분.
grad_h_prev = grad_a @ W_hh      # 이전 은닉 상태에 대한 손실 기울기.
```

| 계산 | 본문의 `B=2,F=1,H=4`에서의 shape | 합산하는 대상 |
| --- | --- | --- |
| `grad_a.T @ x_t` | `(4,2) @ (2,1) → (4,1)` | 같은 입력 가중치를 사용한 샘플들 |
| `grad_a.T @ h_prev` | `(4,2) @ (2,4) → (4,4)` | 같은 순환 가중치를 사용한 샘플들 |
| `grad_a @ W_hh` | `(2,4) @ (4,4) → (2,4)` | 이전 은닉값이 연결된 현재 뉴런들 |

인덱스로 더 정확히 표현할 수도 있다. `b`는 샘플, `j`는 현재 은닉 뉴런, `k`는 입력 특징, `q`는 이전 은닉값의 위치다. 모두 해당 축의 0부터 시작하는 인덱스다.

| 결과 원소 하나 | 그 원소를 만들 때 더하는 것 |
| --- | --- |
| `G_ih_t[j,k]` | 모든 샘플 `b`의 `grad_a[b,j] × x_t[b,k]` |
| `G_hh_t[j,q]` | 모든 샘플 `b`의 `grad_a[b,j] × h_prev[b,q]` |
| `grad_h_prev[b,q]` | 모든 현재 뉴런 `j`의 `grad_a[b,j] × W_hh[j,q]` |

앞의 두 결과는 같은 가중치를 사용한 샘플들의 영향을 합친다. 마지막 결과는 이전 은닉값 하나가 현재의 여러 뉴런에 연결되어 있으므로 그 연결들을 합친다. 이후 `G_ih_t`, `G_hh_t`를 **시점별로** 더하면 공유 가중치의 최종 기울기가 된다. 샘플에 대한 합산, 뉴런에 대한 합산, 시간에 대한 합산을 구분해야 한다.

다변량 예제로 `B=2,F=4,H=3`을 선택하면 위 결과 shape는 순서대로 `(3,4)`, `(3,3)`, `(2,3)`이 된다. 입력 특징 개수가 바뀌어도 각 결과가 대응하는 대상은 그대로다. shape가 우연히 맞아서 기울기가 되는 것이 아니라 각 곱셈의 미분 규칙을 모아 계산했기 때문에 해당 기울기가 된다.

이번 설명은 마지막 시점의 예측에서 손실을 계산하는 조건이다. 각 시점에 별도 손실을 두는 모델이라면, 해당 상태에서 직접 손실로 가는 경로의 기울기도 더해야 한다. 또한 평균 손실에서 시작한 `grad_a`에는 평균 계수가 이미 들어 있으므로 위 합산 이후 배치 크기로 중복해서 나누지 않는다.

</details>

<details>
<summary>E. 세 시점의 수동 역전파를 PyTorch와 검산하기</summary>

이 부분만 숫자 하나짜리 은닉 상태로 줄인 **별도 검산 예제**다. 본문 방문자 예측 모델을 바꾼 것이 아니다. 조건을 먼저 고정한다.

| 조건 | 설정과 역할 |
| --- | --- |
| 입력 | 샘플 하나에 `[1,2,3]`, 세 시점의 검산용 숫자 |
| 구조 | 입력 특징 하나·은닉값 하나·편향 없음 |
| 입력 가중치 | 0.5, 현재 입력에 곱하는 파라미터 |
| 순환 가중치 | 0.5, 이전 상태에 곱하는 별도의 파라미터 |
| 초기 상태 | 0 |
| 정답 | 0.5, 마지막 은닉값과 비교할 목표 |
| 손실 | `0.5 × (마지막 은닉값 − 정답)²` |
| 자료형·장치 | 작은 수치 차이를 확인하기 위한 CPU `float64` |

표에서 같은 0.5를 사용해도 두 가중치, 정답, 손실 계수는 각각 다른 역할이다. 손실 앞의 0.5는 제곱을 미분할 때 생기는 2를 상쇄하는 정의이며, 기본 `nn.MSELoss()`에 들어 있는 계수가 아니다. 여기서는 마지막 은닉값 자체를 예측으로 사용하는 특별한 설정이므로 별도의 Linear가 없다. 이런 식으로 값을 그대로 쓰는 출력을 <strong>항등 출력(Identity Head)</strong>이라고 표현하기도 한다.

검산 코드의 `hs`는 초기 상태까지 함께 저장한다. 본문은 시점을 코드처럼 0부터 적었지만, 여기서는 배열의 첫 자리에 초기 상태를 넣는다. 따라서 **`hs`의 저장 인덱스는 입력 인덱스보다 하나 크다.** 공식 문서에서 초기 상태를 `h_0`라고 표기하는 경우도 있으므로 이름만 보고 같은 값을 뜻한다고 판단하지 않는다.

| 실제 값 | 본문의 표기 | 이 검산 배열 |
| --- | --- | --- |
| 첫 입력 전 상태 | `h_init` | `hs[0]` |
| 입력 인덱스 0의 처리 결과 | `h_0` | `hs[1]` |
| 입력 인덱스 1의 처리 결과 | `h_1` | `hs[2]` |
| 입력 인덱스 2의 처리 결과 | `h_2` | `hs[3]` |

세 입력을 처리했지만 배열에는 초기 상태까지 네 항목이 있다. 초기 상태가 입력 시점을 하나 추가한 것은 아니다. 아래 코드는 처음부터 실행할 수 있는 작은 검산이다.

```python
import torch
from torch import nn

scalar_rnn = nn.RNN(1, 1, bias=False, batch_first=True).double()
with torch.no_grad():  # 초기값 지정은 역전파 기록에서 제외한다.
    scalar_rnn.weight_ih_l0.fill_(0.5)
    scalar_rnn.weight_hh_l0.fill_(0.5)
    # fill_는 기존 텐서 값을 직접 수정한다. l0는 첫 RNN 층이다.

x_scalar = torch.tensor([[[1.0], [2.0], [3.0]]], dtype=torch.float64)
target = 0.5
output_scalar, _ = scalar_rnn(x_scalar)  # (1,3,1): 손실이 아니라 은닉값.
loss_scalar = 0.5 * (output_scalar[0, -1, 0] - target).square()
scalar_rnn.zero_grad(set_to_none=True)
loss_scalar.backward()
autograd_whh = scalar_rnn.weight_hh_l0.grad.item()

hs = [0.0] + output_scalar.detach().flatten().tolist()
# 이 특수 예제에서만 flatten 결과가 시점별 숫자 하나씩인 목록이다.
recurrent_weight = scalar_rnn.weight_hh_l0.detach().item()
adj_h = hs[-1] - target  # 마지막 은닉값에 대한 손실 기울기.
pieces = [0.0] * 3      # 순환 가중치의 시점별 항을 저장할 자리.

for t in range(3, 0, -1):  # 저장 인덱스 3,2,1. 끝 경계 0은 제외.
    adj_a = adj_h * (1 - hs[t] ** 2)  # 현재 가중합에 대한 손실 기울기.
    pieces[t - 1] = adj_a * hs[t - 1] # 가중치 쪽: 이전 상태를 곱한다.
    adj_h = adj_a * recurrent_weight # 이전 상태 쪽: 가중치를 곱한다.

print(pieces)
print(sum(pieces), autograd_whh)
assert abs(sum(pieces) - autograd_whh) < 1e-12
```

`t`는 3, 2, 1 순서로 진행하지만 `pieces[t-1]`에 저장하므로 완성된 배열의 순서는 첫째·둘째·셋째 시점이다. 같은 `adj_a`에서 가중치 쪽과 이전 상태 쪽의 결과를 각각 구한다. 이전 상태 쪽 결과가 다음 반복의 `adj_h`가 되어 그 상태를 만들었던 앞선 `tanh`로 이어진다.

| 해당 사용 위치 | 순환 가중치의 기울기에 더하는 값 |
| --- | ---: |
| 첫 시점 | 0 |
| 둘째 시점 | 0.00251786232041447 |
| 셋째 시점 | 0.03172237391003767 |
| 세 항의 수동 합계 | 0.03424023623045214 |
| PyTorch 자동미분 | 0.03424023623045215 |

첫 시점에서 순환 가중치에 곱한 초기 상태가 0이므로 그 사용분은 0이다. **첫 시점 전체가 학습에서 빠진다는 뜻은 아니다.** 첫 시점 입력에 곱하는 입력 가중치의 기울기 항은 0이 아닐 수 있다. 입력 가중치의 사용분을 검산하려면 그 시점의 `adj_a`에 이전 상태 대신 현재 입력을 곱한다.

마지막에 구한 초기 상태의 손실 기울기는 이 예제에서 더 사용하지 않는다. 초기 상태를 학습하는 파라미터로 두지 않고 0으로 고정했기 때문이다. 또한 `pieces`를 Python 숫자로 계산했다고 모델의 `.grad`가 자동으로 바뀌는 것은 아니다. 이미 `backward()`로 얻은 결과와 비교했을 뿐이며, 이 코드에는 가중치 학습을 수행하는 `step()`이 없다.

<strong>유한차분(Finite Difference)</strong>은 가중치를 조금 바꿔 실제 손실을 다시 계산하고 변화율을 근사하는 방법이다. 중앙 유한차분은 현재 순환 가중치 `w`의 양쪽, `w+ε`와 `w−ε`에서 손실을 구한다. 여기서 `ε`는 작은 변화 간격이다.

<div class="rnn-guide-math">
$$
\frac{L(w+\varepsilon)-L(w-\varepsilon)}{2\varepsilon}
$$
</div>

다운로드 검산 파일은 원본 모델을 수정하지 않는 별도 손실 함수에 순환 가중치의 두 후보값 `w+ε`, `w−ε`를 각각 넣어 손실을 계산한다. 입력 가중치는 고정한다. `ε=10⁻⁶`에서 결과는 `0.03424023624354344`였다. 자동미분·수동 미분과 가까운 결과지만 유한차분은 근사다. 간격을 너무 작게 해도 실수 정밀도의 영향을 받을 수 있다. `1e-12` 같은 허용 오차는 이 작은 CPU `float64` 검산의 선택이며 일반적인 GPU `float32` 계산에 그대로 적용할 기준은 아니다.[^gradcheck]

<summary>F. 다른 RNN 설정과 디버깅에서 확인할 것</summary>

본문의 `B`와 `T`는 호출에 넣는 데이터의 개수다. `F`와 `H`는 가중치 구조를 결정한다. 같은 RNN 객체에 `T=14` 대신 `T=28`인 입력을 넣을 수 있지만, `F=1`로 만든 모델에 특징 네 개를 그대로 넣을 수는 없다.

| 바꾸는 조건 | 같은 기본 모델에서의 의미 |
| --- | --- |
| `B`, 배치 크기 | 호출에서 처리할 샘플 수와 초기 상태의 샘플 수가 달라진다. |
| `T`, 시점 수 | 처리할 시점과 `output`의 시간 축 크기가 달라진다. |
| `F`, 입력 특징 수 | 입력 가중치 구조가 달라져야 한다. |
| `H`, 은닉값 수 | RNN 가중치와 연결할 Linear의 입력 크기가 달라져야 한다. |

`id(model)`은 Python 객체의 식별값이다. 같은 객체를 유지해도 `step()`으로 내부 가중치 숫자는 바뀔 수 있다. 값까지 그대로인지 확인하려면 호출 전후의 파라미터 복사본을 비교해야 한다. 반대로 `no_grad()`에서 시간 길이만 달리해 순전파한 것은 가중치 학습이 아니다. 입력을 모두 0으로 넣어도 편향이 있으면 출력이 반드시 0은 아니다.

다층이나 양방향을 사용할 때에는 반환값을 다시 해석해야 한다. `K`는 RNN 층 수, `D`는 처리 방향 수이며 단방향은 1, 양방향은 2다. 층마다, 방향마다 별도의 파라미터를 사용한다.

| 설정 | 배치 입력에서의 반환 shape와 마지막 상태 |
| --- | --- |
| 일반적인 `batch_first=True` | `output=(B,T,D×H)`, `h_n=(K×D,B,H)` |
| 여러 층·단방향 | `output[:, -1, :]`는 마지막 층의 `h_n[-1]`과 대응한다. |
| 양방향 | 앞→뒤와 뒤→앞의 상태를 따로 확인해야 한다. 본문의 `h_n[0]` 선택을 그대로 일반화하지 않는다. |
| 패딩한 가변 길이 입력 | 각 샘플의 실제 마지막 위치가 다를 수 있어 `-1`이 실제 마지막 관측을 뜻하지 않을 수 있다. |
| 배치 축 없는 RNN 입력 | 입력 `(T,F)`, `output=(T,D×H)`, `h_n=(K×D,H)`이며 `batch_first`가 적용되지 않는다. |
| 배치 축 없는 RNNCell 입력 | 입력 `(F,)`, 이전 상태 `(H,)`, 반환 상태 `(H,)`를 사용한다. |

`nn.RNN` 자체가 배치 없는 입력을 지원하는 것과, 우리가 만든 `VisitorRNN.forward`가 그 입력을 지원하는 것은 별개다. 본문의 `forward`는 세 축의 `output[:, -1, :]`를 사용하므로 배치 축을 유지한 입력을 사용한다. 일반 MLP의 `(B,F)`, Conv2d의 `(B,C,높이,너비)`도 같은 방식으로 배치 축과 샘플 내부 구조를 구분해 읽으면 된다. 여기서 `C`는 이미지의 입력 채널 수다.

모드와 기울기 기록은 다음과 같이 구별한다.

| 코드 | 바꾸는 것 |
| --- | --- |
| `model.train()` | 학습·평가 동작이 다른 모듈을 학습 모드로 설정한다. |
| `model.eval()` | 그런 모듈을 평가 모드로 설정한다. |
| `with torch.no_grad():` | 블록 안의 일반적인 텐서 연산에 역전파 기록을 만들지 않는다. 숫자 계산은 한다. |
| `with torch.inference_mode():` | 순수 추론에서 추가적인 자동미분 관리 비용도 줄인다. 여기서 만든 텐서를 이후 학습에 쓰는 데는 제약이 있다. |

`with` 블록의 효과는 들여쓰기가 끝나면 끝난다. 앞에서 초기 가중치를 지정할 때 쓴 `no_grad()`가 아래쪽의 별도 학습 반복문까지 적용되는 것은 아니다. 평가에는 `eval()`과 `no_grad()`를 함께 사용하거나, 이후 자동미분 계산과 연결하지 않는 순수 추론에서 `inference_mode()`를 사용할 수 있다.

가중치 기울기가 필요하다고 입력 데이터에도 반드시 `requires_grad=True`를 줄 필요는 없다. 일반적인 모듈 파라미터는 학습 대상으로 등록되어 있고, 입력의 기울기가 필요하지 않은 보통의 학습에서는 입력의 미분 추적을 켜지 않아도 파라미터의 기울기를 구할 수 있다.

`model.zero_grad()`는 모델 파라미터들의 기울기를, `optimizer.zero_grad()`는 옵티마이저가 관리하는 파라미터들의 기울기를 비운다. 전체 파라미터를 등록했다면 대상이 같지만 일부만 등록한 경우에는 범위가 달라진다. `step()`은 일반적으로 `.grad`를 자동으로 지우지 않는다. 새 계산 그래프는 기울기 추적이 켜진 새 순전파에서 만들어지며 `zero_grad()`가 만드는 것이 아니다.

<strong>리프 텐서(Leaf Tensor)</strong>는 보통 자동미분이 추적하는 다른 연산의 결과로 만들어진 중간값이 아닌 출발 텐서를 뜻한다. 모듈의 학습 파라미터는 기본적으로 자신의 `.grad`를 보관하지만, 계산으로 얻은 은닉 상태 같은 중간값은 기본적으로 `.grad`를 남기지 않을 수 있다. **중간값의 `.grad`가 `None`이라는 사실만으로 그 연결에서 역전파가 수행되지 않았다고 결론 내리면 안 된다.** 중간값 자체의 기울기를 보려면 손실을 구성하는 실제 연결상의 텐서에 `retain_grad()`를 먼저 호출한다.[^retain-grad]

```python
debug_model = VisitorRNN(hidden_size=4)
debug_output, _ = debug_model.rnn(X[:2])
debug_output.retain_grad()  # 이 중간 텐서의 기울기도 보관한다.
debug_pred = debug_model.head(debug_output[:, -1, :])
debug_loss = nn.MSELoss()(debug_pred, y[:2])
debug_loss.backward()
print(tuple(debug_output.grad.shape))  # (2,14,4).
```

이 검사의 `debug_output.grad`는 반환된 `output` 배열이 이후 예측층에서 사용된 경로의 기울기다. RNN 내부에서 시간 사이로 전달된 모든 은닉 상태의 총 기울기를 곧바로 보여 주는 배열로 해석해서는 안 된다. 이 예제에서는 반환 배열의 마지막 시점만 예측층에 사용했다. 내부 시점별 기울기를 조사하려면 연결을 직접 구성한 `RNNCell` 중간 상태에서 확인한다.

손실은 반드시 shape `()`여야만 인자 없는 `backward()`가 가능한 것은 아니다. 기울기를 요구하는 실수 텐서의 전체 원소가 하나이면 `(1,)`이나 `(1,1)`도 가능하다. 다만 예측 텐서 여러 원소에 바로 `backward()`를 호출하는 것은 숫자 하나의 손실을 만들고 호출하는 본문의 경우와 다르다.[^backward]

<summary>G. 같은 입력창과 수동 역전파를 Rust로 표현하기</summary>

Python과 Rust에서도 입력창·시점·가중치의 관계는 같다. 차이는 아래 Rust 코드가 표준 배열과 실수만 사용한다는 데 있다. 이 배열에는 PyTorch의 자동미분 기록이나 `.grad`, `detach()`가 없으므로 기울기를 직접 계산한다. Rust에서도 자동미분을 지원하는 별도 라이브러리를 사용할 수 있지만, 여기서는 언어에 따른 코드 표현만 비교한다.

`Vec`는 길이를 늘릴 수 있는 배열이고, `push`는 끝에 항목을 추가한다. `f64`는 64비트 실수다. `&`는 값을 읽을 때 빌려 쓰는 참조를 나타낸다. Python의 `range(start,end)`와 Rust의 `start..end`는 끝을 제외한다. Rust의 `1..=3`은 양끝을 포함하고, `.rev()`는 순서를 뒤집는다.[^rust]

아래는 참고 E와 동일한 스칼라 검산이다. 마지막에는 기울기를 구하는 일과 실제 가중치를 바꾸는 일을 구분하기 위해 단순 SGD 갱신 한 번을 덧붙였다.

```rust
fn main() {
    // 먼저 같은 7일 기록으로 입력창과 다음 날 정답을 묶는다.
    let data = [10, 20, 30, 40, 50, 60, 70];
    let seq_len = 3;
    let mut pairs = Vec::new();
    for i in 0..data.len() - seq_len {
        let window = data[i..i + seq_len].to_vec(); // 끝 위치 제외, 복사.
        let target = data[i + seq_len];
        pairs.push((window, target));
    }
    println!("{pairs:?}"); // 입력창 네 개와 정답 네 개.

    // 별도 스칼라 검산: 현재 입력과 이전 상태에 같은 규칙을 반복한다.
    let inputs = [1.0_f64, 2.0, 3.0];
    let input_weight = 0.5_f64;
    let recurrent_weight = 0.5_f64;
    let target = 0.5_f64;
    let mut hs = [0.0_f64; 4]; // 초기 상태와 세 시점의 상태.

    for (index, &value) in inputs.iter().enumerate() {
        hs[index + 1] = (
            input_weight * value + recurrent_weight * hs[index]
        ).tanh();
    }

    let mut adj_h = hs[3] - target; // 0.5*(hs[3]-target)^2의 기울기.
    let mut pieces = [0.0_f64; 3];
    for t in (1..=3).rev() { // 3,2,1 순서.
        let adj_a = adj_h * (1.0 - hs[t].powi(2));
        pieces[t - 1] = adj_a * hs[t - 1]; // 순환 가중치 사용분.
        adj_h = adj_a * recurrent_weight; // 이전 상태로 전달.
    }
    let gradient: f64 = pieces.iter().sum();
    println!("gradient={gradient}");

    // 여기서부터 실제 숫자 갱신. 위의 기울기 계산과 별도 작업이다.
    let learning_rate = 0.01_f64;
    let mut updated_weight = recurrent_weight;
    updated_weight -= learning_rate * gradient; // 단순 SGD 한 스텝.
    println!("updated_weight={updated_weight}");
}
```

이 코드는 `0.034240236230452...`의 순환 가중치 기울기를 계산한다. 다운로드 Rust 파일에는 이 검산과 함께 입력 특징 네 개·은닉값 세 개의 다변량 순전파도 포함했다. 그 계산에서는 현재 시점의 모든 뉴런이 같은 이전 상태를 읽고, 모든 새 은닉값을 계산한 뒤에 상태를 바꾼다. 한 뉴런을 계산할 때마다 이전 상태를 덮어써서 다음 뉴런이 이미 바뀐 값을 읽게 만들면 원래 RNN과 다른 계산이 된다.

</details>
